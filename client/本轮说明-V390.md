# HashMM V390 本轮说明

日期：2026-07-23

## 结果

本轮没有继续增加孤立页面，而是把 Chat、长对话、长任务、多 Agent、RAG 证据、工具执行与跨端运行状态收束到同一条可验证数据链。新增三项版本化协议：

1. `hashmm.context-capsule.v1`
   - 为每次模型调用编译目标、完成标准、关键决策、阻塞项、模型能力和分级上下文。
   - 正文只在本次运行中使用；持久化清单只包含内容哈希、长度、信任级别、截断状态和引用锚点。
2. `hashmm.execution-receipt.v1`
   - 主 Agent 与子 Agent 的每次工具动作都会生成内容寻址回执。
   - 回执记录执行者、权限依据、作用域、风险、副作用、幂等引用、耗时、结果哈希、证据与产物引用，不保存原始参数、凭据、工具正文或思维链。
3. `hashmm.causal-work-graph.v1`
   - 把目标、标准、来源、主张、工具、回执、产物、检查和上下文胶囊组合为带代际与修订号的因果工作图。
   - 来源内容变化时只使下游依赖闭包过期，避免长任务全部重算。

## 已接通的真实链路

- 普通 Chat 的流式 Agent 路径与直接问答路径都会生成 provider-aware 上下文胶囊，并在 run manifest 中保留可跨端读取的脱敏投影。
- AgentLoop 的每次工具调用都会经过权限管线并生成执行回执。浏览器观察、本地写入、外部写入和 Computer Use 使用不同的副作用与风险语义；未知工具不再默认视为只读。
- 可恢复目标循环和定时循环会持久化回执、上下文胶囊与因果图。进程重启只重建确定性元数据，不自动重放曾经中断的副作用。
- Worker 子 Agent 使用与主 Agent 相同的权限与回执管线；Team 聚合全部成员回执并将其纳入完成门。工具动作数、回执数或完整性不一致时不能宣称“已验证”。
- WorkRuntime 只投影有界的完成标准、证据图、因果图、回执、上下文清单和运行前沿；模型正文、原始工具参数和来源正文不会进入跨设备账本。
- 桌面右栏与长任务页面展示真实代际、过期节点、无效回执、副作用、风险、耗时和授权来源，让用户能够判断“做了什么、凭什么、还需重验什么”。

## 安全与正确性边界

- 执行回执只能证明运行时观察到某次动作及其结果哈希，不能证明外部世界中的文字主张天然为真。
- 因果边只由已有任务契约和运行事实确定性生成，`model_inferred_edges` 固定为 `0`。
- 外部网页、检索结果、上传文件和工具输出仍按 `untrusted_data` 处理，不能覆盖系统或用户指令。
- 外部写入和高权限控制需要幂等引用；缺失时回执校验失败。
- SHA-256 是完整性证据，不等同于发布者身份或 Authenticode 签名。

## 明确限制

- 本轮工作区只允许写入 `D:\sheji\agent\hashmm`，因此没有修改位于相邻目录的 Android App 源码。App 可继续消费 WorkRuntime 旧字段；若要原生展示因果图与执行回执，需要在 Android 工程中增加相应类型和卡片。
- 因果失效目前覆盖 HashMM 已记录的来源—主张—目标依赖。没有被检索或工具链记录的隐含业务依赖不会被猜测补全。
- 安装包通过了完整性校验，但在配置正式代码签名证书之前，Windows 仍无法验证发布者身份。
