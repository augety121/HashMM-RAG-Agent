# 本轮说明 V625

## 面向用户的设备接力

- 设备接力首页改为设备列表和当前设备工作区，不再要求用户先在三个抽象卡片之间猜测。
- 列表显示本机、最近一次 App 接力，以及服务端返回的账号所属执行器；在线状态、最后上报时间和接力内容都来自真实接口。
- 选择在线设备后才提供“进入桌面”；离线设备不会伪装成可连接。文件、连接方式、RDP、Moonlight、EasyTier、TURN 与安全策略保留在下一层高级页面。
- App 接力继续回到原对话，沿用同一会话、项目、进度和成果，不复制另一套工作记录。

## 自动任务成为一级工作入口

- 左侧新增“自动任务”，使用现有计划任务服务端事实，不是静态演示页。
- 页面支持创建、启用或暂停、立即运行、删除和刷新；每日简报、资料摘要、知识健康检查只是可编辑起点，不会在用户确认前自动创建。
- 自动任务要求绑定目标对话，执行结果回写原 Chat；界面只展示用户关心的计划、下次运行、最近结果和异常。

## 豆包搜索与 Chat 共用真实链路

- 新增登录用户可调用的搜索连接测试。测试通过与否取决于已经保存且启用的配置，并调用 Chat 实际使用的同一个豆包搜索适配器。
- API Key 只写入服务端密钥存储，不写入源码、前端缓存、测试、日志、发行说明或压缩包；测试响应只返回状态、结果数量和耗时。
- 服务端缺少集成路由时，插件中心明确提示部署版本过旧。用户提供的日志显示当时运行的是 V590，因此必须上传本轮服务器包并重启后再验收。

## 仍需真实环境验收

- 真实 App 接力、远端执行器地址解析、公网设备连接、对称 NAT、自有 TURN、RDP/Moonlight 与 24 小时稳定性必须在实际部署和多设备环境验收。
- 搜索连接测试需要用户在部署 V625 后，以已经轮换的新密钥重新保存并执行；本地验证不会使用或保存聊天中公开过的密钥。
- 当前安装器经 Windows `Get-AuthenticodeSignature` 核验为 `NotSigned`。SHA-256 可证明文件完整性，但不能替代受信任发布者身份；公开分发前仍应完成 Authenticode 签名。
- 当前部署日志中的 `HASHMM_PUBLIC_URL` 仍是 HTTP。公网设备接力和登录令牌必须在 HTTPS/WSS 部署后再做正式验收。
