# HashMM V551–V570 本轮说明

日期：2026-07-27  
Backend：V570  
Desktop / MCP / Native：1.33.0

## 本轮目标

这一轮不是继续堆模型名称，而是把不同 API、Chat、RAG、工具 Agent 和多 Agent 收到同一条可验证运行链。模型 ID 与账号权限仍以服务商实际返回和管理员配置为准；代码不会因为模型名称看起来像“推理模型”就自动扩大能力。

## V551–V570 实现映射

- V551：新增请求级 `hashmm.runtime-plan.v1`，统一 Fast / Auto / Deep。
- V552：统一直接回答、RAG、单 Agent、工作流、多 Agent 五种执行形态。
- V553：只有可独立验收的深度任务才准入多 Agent，长提示词本身不触发扩编。
- V554：统一规划、循环、并行 Agent、工具调用与执行调用预算。
- V555：工具 Schema 增加请求级字符预算，保留核心工具并裁剪尾部非核心工具。
- V556：Provider 注册表覆盖主流云厂商、聚合服务与本地 OpenAI-compatible 运行时；补充 Amazon Bedrock、OCI Generative AI、Perplexity、Fireworks、Cerebras、GitHub Models 与 SambaNova 的显式协议预设。
- V557：服务商协议能力与具体模型能力分离；具体模型只能显式声明、不能靠名称猜测。
- V558：OpenAI 新连接优先 Responses；旧 OpenAI 记录未保存协议时继续使用 Chat Completions。
- V559：Azure OpenAI 保持部署 ID 语义，不伪造通用模型发现。
- V560：OpenAI Responses 适配请求级推理强度、回答详细度与可选提示缓存保留策略。
- V561：DeepSeek 适配显式推理强度，并与受限 `extra_body` 安全合并。
- V562：Anthropic 只有在具体模型声明推理且配置思考 Token 预算后才启用 extended thinking。
- V563：未知 OpenAI-compatible 厂商只有配置明确的参数名时才发送推理扩展。
- V564：模型路由按管理员声明的 fast / auto / deep 角色和能力排序，不硬编码厂商模型 ID。
- V565：用户偏好模型只在能力满足时优先；系统默认模型作为可用回退候选。
- V566：路由候选严格限制为本人模型与系统默认模型，防止跨账号使用加密 API Key。
- V567：模型目录在服务端短时缓存，模型 CRUD 与默认模型切换立即失效。
- V568：统一归一化输入、输出、推理、缓存命中和缓存写入 Token；明细不重复计入总量；上下文预算读取已声明窗口，并按 Fast / Auto / Deep 限制为 8K / 24K / 64K。
- V569：管理员模型页增加能力契约、路由角色、上下文上限、Responses/Anthropic 参数和模型 ID 发现；普通用户可选择服务商与协议。
- V570：补齐后端、桌面、MCP、Native 与发行说明版本，并增加 Provider、路由、所有者隔离、发现、成本、本地免密模型选择和前端能力边界回归。

## 主要代码

- `hashmm/model_runtime.py`：请求准入、执行形态、模型要求、兼容性、路由排序、用量归一化和工具 Schema 计量。
- `hashmm/model_providers.py`：Provider 注册表、协议策略、能力契约和厂商参数边界。
- `hashmm/api/model_manager.py`：统一适配器、请求路由、目录缓存、模型发现和用量明细。
- `hashmm/api/streaming.py`：Chat 主链接入统一准入与模型路由。
- `hashmm/agent/loop.py`、`hashmm/agent/tool_retrieval.py`：Agent 循环与工具 Schema 预算接入。
- `frontend-next/components/admin/ModelsTab.tsx`：管理员模型运行策略界面。
- `frontend-next/components/SettingsModal.tsx`：普通用户主流 Provider 选择。
- `tests/test_v570_model_runtime.py`：V570 回归。

## 明确边界

- Provider 预设只表示 HashMM 已实现相应协议入口，不表示某个账号能访问任何具体模型。
- Amazon Bedrock 走官方 `bedrock-mantle` OpenAI-compatible 入口；OCI Generative AI 走官方区域 `openai/v1` 入口。两者都不伪造模型发现。
- Google Gemini API 已直接适配；Google Vertex/Agent Platform 的 OAuth/ADC 令牌默认约一小时并需要刷新器，本轮没有把短时令牌输入框冒充成完整受管身份接入。
- 模型发现只读取服务商当前账号接口返回的 ID，不把发现结果当作工具、视觉、推理或结构化输出能力证明。
- 本轮没有用真实付费账号逐一调用所有服务商；真实认证、区域端点、模型权限、费率和限流仍需对应账号验收。
- 本轮没有修改仓库外的 Android App 工程，也不把桌面页面变化声称为 App 已发布。
- 未完成 Windows Authenticode、真实公网多设备和 24 小时稳定性验收前，不把本地测试结果表述成生产发布通过。
