# HashMM V2600 本轮说明

本轮交付重点是 Verified Work Kernel：统一版本、统一事件、请求时 Provider 路由和可验证发布，而不是继续堆积孤立入口。

## 已落地

- `hashmm/release-manifest.json` 统一 Backend、API、Desktop、Android、数据库与协议版本。
- Work 事件和账号同步事件增加 `hashmm.event.v1` 信封，支持 cursor 恢复、幂等去重、trace 与脱敏引用。
- Provider Fabric v2 支持多通道、健康/熔断过滤、priority + weight、sticky、并发租约和脱敏预览，并进入 Chat 真实模型选择路径。
- Provider 管理页支持添加通道、预览路由和编辑模型别名策略。
- Chat 专注模式保留任务计划与 Todo，可持续查看执行状态。
- Canvas op/revision/snapshot 从本地 JSON 权威迁入主数据库，并用条件 revision 更新检测并发写冲突；旧 JSON 仅作一次性兼容导入。
- Python 插件工作进程执行只读、无网络 audit policy；声明更宽权限时 fail closed，并要求 MCP/隔离工作区适配器。
- Android 增加 Compose instrumentation 冒烟测试；APK 打包增加统一版本、签名状态、SHA-256 与 release JSON 门禁。
- 新增 JSON Schema、AsyncAPI 与无网络契约校验脚本；桌面发布校验同时核对 Android（存在相邻 App 工程时）。

## 已执行验证

- Backend 全量：`1730 passed, 8 skipped`，0 failed。
- Frontend：`63` 个测试文件、`231` 项测试，以及 TypeScript typecheck 和 Next.js production build 全部通过。
- Desktop/native：ProjectVault、后端管理器、能力包、安装引擎、仓库智能、受管 Worktree、Observer V4 品牌资产、source/packaged/artifact gate 全部通过。
- Android：unit/lint/debug 与 instrumentation APK 编译通过；Debug APK 已生成。生产 Release APK 因未配置发行证书而按策略拒绝冒充生产包。
- Windows：七阶段原生流水线完成，EXE、SHA-256 sidecar 与 release JSON 三方一致；当前未配置 Authenticode 证书，因此是可验收的未签名内部包，不是公开发行签名包。

最终数字以本轮末尾实际命令输出为准，不提前把正在运行或尚未运行的检查写成通过。当前阶段已完成的定向后端与前端检查会在交付回复中列出。

## 未冒充完成

- 没有真实证书时，不能交付“已签名生产包”。
- 没有跨网络真机验收时，不能宣称远程达到商业远控 SLA。
- 没有共享 broker/lease 压测时，不能宣称任意多副本可线性扩展。
- Python audit policy 不等于容器、VM 或 OS 级插件沙箱；原生扩展型第三方代码仍应放入外部隔离运行时。
- Canvas 在 PostgreSQL 才具备共享数据库并发语义；默认 SQLite 仍是单节点部署，不能宣称多副本协同。

详细规范与验收命令见 `docs/HASHMM_V2600_VERIFIED_WORK_KERNEL_SPEC.md`。
