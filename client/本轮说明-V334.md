# 本轮说明 · V334（2026-07-16）—— 安全启动与可交付桌面包

本轮以用户真实使用的 `start-hashmm1.sh` 和 `installer-native` 为准，修复的是开发环境通过、
换到 AutoDL 或干净 Windows 后仍可能失败的交付断层。

## 服务器启动

- 三个 shell 入口统一委托给 `scripts/hashmm_launcher.py`，不再各自复制旧启动逻辑。
- 明文 JWT、Supabase service-role、搜索 key 和 benchmark token 已从项目脚本移除。
- 配置只放 `.env`；公网监听缺少独立随机密钥、鉴权或精确 CORS 时 fail closed。
- `doctor` 校验 Python、核心依赖、实际 import 路径、最低 RELEASE、端口、索引可写性和模型降级。
- 正常启动不访问网络、不执行 pip。STT/文档/视频依赖通过 `install-optional` 显式安装。
- 端口级文件锁阻止同一个服务被重复拉起；可选模型缺失会明确报告降级，不伪报“满血”。

AutoDL 使用：

```bash
cp .env.example .env
chmod 600 .env
# 编辑 .env；公网部署按模板填完整 production 安全项，并轮换所有曾暴露的旧 key
./start-hashmm1.sh doctor
./start-hashmm1.sh
```

`start-hashmm1.sh` 依赖同版本项目中的 `scripts/hashmm_launcher.py`，因此必须上传完整 V334
代码包，不能只把一个 shell 文件覆盖到旧项目。

## installer-native / 桌面端 1.7.0

- 正式包内置 238.4 MB 的 Python 3.12 运行时；首次启用本地后端不再依赖系统 Python 或下载源。
- 运行时的 requirements 指纹和 `fastapi/uvicorn/numpy/multipart` 导入在出包前、成品内各验一次。
- venv 和内置运行时都会核对依赖指纹；源码升级后旧 `.deps-ok` 不再被误当成可用。
- 安装更新先写同盘 stage，检查 Electron、webui、后端和 Python，再原子切换；失败回滚旧版本。
- 保留 `HashMM Files` 与 `local-backend`，同时清掉旧程序残留；目标非空且不是 HashMM 时拒绝覆盖。
- 自解压使用唯一临时目录并在安装结束后清理，避免并发安装和旧残留互相覆盖。
- 能力包的远程下载必须 HTTPS + 64 位 SHA-256；只有 loopback 调试允许不带哈希。
