# HashMM V702 本轮说明

## 本轮解决的问题

V702 收口的是用户截图中已经复现的 Chat 长任务失败，而不是继续增加入口或演示页面：

1. 过去 24 小时简报不得使用跨年旧闻、未来截止时间或只有日期而无法证明时间窗的来源。
2. 二手转述、搜索摘要和无法打开的原页不得标记为“已核验”。
3. Markdown 不能整篇重复；公众号任务必须同时交付 Markdown 与公众号兼容 HTML。
4. 模型说“接下来生成”不等于完成。清单或文件不完整时必须保存已有成果并返回 `delivery_incomplete`。
5. DeepSeek thinking 多轮请求需要的 `reasoning_content` 只用于供应商协议连续性，不向用户显示或持久化。
6. 自检、心跳和轮询不能污染在线数据库、全局配置或淹没关键日志。

## Chat 与项目连续性

- 项目可以拥有多条 Chat；项目内对话只显示在所属项目下，未绑定项目的对话进入“最近”。
- 当前项目下的新会话在发送前完成 owner-scoped 服务端绑定。
- 文件和文件夹附件先创建/绑定真实会话，再上传并保存真实地址；失败保留草稿和附件。
- 停止按钮先请求服务端中断，再对账活动 turn；重复停止保持幂等。
- 重新打开会话时恢复公开任务清单、工具回执、交付状态和失败原因，不恢复或展示隐藏思维链。

## 公众号交付真实性门禁

- 以服务端 Asia/Shanghai 当前时间为唯一时间基准。
- 数据截止时间不得晚于当前时间。
- 精确来源时间必须位于 `[当前时间 - 24 小时, 当前时间]`。
- 只有日期的来源会标记为缺少时分，不能据此声称已覆盖严格的最近 24 小时。
- “已核验”条目必须有原始 URL，且不能同时包含“经某媒体转述、摘要、原页失败、待核验”等冲突信息。
- Markdown 与 HTML 必须包含对应的实质标题，HTML 不允许脚本或外部样式表。
- 检测到整篇重复、缺少 HTML、正文过短或来源窗口不合格时不会写成成功。

## 公开过程与私有推理边界

HashMM 向用户展示的是任务计划、阶段、工具事实、证据、审批、成果和可恢复错误。供应商原始 reasoning、隐藏 Chain of Thought 与 `<think>` 内容不属于公开任务链，也不作为“已完成”的证据。

## 对旧 V700 自检与服务器日志的处理

用户上传的 `hashmm-selftest-2026-07-30055117.md` 与对应服务器日志来自
V700，不是 V702 复测结果。V702 对其中可复现的确定性缺陷做了以下修复：

- 在线自检改用独立加载的数据库模块与临时数据库，不再重定向正式
  `DB_PATH`，也不替换正式连接池。
- 数据库损坏或旧快照恢复后，先关闭旧连接池，再针对当前活动数据库执行
  全量 schema 与迁移；`work_runs` 等运行表不会因迁移写入旧 inode 而缺失。
- 正常的自检任务轮询与心跳不再逐请求刷屏；失败、超时和慢请求仍保留日志。
- 安全拒答、无 OS 沙箱、记忆幂等、多轮空响应、画布语义结构和工具调用判定
  均补充了回归覆盖。

这只能证明 V702 源码和本地测试环境中的修复。服务器必须部署 V702 后重新
执行自检；旧 V700 进程和旧报告不会自动变成通过状态。
