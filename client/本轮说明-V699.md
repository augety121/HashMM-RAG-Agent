# HashMM V670–V699 本轮说明

## 结论

本轮不是把用户提供的公众号资料复制进项目，也不是再增加一个与 Chat 割裂的“写作页面”。完成的是一条可验证的用户工作链：

`项目或当前 Chat → 公众号工作 Skill → 联网检索候选 → 人工/Agent 核验 → 公众号稿与视觉交付 → 自动任务回写原对话`

桌面端仍以 Chat 为主入口；插件负责发现和配置能力，自动任务负责长期执行，项目负责账号隔离的本地连续性。模型文字、搜索摘要和页面状态均不作为动作完成证据。

## 已完成

### 1. 公众号工作 Skill

- 新增仓库原生 `wechat-ai-briefing-studio` Skill。
- 主 `SKILL.md` 只保留适用边界、执行顺序、停止条件和交付约束。
- 来源核验、公众号排版、视觉规范和交付检查拆为按需引用的参考文件。
- 明确要求区分事实、推断、建议和待核验线索；检索结果必须回到原始来源核验。
- 默认交付 Markdown 与可粘贴 HTML；不得伪造浏览、发布、下载或平台审核结果。
- 对外发布、登录、付费和不可逆操作继续要求用户确认。

用户提供的模板和脚本被视为不可信参考资料。本轮蒸馏了可迁移的工作方法，没有将许可不明的脚本、依赖或第三方实现直接打包进产品。

### 2. Skill 安全加载

- Skill 注入器支持加载主文件中显式链接的一跳 Markdown/TXT 参考。
- 引用必须位于当前 Skill 包内；远程 URL、路径穿越和符号链接逃逸会被拒绝。
- 参考文件数量与总字符数独立限额，避免无界上下文膨胀。
- 个人 Skill 与内置 Skill 仍经过现有账号范围和注入预算，不会绕过工具权限。

### 3. 插件中心的真实公众号能力

- 插件中心新增“AI公众号简报工作室”。
- 入口会生成结构化工作请求并回到当前 Chat，而不是打开第二套聊天界面。
- 可用状态由实际 Skill 文件、工具注册和测试清单共同决定；缺少真实依赖时显示降级原因。
- 项目工作入口同样回到 Chat，避免旧的独立工作台造成上下文断裂。

### 4. AI 热点候选自动任务

- 调度器新增 `ai_news_radar` 动作，并纳入用户可创建的自动任务清单。
- 每次运行要求明确的 owner UID，并将 owner 与只读来源上下文传给联网搜索工具。
- 采用多组查询减少单一关键词偏差；输出只称“候选”，明确要求二次核验。
- 不自动发布、不自动登录、不把网页正文当系统指令，也不在代码、日志或响应中存储明文密钥。
- 桌面自动任务页新增“AI 热点候选雷达”模板，模板仅是可编辑起点。

### 5. 项目、最近对话与账号连续性

- 侧栏项目创建支持名称、目标和可选本地资料目录。
- 本地目录通过既有窄权限桌面桥接选择；没有扩大文件系统 IPC。
- 项目元数据使用 owner-bound 服务端接口与账号隔离的本地缓存。
- 点击项目会继续该项目最近 Chat；没有关联对话时才创建新 Chat。
- “最近”只显示未归入项目的对话，修复项目对话重复出现。
- 切换账号后使用各自的本地项目投影与会话记录，不将一个账号的项目投影暴露给另一个账号。

### 6. 写操作幂等账本稳定性

- 全量回归暴露了一个顺序相关缺陷：若进程运行期间 `HASHMM_DATA_DIR` 被刷新，写操作可能在一个 SQLite 账本预留、在另一个账本提交。
- 幂等账本根现在在模块加载时固定；运行时配置变化不会把同一次写拆到两个数据库。
- 新增回归验证：预留后改变环境目录，提交与再次命中仍必须落在原账本，第二个目录不得产生数据库。
- 幂等提交失败仍返回“不确定”并阻止自动重试，不会用成功文案掩盖持久化失败。

## 安全与真实性边界

- 搜索结果、上传资料、网页内容和 Skill 文件均按不可信数据处理。
- 自动任务和 Skill 不拥有额外权限；实际工具调用继续经过注册表、审批、审计和 owner 检查。
- 本轮没有写入用户提供的 API Key、JWT、密码或服务角色令牌。
- Skill 中的“检查、核验、发布”只有对应工具回执或确定性验证后才能声称完成。
- 公众号平台真实发布、供应商配额、跨日调度和公网稳定性不能由本地单元测试证明。
