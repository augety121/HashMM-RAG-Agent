# HashMM V411–V415 本轮说明

本轮不是新增五组孤立页面，而是把“我的电脑”从旧远程演示收敛为 Chat、长任务和跨端接力可以共同使用的一条受治理能力链。下面只记录已经进入代码并能被确定性检查的内容；尚未做真实弱网和长时间运行验证的部分单独列出。

## V411：用户入口与管理员控制面分层

- 桌面一级导航加入用户可理解的“我的电脑”，Chat 输入框的“更多”可以直接进入同一页面。
- 普通用户只看到设备状态、连接请求、画质、隐私防护、显示器和远程开机；局域网地址、手工 SDP、TURN/ICE 等部署细节只对管理员显示。
- 没有删除管理能力。管理员仍能进入网络、中继、手工排障等完整控制面。
- 文案区分两种真实边界：账号连接逐次在本机确认；局域网授权码属于一次性显式配对，不再把二者混写成同一种授权。

## V412：统一远程会话模型

- 新增 owner-bound `RemoteSession`，统一描述 host/viewer 设备身份、请求权限、批准权限、状态、代次、过期时间和关联工作。
- 权限限定为 `view / control / clipboard / file_read / file_write / audio / power`；未知权限不会扩大能力。
- 同一被控端同一时刻只接受一个待确认或活动控制会话，避免重叠授权和输入竞态。
- 缺失会话和跨账号会话使用相同的不可枚举结果；账号相同不等于自动授权。

## V413：短时能力票据、撤销与审计

- 会话批准后分别给 host 和 viewer 签发短时 HMAC 能力票据；票据绑定账号、会话、角色、设备、权限、代次、唯一 ID 和过期时间。
- 断开、拒绝、撤销、超时或代次变化会使旧票据失效。
- 控制消息带单调序号和时间戳；服务端拒绝过期、未来、重复和乱序消息。
- 新增会话列表、请求、批准、拒绝、撤销、签票和 owner-bound 审计 API。TURN 配置接口只返回“是否已配置”，不回传用户名或凭据。

## V414：桌面端与 App 使用同一信令事实

- 生产运行统一使用 HashMM 后端 `/api/remote/ws`；设备发现、权限请求、RTC 协商、控制回退和票据刷新不再由桌面端与 App 各走一套状态。
- 桌面被控端、桌面查看端和 Android 查看端都发送稳定设备 ID，并消费相同的 `permissionPending / ready / ticket / pairFail` 协议。
- Android 不再选择直接 Supabase 远程信令作为产品运行路径；Supabase 仍只负责统一账号会话，后端负责 owner 校验和能力签发。
- 账号令牌不再放入 Electron `file://` 查询参数；主进程通过窄 preload 一次性注入并在刷新后热更新。

## V415：受控传输与最小桌面能力

- 鼠标和键盘优先走 DTLS 保护的有序 WebRTC DataChannel（SCTP over DTLS）；通道消息再次绑定会话、序号和时间窗，WebSocket 保留为经过同一会话检查的回退。媒体轨使用 WebRTC 的 SRTP 保护，二者不混写。
- 文件字节优先走独立的加密 WebRTC DataChannel，小型接受/进度消息仍可经受控信令返回；当前内存组装实现的单文件安全上限明确为 256MB，不再宣称“无限制”或不现实的多 GB 能力。
- MJPEG 兼容中继只接受短时 Remote ticket，账号 access token 不进入帧 URL；room 必须等于已批准 session ID。
- ICE 配置执行协议白名单和数量上限；TURN/TURNS 必须同时提供用户名与凭据，不再内置第三方公共 TURN 账号。
- 可选 `HASHMM_REQUIRE_SECURE_REMOTE=1` 会同时阻断非 HTTPS/WSS 信令与帧中继，并进入生产部署安全检查。
- 远程隐藏窗口关闭 Node 集成，使用窄 preload；文件、多屏、接力和系统输入 IPC 校验发送者。重启、关机等高风险操作仍需主窗口逐次确认。

## 与 Codex / Claude Code 的可核验对齐

- 对齐 Codex 的方向是“任务/会话隔离、并行但不共享未受控写边界、权限与沙箱优先”，不是复制界面或声称实现同一内部代码。
- 对齐 Claude Code 的方向是“默认询问、权限分层、工具与 OS 边界双重约束、子任务隔离”，本轮把这些原则应用到跨设备 Computer Use。
- HashMM 本轮自己的重点是：把远程电脑作为 Chat 和长任务可申请、可撤销、可审计的一项能力，而不是独立远控产品或管理员演示页。

## 尚未冒充完成

- 尚未执行真实公网多设备、对称 NAT、蜂窝网络切换、24 小时会话和断网恢复混沌测试。
- 未在本轮部署自有 TURN 服务；代码只验证受控 TURN 配置，不把“可配置”写成“已有全球中继网络”。
- 远程会话和审计当前是进程内权威状态，后端重启会 fail-closed 令全部会话失效；长期审计归档仍需接入持久化审计仓。
- HTTP 帧中继是受限网络兼容通道，不等于商用远控的全球边缘媒体网络。
- 既有局域网授权码和管理员手工 SDP 仍作为兼容/排障路径保留；产品账号路径已经统一，但旧实现源码尚未全部物理删除。
- 本轮没有重新生成 Windows 安装器、服务器 ZIP 或正式签名 APK；旧 V410 成品不能冒充 V415 交付物。
