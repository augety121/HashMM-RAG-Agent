# HashMM V1301 本轮说明

日期：2026-08-10  
主题：生产启动诊断与安全门一致性修复

## 根因

服务器 V1300 已成功导入并挂载路由，但 `.env` 同时满足：

- `HASHMM_ENV=production`
- `HASHMM_PUBLIC_URL` 使用 `http://111.115.7.14:20014`
- `HASHMM_REQUIRE_SECURE_REMOTE` 未启用

生产安全门因此正确拒绝通过明文 HTTP 承载登录令牌。V1300 启动器将这两项显示为 WARN，而后端 lifespan 将其作为阻断错误，造成“诊断通过后才崩”的误导。

## 修复

- 启动器与后端采用相同的生产判定：HTTP 公网 URL 和未启用安全远程均在 Uvicorn 启动前 FAIL。
- 错误信息明确区分正式公网 HTTPS 与只有校园网 HTTP 的临时非公网模式。
- 不自动启用 `HASHMM_ALLOW_INSECURE`，不降低鉴权、CORS、密钥和 HTTPS 门槛。

## 正式公网配置

```dotenv
HASHMM_ENV=production
HASHMM_PUBLIC_URL=https://你的真实域名
HASHMM_REQUIRE_SECURE_REMOTE=1
HASHMM_REQUIRE_AUTH=1
HASHMM_CORS_ORIGINS=https://你的真实域名,http://localhost:3000,http://localhost:6006
```

必须先让该 HTTPS 域名通过 Cloudflare Tunnel、Nginx 或其他受控反向代理真实转发到 `127.0.0.1:6006`，不能只修改字符串。
