# HashMM V368 本轮说明

## 目标

把桌面端和 App 中“有页面但 Chat 不会调用”“客户端各写一套可用状态”的能力收回到一条可核验主链：后端根据真实工具、执行器、路由和账号配置声明能力，两个客户端只负责解释与操作，不猜测、不把演示页当成功能。

## 已完成

- 主 Agent 的默认工具由基础 Agent 工具与中心注册表合并，按名称去重后再经过模块开关过滤；后台 Worker 执行同一过滤规则。
- 当前默认环境可核验到 43 个 Chat 工具、13 项产品能力，其中 10 项就绪；MCP、Hook、Graph-RAG 因本机或账号尚无配置/数据明确显示待配置。
- 运行时能力契约覆盖 RAG、联网调研、图片检索、Browser Use、Computer Use、Artifacts、多 Agent、记忆、画布、长任务、MCP、Hooks 和 Graph-RAG。
- 桌面端“高级能力”展示真实工具数、状态、原因、承载面和桌面在线要求，不再依靠导入成功或静态文案判断“可用”。
- App 动态页与工作台从同一接口取状态；Browser Use、取文件、远程屏幕等操作只有满足后端能力与桌面在线条件才可进入，否则显示确切原因。
- App 使用账号隔离的加密快照、60 秒内存缓存、5 分钟本地回退和 ETag 条件请求；缓存用于减少重复读取，不把旧数据伪装成实时数据。
- 图片库按账号隔离，同一内容可由不同账号独立拥有；Chat 图片检索只返回当前账号结果。上传接口先鉴权再读取文件内容。

## 参考如何进入实现

- Claude Code 官方概览中的工具、MCP、Hooks、子 Agent 与可扩展工作流，被落实为“可执行器存在、权限已登记、主循环能拿到、客户端能解释”的四重接线检查。
- Codex 官方文档与本地 `codex-main` 的工程方法用于约束长任务体验：任务状态可恢复、工具结果是证据、客户端不把模型自述当执行成功。
- 用户提供的面试实战资料继续作为 RAG 质量主线：检索、评估、失败分类和回归测试形成闭环；本轮没有把资料中的概念名直接包装成静态功能。

## 权限与正确性

- 新工具必须同时存在 schema、执行器和显式权限；缺任一项即不可用。`image_search` 为账号内只读能力，不授予全局图片访问。
- 能力接口需要登录，响应仅包含状态、原因、工具名和测试路径；不包含密钥、Token 或授权头。
- 外部网页、上传文件和工具输出仍是不可信数据；“浏览器已就绪”只表示执行链存在，不表示网页内容可信或可绕过审批。

## 明确限制

- 当前 MCP 为“待配置”：必须注册可用服务器和工具后才能进入 Chat，不能根据页面入口推断完成。
- 当前账号没有 Hook 时显示“待配置”；系统不会伪造触发器。
- Graph-RAG 没有知识图谱数据时显示“待配置”，不会凭空生成实体关系。
- Computer Use 的后端工具就绪不代表手机可直接控制电脑；App 还要求可信桌面连接在线并继续经过权限、确认和审计。
- Windows 安装器若仍为 `NotSigned`，SHA-256 只能证明文件完整性，不能替代 Authenticode 发布者身份。
