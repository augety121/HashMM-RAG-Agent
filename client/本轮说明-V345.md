# HashMM V345 本轮说明

日期：2026-07-18

## 本轮完成

- 修复 App 与桌面端管理员身份不一致：本地验证旧 JWT 后会向 Supabase 读取当前服务端 `app_metadata`；管理员只接受服务端元数据或后端邮箱白名单，不再信任可由用户修改的 `user_metadata.role`。
- 新增 Supabase 权限加固迁移：把 `profiles.is_admin` 回填到 `auth.users.raw_app_meta_data.role`，并阻止普通用户修改自己的 `is_admin`。
- App 定时任务从动态摘要切换到 `/api/admin/scheduled` 真实 CRUD：列出、创建、立即运行、启停、删除；新任务可绑定最近 Chat，结果由调度器回写同一会话。
- App 与桌面端运行轨迹统一读取 Assistant 消息持久化的 `run_manifest`，仅返回当前账号拥有的 Chat；记录包含模型、执行模式、耗时、Token、停止原因和外部校验结果，可回到原 Chat。
- 上下文透视自动选择当前账号最近 Chat 和最近用户问题；显式会话 ID 必须通过属主校验。App 展示透视对象并支持展开，桌面统一右栏新增“系统”页。
- 质量看板严格区分可评估、不可评估、证据覆盖与弱依据样本，显示真实每日趋势；没有样本时解释采样口径，不填演示数据。
- 个人用量补齐输入/输出 Token、币种与按模型拆分；个人用量不再误报“需要管理员”。管理后台合并本地用户与 Supabase `profiles`，标注身份来源。
- 修复桌面定时任务启停请求未发送 `enabled` 导致操作失败的问题，并补齐删除动作和调度器未启动提示。

## 对标来源与采用边界

- 参考本地 `codex-main.zip` 与 `openai-agents-python-main.zip` 的会话状态单一归属、逐轮持久化、稳定运行项 ID 和可恢复运行原则。
- 采用的是可验证机制，不复制品牌界面或把模型文字当执行证据：Chat 消息及 `run_manifest` 是运行状态主记录，App/桌面只是同一状态的两个视图。
