# HashMM V416–V420 本轮说明

本轮把 V415 的“受治理远程能力”继续推进到可恢复、可追溯、可部署、可实测和可拒绝虚假通过的生产门禁。这里的“完成”只指代码和确定性验证已完成；没有真实公网设备、固定公网 IP、域名和连续 24 小时时间窗口的事项不会写成已经验收。

## V416：持久化远程会话与审计

- 数据库 schema 升至 25，新增 owner-bound `remote_sessions`、`remote_audit_events` 和 `remote_acceptance_runs`。
- 后端重启时，遗留的 `pending/active` 会话在开始接收请求前统一转为 `interrupted`，代次递增，旧能力票据立即失效。
- 每个 owner/session 的审计事件使用 HMAC 链接；事件正文、父哈希和顺序均参加校验。保留期裁剪后仍能验证保留区间的内部链路。
- 审计只保留 scope、角色、传输类型、候选类型、协议和有界质量计数；账号令牌、TURN 凭据、SDP、ICE 地址、剪贴板、文件和输入正文不会持久化。
- 会话状态写入与审计追加在同一数据库事务中完成；跨账号查询继续返回不可枚举结果。

## V417：自有 TURN 基线

- 后端按 coturn TURN REST 约定签发短期凭据：用户名为 `到期时间:设备伪名`，密码为 shared secret 对用户名的 Base64 HMAC-SHA1；真实账号和设备 ID 不进入 TURN 用户名。
- 新增 `deploy/turn` 生产模板、只读容器、host network、TLS 端口、受限 relay 端口段、配额和私网/回环/组播 peer 拒绝策略。
- `scripts/render-turn-config.py` 只从环境变量读取至少 32 位 shared secret，原子生成 0600 配置，不输出 secret，也不允许把成品写出 `deploy/turn`。
- `HASHMM_REMOTE_REQUIRE_TURN=1` 时，启动器和生产安全门都会检查 TURN URL 与动态凭据 secret；缺失时服务拒绝进入生产运行。
- 服务器 ZIP 包含 TURN 模板和说明，但明确排除可能包含真实 secret 的 `deploy/turn/runtime`。

## V418：真实公网、多设备与对称 NAT 验收

- 新增 `scripts/remote-acceptance.py probe`，在每台真实设备/网络上测量 HTTPS 后端、TURN UDP、TURN TLS 和同一 UDP socket 面向不同 STUN 目的地的映射行为。
- 网络通过条件是硬门槛：至少两台不同设备、host/viewer 两种角色、HTTPS、实际观察到地址和端口相关映射、TURN UDP/TLS 可达，以及同一 HashMM 会话两端都上报选中的 `relay` candidate。
- 端口可达不等于 TURN 分配成功；没有真实 WebRTC 两端 relay 审计时，结果只能是 `incomplete`。
- 回执中的设备 ID、会话 ID 只输出短哈希；原始探测细节不通过普通用户的就绪接口返回。

## V419：24 小时稳定性与恢复验收

- 24 小时脚本不再只轮询 `/api/health`。每个样本还必须通过鉴权的远程控制面，并在持久化 owner 审计里找到同一近期会话的 host/viewer 双端 relay 观测。
- 通过条件包括：持续至少 86400 秒、至少每五分钟一个样本、可用率不低于 99.5%、relay 覆盖率不低于 99.5%、连续失败不超过 3 个样本。
- 短时 smoke run 即使健康页全绿也不会得到生产 `passed`；旧格式、缺少 relay 条件或调用方强行传入的 `passed` 会在持久化层降级为 `incomplete`。
- 回执记录恢复次数、最大连续失败、控制面/relay 覆盖和受限证据；访问令牌只从环境变量读取，不写入 JSONL 或数据库。

## V420：生产就绪门禁与用户投影

- 新增 owner-bound `/api/remote/readiness`。只有安全远程已强制、动态 TURN 已配置、30 天内真实公网回执通过、14 天内真实 24 小时回执通过且持久化审计可用时，`production_ready` 才为真。
- 桌面端“我的电脑”只向普通用户呈现“已通过生产验收/待真实环境验收”；管理员可以看到安全链路、短期 TURN、公网双端和 24 小时四项判定，不把内部凭据和证据正文暴露给用户。
- App 与桌面查看端每分钟从实际 `RTCStats` 上报有界候选类型和质量摘要，给网络与 soak 验收提供真实 relay 证据。
- AutoDL/服务器启动器升到 V420：安全远程或强制 TURN 配置不完整时在启动前给出确定性 FAIL，不再先报告 ready 再由后台任务报错。

## 必须在真实环境继续完成

- 尚未替用户购买或准备固定公网 TURN 主机、域名、TLS 证书和网络安全组，因此自有 TURN 是可部署基线，不是“已经在线”。
- 尚未拿到两台真实设备、两种公网运营商网络和可确认的对称 NAT 环境，因此本轮没有伪造公网通过回执。
- 尚未实际等待连续 24 小时，因此当前就绪接口应保持“待真实环境验收”。只有真实脚本完成并记录回执后才会改变。
- HMAC 审计链用于发现数据库行被修改，不等于第三方时间戳、公证或不可否认性证明。
- 本轮通过 source gate，但没有重新生成或宣称新的 Authenticode Windows 安装器；正式 EXE 仍须走 `installer-native/build-all.bat` 并核对 EXE、`.sha256` 与 `.release.json` 三方一致。

## 真实验收顺序

1. 在固定公网 Linux 主机部署 `deploy/turn`，开放 UDP/TCP 3478、TCP 5349 和 UDP 49160–49200，并配置与 HashMM 私有 `.env` 相同的 shared secret。
2. 在电脑和手机的两条真实网络分别执行 `probe`，同时保持一条经 TURN relay 的 HashMM 远程会话。
3. 导出 owner 远程审计，执行 `evaluate-network`；只有所有硬条件满足才记录 network 回执。
4. 通过环境变量提供验收账号 token，保持真实 relay 会话/必要的重新授权，执行不少于 86400 秒的 `soak`。
5. 重新打开“我的电脑”，确认生产就绪卡基于新回执变化，而不是手工配置或模型描述变化。
