# HashMM V400 本轮说明

V400 合并完成了 V396 至 V400 的计划范围。本轮重点不是继续增加孤立页面，而是把此前已经存在的 Chat、长任务、多 Agent、Browser Use、Computer Use、画布、文档成果、证据和技能治理串成一条可恢复、可核验、可验收的用户工作流。

## 本轮完成

### 统一工作画布

- 新增 `hashmm.work-canvas.v1`，统一投影工作概览、过程、依据、成果、完成收据、受治理下一步和变更影响。
- 桌面端新增原生工作详情，提供“概览 / 过程 / 依据 / 成果”四个层次，成果继续使用现有右栏 Artifact 与 Office 查看器。
- App 新增独立原生工作画布，不把桌面诊断页面直接搬到手机上。
- 工作入口、活动入口和工作台入口读取同一服务端事实源。

### 真实成果与交付闭环

- 统一识别文档、PPT、表格、PDF、图片、画布和代码成果，并保留真实 artifact 引用。
- 完成收据区分自动核验、带限制完成、等待复核、用户接受限制、阻塞和未就绪。
- 新增修订号绑定、幂等的“接受成果 / 要求修改”决策接口。
- 要求修改必须填写说明，接受或退回都不会隐式执行工具或扩大权限。

### 证据、失效和可信度

- 模型文字不再作为执行证据。
- 结果与因果证据节点绑定；依赖变化只让真正受影响的成果过期。
- 来源、检查、回执、失效原因和技能版本统一进入依据层。
- 同一运行只记录实际使用的技能精确版本，不暴露技能私有提示正文，也不把一次使用误写成质量改进。

### 长任务与受治理下一步

- 过程层统一显示阶段、分支、检查点和有界事件。
- 服务端投影控制、恢复、复核三类下一步，全部固定为 `auto_execute=false`。
- 暂停、继续、重试和取消仍只使用运行时发布的真实动作；客户端不凭页面状态虚构按钮。

### 跨端缓存与登录稳定性

- 工作画布使用私有 ETag，未变化时返回 304。
- 桌面端使用 `safeStorage` 加密持久缓存，无法加密时拒绝写盘，不存在明文回退。
- 缓存按认证身份哈希隔离，切换账号自动丢弃前一身份的数据。
- App 使用账号隔离加密缓存；命令和决策成功后只失效对应运行。
- 桌面工作画布请求会先刷新临近过期的令牌，并在 401 时执行一次受控刷新，避免长任务页面因旧令牌反复要求登录。

### 安全与数据库

- 新增 owner-bound `work_decisions` 表，数据库 schema 升级至 23。
- 运行工作区和决策接口继续对对象执行 owner 校验，缺失与越权保持不可枚举。
- 外部网页、文件、工具输出和模型文字继续作为不可信数据处理。
- Electron 新增的工作缓存 IPC 已纳入敏感 IPC 守卫，并只通过窄 preload 方法暴露。
