# 本轮说明 · V333（2026-07-16）—— 平台化 SDK · 可归因跑测 · 可靠性收口

本轮依据用户提供的《2026 年 7 月 Agent/RAG 趋势》逐项对照真实代码，不把趋势材料中的
型号、分数或产品传闻直接当事实。核心 RAG、Context Engine、工具检索、记忆和多 Agent
能力在 V332 已存在；V333 处理的是三个仍可验证的高 ROI 缺口，以及全量测试揭出的真实回归。

## 一、产品能力

1. **可安装 Python SDK**
   - 新增标准 `pyproject.toml`，支持 `pip install -e .` / 构建 wheel。
   - 新增 `hashmm.client.HashMMClient`，覆盖 `/v1/info`、`/v1/search`、`/v1/rag`。
   - 非 2xx、网络失败、非法 JSON 分别抛结构化异常，不再返回容易被误当成功的
     `{"error": ...}`。
   - `/v1` 的 `top_k`、`history` 参数增加服务端边界校验；API 文档修正真实鉴权变量为
     `HASHMM_API_KEY`。

2. **同轮可归因消融**
   - 桌面测试中枢新增“可归因跑测”：可选基准、standard/full 题量、1–4 基准并发，默认
     同跑裸模型基线。
   - 后端一个 job 先跑裸模型、再跑 Agent；两轮使用相同题集、模型和样本档位，差值才可归因
     给脚手架。
   - GitHub Actions 新增 `paired_baseline`，一次 Artifact 同时输出
     `<bench>_baseline.json` 与 `<bench>.json`。
   - 基线模式由全局环境变量切换改为 `ContextVar` 任务作用域，避免并发任务互相污染。

3. **榜单来源透明**
   - 当前 runner 固定 Terminal-Bench 1.0（80 题、`terminal-bench-core==0.1.1`），不与
     2.0/2.1 混榜。
   - SWE-bench Verified、SWE-bench Pro public、Terminal-Bench 1.0 均登记官方来源 URL，
     前端可直接打开。
   - 删除活跃代码/测试里无法由官方来源支持的 `Fable 5`、`GPT-5.6 Sol`、`19.78% 假解`
     等硬编码断言；历史 changelog 原文仍保留，但不再作为产品事实。

## 二、全量测试抓出的真实修复

- CI 模型适配器初始化失败时也会生成结构化 skip JSON，不再只打印错误后空手退出。
- 删除 `data/skill_packs` 中 14 个 SHA-256 完全重复的中文/乱码目录，只保留 7 个 ASCII 正式目录。
- Windows GBK 下 `check_frontend.py`、`security_check.py`、`dependency_audit.py` 不再因 ✓/✗ 崩溃。
- Markdown 恢复安全链接、语义列表、引用块；40 个前端单测覆盖 XSS 与渲染。
- SQLite 导出快照显式关闭连接，解决 Windows 文件锁导致无法删除临时快照。
- `/app` 映射在无 symlink 权限的 Windows 上回退目录联接；官方 `/app` 路径检测跨平台一致。
- SSRF 加固：拦截无 `://` 的 `javascript:`/`data:`，识别十进制/八进制/十六进制 IPv4 变体。
- `create_file` 幂等命中不再只看同名文件存在，还校验内容一致；避免“缓存说已修复，坏文件仍在”。
- 补齐 Vitest 的 `jsdom` 声明；Next 内嵌 PostCSS override 到 8.5.10，npm 审计清零。

## 三、使用

```bash
pip install -e .
python -m hashmm.api.server
```

```python
from hashmm.client import HashMMClient

client = HashMMClient("http://127.0.0.1:6006", api_key="你的 HASHMM_API_KEY")
print(client.rag("知识库的关键结论是什么？"))
```

桌面端：测试中枢 → 可归因跑测 → 保持“同跑裸模型基线（推荐）” → 选择 standard（≥50 题）
→ 开始正式跑测。

## 四、上线前仍需用户提供的安全配置

安全门禁当前会正确阻止默认配置上线：必须更换 `HASHMM_JWT_SECRET`、修改 admin 默认密码，
并限制 `HASHMM_CORS_ORIGINS`。这些值不能由代码替用户擅自生成并写进仓库。
