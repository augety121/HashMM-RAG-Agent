# HashMM V388 本轮说明

日期：2026-07-22

## 结果

本轮没有继续堆叠入口，而是按运行链逐项检查“页面上的能力是否由当前服务真实支持、失败是否被空数据掩盖、缓存是否会跨服务污染、文件操作是否有确定回执”。完成了运行能力实证、管理页部分数据状态、文档上传安全链和 App 能力缓存隔离四个高优先级闭环。

后端能力接口现在读取当前 FastAPI 实例实际挂载的路由。画布和长任务只有在依赖、开关、执行器与 API 路径都存在时才会进入 Chat 可用能力，不再因为模块可以导入就显示就绪。管理总览把用量、运行、质量和系统拆成独立数据源，显示本次验证数量与时间；读取失败显示权限、网络或服务错误，未读取值为“—”，不会用 `0` 冒充事实。

文档工坊上传改为流式有界暂存：文件名净化、扩展名白名单、大小上限、空文件拒绝、SHA-256 回执、冲突隔离、原子替换和失败清理均在后端执行。文档 ID 在删除、重解析和查看前拒绝路径穿越与控制字符；列表和扫描不再发布服务器绝对路径。前端逐项核验操作回执，批量重解析断线时明确显示“结果未知”，不会声称服务器一定继续执行。

Android 工作台将能力状态区分为本次已验证、最近缓存和离线旧状态。内存与磁盘缓存同时绑定账号和规范化后端地址指纹，切换服务器不再复用上一服务的 ETag 或能力结论；周期刷新合并并发请求，手动刷新会取消旧任务，避免迟到响应覆盖新事实。

完整审计、已修问题和保留边界见 `docs/code-audit-V388.md`。

## 明确限制

- 本轮没有生成新的 Windows 正式安装程序。源码发布门通过不等于 EXE 发布完成；正式版本仍须执行 `installer-native/build-all.bat` 并核对 EXE、`.sha256`、`.release.json` 三方一致。
- APK 是 debug-signed 测试包，不是应用商店正式签名包。
- 文档重解析后端目前仍是同步流程；虽然界面已经不再虚构断线后的结果，但“新代索引完成后原子切换”和持久 job receipt 仍是后续应做的事务深化。
- 较早的部分管理页与 App Repository 仍需继续迁移到统一的加载、真实空态、缓存旧值、权限错误和网络错误协议；审计清单已经记录，不能把本轮通过理解为整个代码库不存在其他改进空间。
- SHA-256 只能证明交付字节一致，不能证明文档内容正确、来源可信或正式发布者身份；外部文件和网页仍按不可信数据处理。
