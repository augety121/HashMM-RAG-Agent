# HashMM V519–V550 本轮说明

日期：2026-07-26  
Backend：V550  
Desktop / MCP / Native：1.32.0  
Android App：1.21.0（138）

## 结论

本轮没有把 V519–V550 做成 32 个彼此割裂的页面或开关，而是完成一条跨端工作主线：

`用户目标 → 结果契约 → WorkRuntime → 上下文与证据 → 桌面工作空间 → App 控制面 → 验收与继续`

原有 Chat、长任务、Browser Use、Computer Use、多 Agent、远程、画布与成果能力仍由既有运行时执行。V550 新增的是稳定的用户工作域、统一投影和跨端同步层，不创建第二套任务引擎，也不把模型文字当成执行证据。

## V519–V526：统一工作域

- 新增 `hashmm.workspace.v2`、`hashmm.workspace-run.v2`、`hashmm.outcome-contract.v2`、`hashmm.workspace-command.v2` 与 `hashmm.evidence-graph.v2`。
- 将不同执行器状态映射为同一用户生命周期：草稿、已规划、待开始、进行中、等待补充、等待确认、受阻、待验收、已验收、修改中、完成、失败、取消、中断与历史观察。
- 未知状态失败关闭为 `blocked`；历史导入的 `observed` 不会被升级为已完成。
- 个人工作空间聚合当前账号全部项目和未归类工作；具体项目仍是严格的 owner 边界。

## V527–V534：命令、上下文与证据

- 新增 owner-scoped Workspace API：私有 ETag 快照、Bearer SSE、工作详情、创建待执行工作及带修订号的控制/验收命令。
- 缺失对象和越权对象使用同一不可枚举 `404`；对象 ID、工作空间 ID、幂等键与命令修订号均有有界校验。
- Workspace 新工作在准入时生成结果契约和内容寻址的 Context Capsule；只持久化来源边界、摘要元数据和哈希，不持久化来源正文。
- 证据图只投影已有节点与边，不根据模型文本补写 supports、produces 或 verifies 关系。

## V535–V542：桌面端面向用户的工作空间

- 左侧一级入口收敛为“今天、项目、资料库、我的设备”，普通用户不再先理解 RAG、Agent 编排、MCP、Hook 或运行治理。
- “今天”合并待确认、正在推进和最近成果；“项目”用目标、交付物、验收标准与权限方式组织长期工作；“资料库”直接把真实可检索资料带回 Chat。
- 普通输入默认显示“自动”；资料方式、模型档位、多 Agent、画布、电脑操作等高级方式仍可展开使用。
- 管理员能力没有删除，仍保留在管理与治理页面；普通用户入口与管理员控制面分层。
- Workspace 快照使用账号隔离内存缓存和 Electron 加密磁盘缓存，在线时用 ETag 条件校验，离线只恢复通过 schema 与 trust 校验的最近快照。

## V543–V549：App 移动控制面

- App 优先读取 `/api/v2/workspaces/personal/snapshot`，只在服务器明确返回 `404` 时回退旧 Work Feed；网络错误、鉴权失败和不兼容 schema 不会伪装为旧接口成功。
- App 长连接优先使用 v2 Workspace SSE，Bearer 令牌只在请求头中；旧服务器兼容回退仍使用 owner-scoped v1 Work Feed。
- v2 状态、成果、证据数量、可用命令和待处理事项投影到原生工作台与详情页；未知状态映射为受阻，`observed` 保持历史记录。
- App 的持久快照继续使用现有账号隔离加密 LocalStore；数据未变化时复用 ETag，断线时明确显示最近同步结果。
- App 定位为查看、确认、接力和远程控制；桌面端继续负责本机文件、浏览器、终端与 Computer Use。

## V550：发布收口

- Backend、Desktop、Native 与 App 版本统一为 V550 / 1.32.0 / 1.21.0（138）。
- 帮助中心发行说明更新到 V550；旧 V518 记录保留但不再标记为当前版本。
- 新增工作域、上下文隔离、证据投影、owner 边界、个人聚合、ETag/304、不可枚举 404、桌面加密缓存、桌面入口和 App v2 信任边界回归。

## 明确限制

- Workspace 的“创建待执行工作”只负责持久化一条带结果契约的待执行记录；真正执行仍从 Chat、已有调度器或受控设备领取链路开始。页面或 HTTP 201 不等于任务已经执行。
- SSE 是变化通知，ETag 快照是断线、休眠、代理缓冲和数据缺口后的修复路径；客户端不会把单个增量包当完整工作空间覆盖本地状态。
- 真实公网多设备、对称 NAT、自有 TURN、24 小时稳定性、Windows Authenticode 发布者身份和 Android 商店签名需要真实外部环境验收，本地代码和测试不能替代这些结论。
- SHA-256 只能证明交付物完整性，不能替代 Authenticode 发布者身份。
