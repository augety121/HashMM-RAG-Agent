# 本轮说明 · V338（2026-07-17）—— 执行 Hooks 信任闸与桌面审计面板

本轮没有把资料中的产品宣传或未经证实数字直接写进代码，而是先对现有桌面执行链做旁路审计，
再用官方机制核对生命周期语义。审计确认了两个真实缺陷：`data/hooks/*.py` 会在启动时无信任导入；
代码 Hook 还能在内置权限检查之后请求改写参数，存在把已批准安全参数替换成高权限参数的风险。

HashMM 后端迭代号为 **V338**，桌面端、MCP client/server 身份版本与原生安装器版本为
**1.11.0**。MCP wire protocol 仍是项目已支持的 `2024-11-05`，本轮没有伪造一个不存在的协议升级。

## 已完成

### 1. Python Hook 不再“文件出现即执行”

- 目录里的新 Hook 默认状态为 `untrusted`，清单扫描只做受限文件读取、SHA-256 和 AST 函数清点，
  不导入未信任模块。
- 管理员信任请求必须携带界面刚看到的完整 64 位 SHA-256；后端重新读取快照并比较，文件在审查后
  发生变化就拒绝信任。
- 信任回执原子写入数据目录根部的 `hook-trust.json`；损坏、未知 schema 或非法摘要按未信任处理。
- 信任操作只做语法编译检查，不执行代码。新信任状态为“待重启”，只有下一次后端启动才加载。
- 文件缺失、symlink、非普通文件、超过 256 KiB、语法无效或内容变化均不加载。
- 已加载 wrapper 每次回调前重新核对信任回执与磁盘摘要；撤销或文件变化不等待重启即可失效。

### 2. 参数与权限边界收紧

- Python `pre_tool` 只支持观察或 `deny`，不再接受参数改写。旧 Hook 返回 `{"args": ...}` 时会记录
  警告并忽略。
- 传给 Hook 的参数、上下文和完成摘要使用深拷贝，嵌套 dict/list 的原地修改不能逃回真实工具参数。
- 代码 Hook 和声明式 Hook 都插入统一的 `hashmm.hooks` 工具入口，位于 permission 之前；所有经
  `tool_registry` 的主对话、AgentLoop 和工作流路径共享同一裁决点。
- 声明式 `confirm` 会拒绝当前调用并要求人工确认，`block` 直接拒绝，均不依赖模型提示词服从。
- 声明式配置损坏、Hook 返回非法裁决类型或统一 Hook 层本身异常时均 fail closed，不再静默执行工具。

### 3. 声明式正则的资源边界

- 规则上限 100 条、每条最多 64 个工具名、pattern 最长 160 字符、匹配文本最多 2048 字符。
- 禁止分组、断言、反向引用和花括号量词，并限制 `*`/`+`/`?` 数量，拒绝 `(a+)+$`、
  `(a|aa)+$`、多重 `.*` 等常见高回溯构造。
- 匹配会遍历受限的嵌套参数值，不能因为危险命令藏在子对象中就完全看不到。
- 保存使用同目录临时文件、flush/fsync 和原子替换；非法新规则不会覆盖原有有效配置。

### 4. 桌面端“执行 Hooks”面板

- “高级能力”中把原 webhook “触发器”明确改名为“自动触发”，另增“执行 Hooks”，避免两个概念混淆。
- 无代码区可新增、启停和删除 notify/confirm/block 规则，并展示工具、pattern、动作和生效状态。
- Python 区展示来源、事件、完整 SHA-256、大小、修改时间、信任时间和
  `untrusted / changed / active / trusted_pending_restart / unsafe / missing` 等真实状态。
- 信任前弹窗再次显示来源、完整摘要和“以后端系统用户完整权限执行”的风险；撤销入口立即生效。
- 普通登录用户只有可见性，信任、撤销和全局规则修改均由后端 `require_admin` 强制检查，按钮禁用不是
  权限事实源。

## 仍然存在的边界

- 被明确信任的 Python Hook 与后端同进程、同 OS 权限运行，目前没有进程沙箱或可强制中断的硬超时；
  2 秒只做慢 Hook 遥测，不是隔离承诺。
- SHA-256 信任防止“审查后内容悄悄变化”，不证明代码本身安全，也不能防御已经控制同一 OS 用户和
  信任回执文件的攻击者。
- 当前可执行用户事件只开放 PreToolUse、PostToolUse、Stop 的安全子集；尚未复制 Codex/Claude 的
  全部生命周期事件、图形化事件拓扑或项目级 Hook 来源层级。
- 桌面清单不直接渲染 Python 源码；管理员仍需在可信编辑器中逐行审查文件，再对照界面完整摘要。
- 声明式 pattern 是受限正则子集，不兼容任意 Python 正则；这是避免 ReDoS 的明确取舍。
- 安装包完整性哈希不能替代 Authenticode 发布者身份。
