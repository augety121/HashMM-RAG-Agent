# HashMM V361 本轮说明

日期：2026-07-19

## 本轮结果

本轮集中修复桌面端长时间使用时最影响信任感的四类问题：旧运行记录打开即崩溃、PPT 永久停在加载态、不同对话共用输入草稿、文档重复从服务器取回。右侧文档工作区、帮助中心和设置页面也统一为更清晰的用户化信息架构。

## 关键改进

- 右侧“运行”兼容早期不完整 `run_manifest`、旧版团队状态和空步骤；缺少证据时显示“未记录”，不再读取不存在的 `status` 让整页崩溃。
- 输入草稿改为“账号 + 对话”双重隔离，并在本机持久化最近草稿；切换消息不会把 A 对话的未发送文字带到 B 对话。
- 文件预览增加持久 Cache Storage 和 ETag 条件校验：重开桌面端先显示本机缓存，后台未变更返回 304，不重复下载或解析 Office 正文。
- 文件读取仍先做会话属主校验；下载端点新增受控 `inline=1` 用于 PDF 右栏，同时修复鉴权前枚举目录和路径穿越风险。
- PPT 预览加入明确的加载、成功、失败与重试状态；提取到的逐页内容以 16:9 幻灯片形式显示，复杂动画、媒体和精确排版仍以原文件为准。
- Word 改为居中的只读纸张视图，PDF 使用右栏内嵌阅读器，图片、表格、代码和画布继续共用同一文件检查器。
- 帮助中心重做为 7 个真实用户任务入口，每个详情页包含使用方式、边界、恢复建议和“填入当前对话”操作。
- 设置 10 个页面保留真实功能，统一增加分组、页面说明、数据作用范围和一致的内容容器；没有用演示数据替换实际配置。
- 只读参考用户提供的 Codex 源码归档中会话状态和上下文压缩的协议组织方式；没有把源码目录中的实现描述当作已验证的 HashMM 功能。

## 已知边界

- 客户端无法在完全不联系服务器的情况下知道另一台设备是否修改了文件，因此采用“本机缓存立即显示 + 小型 ETag 条件校验”；未变化时服务器不传正文也不重新解析 Office。
- PPT 的快速预览以可提取文本为主，不承诺还原动画、嵌入音视频、特殊字体和所有 PowerPoint 版式；原文件下载始终保留。
- Cache Storage 是当前账号在当前设备上的体验缓存，不是执行证据，也不替代服务端属主校验。
- 本轮安装器未配置 Authenticode，状态为 `NotSigned`；APK 是 Debug 构建。SHA-256 只证明当前制品完整性，不能替代发布者身份签名。
