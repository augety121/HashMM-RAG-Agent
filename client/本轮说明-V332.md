## 你最关心的：并发怎么开（跑分提速）

**桌面端（本包）**——两种方式任选：
1. 环境变量：启动后端前 `set HASHMM_BENCH_PARALLEL=4`（基准级，上限 4）
   ＋ `set HASHMM_BENCH_CONCURRENCY=8`（逐题级，付费 API 可开 8~12）。
2. API 调用：`POST /api/selftest/bench/comparable-run`，body 里加 `"parallel": 4`。
   前端封装 `benchComparableRun(ids, "standard", 4)` 已带该参数。
- 总 LLM 压力 ≈ 基准级 × 逐题级（例：4×8=32 路并发请求）。DeepSeek 付费档没问题；
  本地 vLLM 小卡别超 4×4。humaneval/kotlin 会在**本机**真跑代码/编译，故基准级硬上限 4。

**GitHub CI**——Run workflow 时直接填两个新输入：
- `bench_workers`（同时跑几个基准，默认 2，上限 6）
- `concurrency`（逐题并发，默认 6）
- benches 现在认全部 11 项 + 别名：`nodocker`（免 Docker 六项）/ `all`。

## 上传 GitHub 时务必注意

打开 CI 最小包文件夹**全选内容**上传（或压缩后在 GitHub 网页 upload），确认仓库里能看到
`.github/workflows/docker-benchmarks.yml`——Windows 资源管理器拖拽**不含隐藏文件夹**，
上一版三个包全都因此丢过这份 workflow（这正是"点了 Run workflow 没反应/找不到 workflow"的原因）。

要跑 GAIA/WebVoyager：仓库 Settings → Secrets and variables → Actions 新增
`HASHMM_SERPER_API_KEY`（serper.dev 免费注册）。不配也不报错，这两项会以
「缺搜索 key」跳过并把原因写进 Artifact。
