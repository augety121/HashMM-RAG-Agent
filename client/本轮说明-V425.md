# HashMM V422–V425 本轮说明

日期：2026-07-25  
最终版本：Backend V425 / Desktop、MCP、Native source 1.22.0 / Android 1.15.0（132） / database schema 27

## 本轮完成内容

### V422：统一的远程授权待办

- 远程会话仍由 owner-bound `RemoteSessionRegistry` 决定授权，WorkRuntime 只做用户可见投影，不能反向放大权限。
- `action_inbox` 对远程工作只公开 session、状态、generation、授权范围和 predecessor；设备原始 ID、Remote ticket、TURN 凭据和账号令牌均不进入桌面/App 待办。
- 桌面端与 Android App 都以 `hashmm.action-inbox.v1` 为权威来源；仅在旧服务器没有该契约时才使用兼容回退。

### V423：把真实传输观测变成完成证据

- host 与 viewer 继续上报浏览器/WebRTC 实际选中的传输摘要。
- WorkRuntime 按 `session + generation + role + minute bucket` 幂等写入，避免高频统计污染工作时间线。
- 工作快照只保存 allowlist 字段：角色、candidate type、protocol、RTT、packet loss。候选地址、SDP、字节内容、令牌和模型文字都不作为执行证据。

### V424：最小权限设备接力

- 新增 `POST /api/remote/sessions/{id}/handoff`。
- 接力不是修改 viewer ID，而是创建新的 pending session，并用 `predecessor_session_id` 建立谱系。
- successor 权限必须是 predecessor 已授权权限的子集且必须包含 `view`；任何 scope escalation 都失败。
- predecessor 进入 `superseded`，generation 递增、控制序列清空、旧票据立即失效；同一接力重试返回现有 successor，避免重叠授权。
- fresh/legacy SQLite 都会补齐 lineage 列与 owner-scoped 索引；外部 owner 无法枚举会话。

### V425：正常完成与验收回执

- 新增 `POST /api/remote/sessions/{id}/complete` 和 WebSocket `complete / remoteCompleted`。
- 正常完成状态为 `completed`，投影到 WorkRuntime 的 `delivered`；掉线、撤销和超时仍分别保持 `interrupted / revoked / expired` 语义。
- 完成回执采用 `hashmm.remote-completion.v1`，根据 host/viewer 传输记录给出：
  - `verified`：两端均有观测；
  - `partial`：只观测到一端；
  - `not_observed`：没有可核验传输样本。
- Android 离开远程控制或返回设备列表时先发送正常完成消息，再关闭流与信令；服务端完成后双方解除配对，旧票据失效。

## 安全与正确性边界

- 缺失对象与其他 owner 的对象继续返回不可枚举的 404。
- 接力不会复用旧 ticket、generation 或 replay sequence。
- 模型输出不是传输或完成证据；完成核验只读取持久化的结构化传输事件。
- 完成/接力摘要均有长度限制，持久化审计使用字段 allowlist。
- 本轮未修改登录密钥、Supabase 私密配置或启动脚本的安全降级策略。
