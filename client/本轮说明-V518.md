# HashMM V499–V518 本轮说明

日期：2026-07-26  
Backend：V518  
Desktop / MCP / Native：1.31.0  
Android App：1.20.0（137）

## 本轮目标

本轮没有按版本号堆叠二十个孤立页面，而是把 V499–V518 收敛为一条面向用户的工作链：

1. 用户定义项目目标、交付物、成功条件与权限方式。
2. Chat、长任务、浏览器、画布、多 Agent、Computer Use 和跨设备执行继续进入同一 WorkRuntime。
3. 用户在任务运行时可补充文字与真实附件。
4. 桌面端与 App 读取同一工作事实、待处理事项、成果与验收状态。
5. 管理员能力保留在治理界面，普通用户不再直接面对内部模型、路由和诊断结构。

## V499–V503：项目与进行中工作

- 数据库项目表新增目标、交付物、成功条件、权限方式、状态、归档与修订号，并通过幂等迁移修复旧库。
- 项目创建、读取、修改和对话绑定继续执行 owner 检查；不存在与不属于当前账号的对象不提供可枚举差异。
- 对应 Chat 注入用户编写的项目简报；简报被明确标记为用户上下文，不能扩大工具权限。
- 运行中的转向支持附件。服务端不接受客户端路径或 URL，只接收已提交到当前对话目录的文件名与摘要，并重新计算 SHA-256。

## V504–V508：证据、画布、成果与例行工作

- 复核现有 Browser EvidenceRef、Canvas evidence link、内容哈希验证、来源失效传播和完成门禁，继续以 WorkRuntime 为唯一任务事实源。
- 普通用户例行工作改为 owner-scoped API，支持创建、立即运行、启停和删除；不再依赖管理员接口。
- 每日工作简报由服务端基于账号范围内的对话、项目和工作记录确定性生成，不把模型文字当作执行事实。

## V509–V513：多 Agent、模型策略、偏好与跨端分工

- 多 Agent 继续通过运行契约、能力准入、写隔离、只读验证者和完成门禁工作；用户侧只展示协作摘要、阻塞、成果和下一步。
- 不新增第二套模型路由或跨端状态。模型/MCP/Hook/Computer Use 继续服从运行时能力、权限、审计和回执。
- App 根据登录令牌中的角色只展示适合当前账号的页面；这是体验分层，真正权限仍由后端逐请求校验。

## V514–V518：统一入口、缓存、信任与发布

- `/api/user-work/overview` 聚合项目、WorkRuntime、行动收件箱、例行工作、设备与信任状态，支持项目过滤、私有 ETag 与 `304`。
- 侧栏统一搜索限定当前账号，覆盖对话、消息、项目与工作记录；项目搜索结果可驱动已挂载工作台切换。
- 工作画布继续使用账号绑定的本地加密缓存和服务端 ETag；App 继续使用账号与后端地址共同分区的本地快照。
- 版本同步到 V518 / 1.31.0 / 1.20.0（137），并加入本轮回归测试。

## 不冒充完成的外部验收

以下不能仅靠本机代码和单元测试证明，因此本轮不会写成“已完成”：

- 真实公网多设备与对称 NAT 可达性。
- 自有 TURN 的容量、地域、证书与故障切换。
- 24 小时持续运行、睡眠恢复、弱网和断网重连。
- Windows Authenticode 发布者身份与 SmartScreen 信誉。
- 各模型供应商真实账号的额度、计费、限流和兼容性。

这些项目需要在目标服务器、真实账号、真实设备和正式证书环境中单独验收。
