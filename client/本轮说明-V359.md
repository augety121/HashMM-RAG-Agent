# HashMM V359 本轮说明

日期：2026-07-19  
版本：Backend `V359`，Desktop / MCP / Native `1.17.15`，App `1.10.63`（versionCode `104`）

## 本轮结果

1. 修复嵌入浏览器“页面已经正常显示，但顶部仍残留未授权跳转错误卡”的状态竞态。主进程现在区分最后一次成功提交的主文档与随后被拒绝的候选跳转；存在可用页面时保留页面、清空展示错误，同时保留阻止事件供审计。
2. 删除浏览器中冗余的大错误卡及“重试 / 用 Google Chrome 打开”按钮。真正的冷启动加载失败只显示一行紧凑状态，重载与外部打开继续由地址栏右侧真实操作承担。
3. 从用户提供的 `codex-main (1).zip` 只读核对 Codex 的上下文压缩机制：自动压缩与手动压缩共用可见生命周期，手动入口为显式 thread compact 请求，压缩事件区分自动与手动来源；未执行压缩包中的任何脚本。
4. 新增长对话手动压缩 API：`POST /api/conversations/{conv_id}/compact`。接口先执行会话属主校验，再生成派生检查点；不存在对象和越权对象沿用不可枚举边界，响应只返回统计数据，不泄露摘要正文。
5. 自动与手动压缩共用 `conversation_compactions`，新增 `last_trigger=auto/manual` 审计字段。手动压缩保留最近原文并折叠更早内容，完整消息不删除；新消息不足时确定性返回无需建立新检查点，不伪造执行结果。
6. 桌面端右侧“上下文 → 系统”加入真实“压缩上下文”操作，运行中禁止重复提交，完成后刷新同一会话的上下文透视。App 工作台上下文页接入同一个 owner-authenticated API，不再是演示按钮。
7. 没有照搬 Codex 的 active-turn steer 外观。HashMM 当前还缺少可跨请求验证的活动 run 注册表；在这个前置条件完成前不加入不能绑定真实 turn ID 的假“插话/转向”功能。

## 安全与正确性边界

- 浏览器已加载页面与被拒绝的候选跳转是两个状态：前者决定是否向用户显示页面错误，后者继续进入审计记录，不能因为隐藏旧卡而放宽跨站授权。
- 压缩检查点是续接上下文的派生数据，不是工具执行证据，也不删除原始消息。响应中的完成、文件或命令主张仍需真实工具结果或确定性检查确认。
- 本轮参考的是用户提供的 Codex 源码归档中的可核对实现，不把产品截图或模型描述当作实现证据。
