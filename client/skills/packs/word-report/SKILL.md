# 专业 Word 报告：操作手册

## 何时使用
交付物是一份**正式文档文件**（方案/报告/纪要/说明书），用户会拿去转发、打印或存档。

## 工具分工
- `create_document`：**唯一交付通道**。doc_type=docx，title 是文件名级标题，content 传完整 Markdown 正文。
- `kb_search` / `kg_query`：正文涉及用户自己的项目、术语、历史结论时先查内部，再动笔。
- `web_search` + `fetch_url`：需要外部事实/数据时先查证，正文中注明来源。
- `update_todo`：章节超过 4 个时先列大纲计划。

## 流程
1. **定规格**：先确认（或按行业惯例默认并说明）三件事——读者是谁、篇幅量级、要不要数据表。
2. **列大纲**：把章节结构先发给用户过目（一屏以内）；用户没异议或明确赶时间时直接进入成文。
3. **成文规范**：
   - 标题层级用 Markdown `#`/`##`/`###`，工具会渲染成 Word 样式；
   - 数据一律用 Markdown 表格，不要用竖线堆文字；
   - 每章开头一句话交代本章解决什么问题；结尾避免空话（"综上所述"式收尾只允许出现一次）。
4. **自检**：生成前通读一遍 content——检查数字前后一致、称谓统一、无占位符（"XXX""待补充"必须清零或明确标注）。
5. **交付**：调 `create_document` → 回复里给下载链接 + 30 字内容摘要 + "哪里可以再定制"一句。

## 红线
- 不虚构数据、案例和引用；没有来源的数字宁可写"需实测确认"。
- 聊天回复里不要整篇粘贴正文——文件即交付物，聊天里只放摘要。
