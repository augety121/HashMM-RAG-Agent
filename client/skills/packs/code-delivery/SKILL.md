# 代码工程交付：操作手册

## 何时使用
用户要拿走能用的代码（脚本/模块/修复补丁），而不是一段概念解释。

## 工具分工
- `execute_code`（python）：**验证**。任何交付前的代码都要在这里跑一遍（或跑其核心逻辑的最小样例）。
- `create_file`：**交付**。最终 .py/.json/.md 等文件用它落盘并给下载链接。
- `read_file_range` + `file_tree`：**读现场**。改用户已有文件前先看目录结构、再按行读相关片段，禁止凭空猜文件内容。
- `str_replace`：**做小修改**。对已有文件做定点替换（老串必须唯一），比整文件重写更安全。
- `update_todo`：3 步以上的工程任务先列计划。

## 流程
1. **复述需求**：一句话确认输入、输出、运行环境；有歧义就给出你选的默认并说明。
2. **先读后写**（涉及已有代码时）：`file_tree` 定位 → `read_file_range` 读上下文 → 再动手。
3. **小步验证**：写完核心函数立刻 `execute_code` 跑最小用例；报错自己读栈自己修，修不动三次以上再向用户说明卡点。
4. **交付件标准**：
   - 文件头部注释：用途、用法（一行运行命令）、依赖。
   - 函数有 docstring；魔法数字提成常量；错误路径有明确报错信息而非裸 pass。
   - 提供 1 个可直接运行的示例入口（`if __name__ == "__main__":`）。
5. **交付**：`create_file` 落盘 → 回复里给下载链接 + "怎么跑 + 验证过什么"两三句。不把整个文件内容重复粘贴在聊天里。

## 红线
- 没跑过的代码不说"已测试"；受环境限制没法跑的（如需要 GPU/外网服务）明确标注"未在当前环境验证"。
- 修改用户文件时，只动与需求相关的行；顺手重排格式属于制造 diff 噪音，禁止。
