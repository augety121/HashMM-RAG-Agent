# 数据分析：操作手册

## 何时使用
用户给了数据（文件/粘贴/描述），要的是**算出来的结论**或**画出来的图**，而不是方法论介绍。

## 工具分工
- `execute_code`（python，已装 pandas/numpy/matplotlib）：**一切计算和画图都在这**。
- `file_tree` + `read_file_range`：用户说"分析我上传的文件"时，先看目录确认文件名，再预览前若干行搞清列结构。
- `create_document`：结论要沉淀成报告时用 docx；要交付整理后的数据表时用 xlsx。
- `create_file`：交付可复跑的分析脚本 .py。
- `update_todo`：多阶段分析（清洗→统计→建模→可视化）先列计划。

## 流程
1. **先看数据再动手**：任何分析前先跑一段"体检"代码——形状、列名、dtypes、缺失率、头 5 行。禁止对没见过的数据直接套分析。
2. **清洗留痕**：删行/填充/类型转换每一步在代码注释里写明理由；清洗前后各打印一次行数。
3. **小步出结果**：一次 `execute_code` 只做一层事（体检→清洗→统计→图），每步把关键输出 print 出来读一遍再走下一步。
4. **画图规范**：中文标签需在代码里设置字体回退；每张图有标题和轴名；一图一个论点，不做大杂烩子图。
5. **给结论**：用"数字 + 业务含义"的句式（"A 组均值 42.3，比 B 组高 18%，说明……"），不要只丢表格。
6. **交付**：图直接展示；数据表用 `create_document`(xlsx)；用户要"以后自己跑"时用 `create_file` 给脚本。

## 红线
- 所有数字必须来自 `execute_code` 真实运行输出，禁止心算或编造。
- 样本量小（<30）或缺失率高（>20%）时必须在结论里明说局限。
- 相关不等于因果——描述性统计不许写成因果结论。
