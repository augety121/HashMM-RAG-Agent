# 进度 / 状态报告 —— 配方

**读者一眼要得到**：到哪了 → 卡在哪 → 下一步谁做什么。

## 区块顺序
1. 页头：标题=任务名，副题=一句话现状结论；meta 行给生成时间/范围/状态。
2. 「需要你拍板」置顶：只列真决策，每条附下一步动作或命令（`code` 标签）。
3. 指标带 `wc-grid`+`wc-stat`：3–5 个（完成数/失败数/耗时/待办），语义色只标异常
   （good/warn/bad），正常值用默认色——满屏彩色等于没有重点。
4. 时间线 `wc-timeline`：关键节点（done/fail/now），每条 ≤1 行，失败节点必须出现。
5. 待办卡 `wc-card`：未完成项 + 可复制的下一条命令（`data-wc-copy`）。
6. 署名 footer。

## 红线
- 状态措辞用事实（"3/5 通过"），不用情绪（"进展顺利"）。
- 长任务原地重生成同一文件；跑完所有数据前不写"已完成"。

## V216 组件
- 覆盖率/完成度用 `wc-progress`（bar 内 `<i style="width:NN%">`，语义色只标异常）。
- 指标卡可加 `wc-trend up/down/flat` 角标标环比；有真实序列时用
  `<span data-wc-spark="a,b,c">` 出迷你趋势图——**没有真实数据别画趋势**。
- 长日志/长证据收进 `wc-details`（summary 一句话 + `.bd` 正文），首屏保持一屏内可读。
