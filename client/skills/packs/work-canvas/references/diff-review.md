# 变更看板（diff）—— 配方（fanbox 能力的画布化）

**读者一眼要得到**：这轮碰了哪些文件 → 每处改了什么 → 我要不要放行。

## 区块顺序
1. 页头：标题=本轮改动主题，副题=一句话说清改动目的。
2. 「需要你拍板」：合入/回滚/部分采纳，逐文件可拆分时说明怎么拆。
3. 指标带：文件数 / +新增行 / −删除行 / 待确认项（新增 good、删除默认、待确认 warn）。
4. 变更主体 `wc-changed`：
   - 左列 `wc-files`：每文件一行 `wc-file`（`data-target` 指向 diff 面板 id），
     状态点 dot mod/add/del + 文件名 + `+a −d` 统计；
   - 右侧 `wc-diff`（同 id，`hidden` 由 canvas.js 切换）：`wc-diff-head` 放文件路径
     和"复制 diff"按钮（`data-wc-copy` 指向隐藏的 `<pre>` 统一 diff 文本）；
     `wc-diff-body` 逐行 `dl add/del/ctx/hunk`，行号放 `.ln`，代码放 `.tx`。
   - 表尾必配 `wc-legend`：新增/删除/修改文件三色图例（红线）。
5. 建议卡：合入/回滚建议 + 风险点（改了公共契约要点名下游）。
6. 回喂 composer：chips 预置"合入全部""回滚 <文件>""解释 <文件> 第 N 行为什么这么改"。

## 红线
- diff 内容必须来自真实改动（agent 自己刚写过的），行号与源码对得上；截取要在
  hunk 行注明 `@@ 位置 @@`，禁止无中生有的示例行。
- 超过 ~40 行的 hunk 折叠为"上下文 N 行未变"一行，别把整文件贴成 diff。
- 只展示 + 复制，绝不从画布改用户文件（非破坏）。

## V216 组件
- **词级标注**：改动行内用 `<mark class="wc-mark">` 圈出真正变化的词/标识符（例：同一行只改了
  `docHtml`→`shownHtml`，就只 mark 这两个词）。红线：mark 必须对应真实 token 变化，禁止整行乱标。
- **热度徽章**（fanbox `app.js:452-467` 机制移植）：同一文件本轮被改多次时，`wc-file` 里加
  `<span class="cnt">改·N</span>` 并在该行 style 上设 `--heat:0.4~1`（次数越多越醒目）；只改一次不加。
- 超长 diff 的次要文件整块收进 `wc-details`，首屏只展开读者必看的 1-2 个文件。
