# 知识库溯源回答：操作手册

## 何时使用
用户要的是"**我的资料里**怎么说"，答案的价值在于**可溯源**——每个论断都能指回知识库原文。

## 工具分工
- `kb_search`：**主通道**。mode 默认 mix；查具体事实用 naive（向量）补一枪；查关系脉络用 kg。
- `kg_query`：实体之间的关系问题（"A 和 B 什么关系""谁负责过 X"）优先走图谱。
- `read_file_range`：命中片段需要看上下文时按行精读原文件，避免断章取义。
- `web_search`：**仅当**用户明确允许"库里没有就上网查"时才用，且答案里必须区分"库内结论"与"网络补充"。

## 流程
1. **先检索后回答**：哪怕自以为知道答案，也必须先 `kb_search`——这个技能的承诺就是"以库为准"。
2. **多路检索**：首查不理想时换 2~3 组同义关键词再查（专业术语 ↔ 口语说法互换），必要时切 mode 重试。
3. **核对上下文**：对将要引用的关键片段，拿 `read_file_range` 看前后文，确认没有把否定句读成肯定句。
4. **组织答案**：
   - 直接回答问题（1~3 句）；
   - 逐条列依据：`——出处：《文件名》`，引用原文控制在一两句内；
   - 库内信息互相矛盾时，两说并列并给出各自出处，不擅自裁决。
5. **答不出的处理**：检索三轮仍无有效命中 → 明确说"知识库中没有找到相关记录"，并列出已尝试的关键词，让用户判断是换词还是补资料。

## 红线
- 禁止把模型自身知识包装成"知识库里说的"——库里没有就是没有。
- 出处必须真实存在于检索结果中；不确定出处的内容宁可不写。
