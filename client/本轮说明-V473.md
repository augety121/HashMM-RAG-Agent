# HashMM V473 本轮说明

V459–V473 的目标不是继续增加孤立页面，而是把 Chat、长任务、多 Agent、浏览器、Computer Use、画布、桌面执行和 App 接力收敛到同一套可审计的 Work Kernel。用户只表达目标，系统依据运行时事实选择能力；任何设备执行、工作流沉淀和主动建议都不能绕过所有者、版本、租约、回执与明确确认。

## V459–V473 已实现

- **V459 · 统一工作准入**：新增 `hashmm/agent/work_kernel.py`。所有通过 `work_runtime.create_run` 创建的工作都会得到同一份服务端准入快照，不依赖模型自述。
- **V460 · 目标与验收契约**：在准入阶段确定性编译用户目标、任务类型、执行模式和成功条件；进度按真实验收条件展示，不虚构百分比。
- **V461 · 运行时能力事实**：能力可用性来自已挂载的工具/运行时注册表。加载不完整或异常时失败关闭，不把未知工具当成只读能力。
- **V462 · 因果工作种子**：只把目标与明确验收条件写入初始因果图；模型推断边固定为 `false`，后续执行关系必须由事件、回执或持久化事实补充。
- **V463 · 设备放置意图**：桌面端与 App 可以读取当前账号在线设备，并为工作记录目标设备；选择设备只记录意图，不自动授予执行权。
- **V464 · 短期执行租约**：设备执行继续要求 owner、目标设备、工作 revision、租约 ID、generation 和幂等键一致。过期租约的旧幂等键不能重新取得权限。
- **V465 · Dispatch 接入 Work Kernel**：桌面调度、计划子任务和重试任务都会建立对应 WorkRun，不再形成无法被 Chat、画布和 App 观察的第二套任务状态。
- **V466 · 设备绑定的完成回执**：桌面轮询只有在取得所选设备的执行租约后才获得执行权；完成请求必须提交同一设备、租约 ID 和 generation。仅有账号令牌不能替另一台设备结束任务。
- **V467 · 证据化工作流候选**：只有已完成工作中的有效、成功执行回执可以生成工作流候选；仅保存工具名、参数哈希、作用域和副作用分类，不保存原始参数或结果正文。
- **V468 · 独立重复验证**：工作流必须由同一所有者的另一条已完成 WorkRun 产生相同有效动作签名，才会进入 `verified`。源运行不能充当自己的复现证据。
- **V469 · 显式发布**：发布要求 `verified` 状态、匹配 revision、独立复现记录和用户明确批准。页面按钮已接真实 API，不是本地演示开关。
- **V470 · 持久化主动工作项**：主动提醒只从“等待设备”或“可重试失败”等持久化事实生成，owner-bound、可批准、可忽略，模型文本本身不能产生执行命令。
- **V471 · 注意力预算与双阶段执行**：每个用户最多保留 24 个活跃主动工作项；建议与执行是两次独立操作，未经批准调用完成接口会返回 `approval_required`。
- **V472 · 桌面/App 双端接通**：桌面工作画布和 Android Work Canvas 使用同一在线设备、放置和工作流发布接口；App 定位为查看、确认与接力控制面，不复制桌面诊断后台。
- **V473 · 版本与发布收口**：数据库 schema 升至 29；Backend `V473`，Desktop/MCP/Native `1.29.0`，Android `1.18.0 (135)`；启动器最低完整版本同步为 473。

## 安全与一致性边界

- WorkRun、ExecutionLease、Workflow、ProactiveWorkItem、设备和 Dispatch 均按 owner 隔离；不存在与越权对象使用不可枚举结果。
- 设备选择不会扩权，真正执行必须再次取得短时租约。
- Dispatch 完成在修改任务状态前校验设备和租约，避免“账号已登录即可替任意设备报完成”的失败开放。
- 工作流只使用结构化执行回执，模型回答、页面文案、HTTP 成功码和工具参数正文都不能单独证明工作完成。
- 主动建议不会自动执行，预算耗尽时不继续创建新的活跃项。
- 外部网页、上传文件、命令输出和仓库差异继续作为不可信数据处理，不能覆盖系统或用户指令。
