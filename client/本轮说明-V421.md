# HashMM V421 本轮说明

V421 解决的是一条具体架构断点：远程控制已经有会话、权限票据、TURN、审计与真实环境验收，但它仍可能脱离 Chat 和长任务形成第二套生命周期。本轮把远程协作绑定到 V373 起的统一 `WorkRuntime`，让桌面端与 App 看到的是同一项工作的申请、状态、证据和中断，而不是两个产品各自维护的“远程页面状态”。

这里的完成只指代码和确定性验证。真实公网双设备、对称 NAT、自有 TURN 在线部署和连续 24 小时稳定性仍必须在用户的真实基础设施上验收，本轮没有伪造这些结果。

## 统一工作绑定

- 新增 `hashmm/api/remote_work.py` 作为远程能力进入工作运行时的唯一绑定边界。
- 请求显式给出 `work_run_id` 时，后端通过 owner-bound `WorkRuntime.get_run` 校验；不存在、格式无效和属于其他账号统一表现为“未找到”。
- 未给出运行时且已经有稳定 `client_request_id` 时，以 `remote-request:<id>` 作为幂等来源创建专用远程工作。网络重试不会生成第二项工作。
- 没有稳定请求 ID 的旧客户端仍可创建远程工作，但不会把原始 host/viewer 设备 ID 写入工作账本，只保存不可逆短哈希引用。
- `WorkRuntime` 新增用户可理解的 `remote / 远程协作` 类型；桌面端统一运行面板可以直接展示它。

## 生命周期投影

- `requested` 投影为等待批准，`approved` 投影为运行中，`denied/revoked/expired` 投影为取消，`interrupted` 投影为中断失败。
- 事件幂等键包含远程 session、generation 与事件类型；数据库提交成功但调用方重试时不会复制同一生命周期事件。
- 只有专用 `kind=remote` 工作会随远程状态改变整体状态。若远程能力绑定在 Chat、Loop 或 Team 上，只追加一个有界子事件，不会把父工作错误标成完成或取消。
- 投影发生在持久化会话与权限审计成功之后；投影失败会拒绝继续扩权，而不是让控制能力在账本缺失时继续运行。
- 服务重启将遗留会话转为 `interrupted` 时会按相同幂等规则补投影，保证重启恢复后跨端状态一致。

## 迁移与兼容

- 数据库 schema 从 25 升至 26，`remote_sessions.work_run_id` 成为权威列。
- 旧 `work_id` 只在 `work_runs.id` 存在且 owner 相同的情况下回填。无法证明所有权的历史值保留为兼容数据，但不会被采用为权威绑定。
- HTTP 请求同时接受新 `work_run_id` 和一版兼容别名 `work_id`；两者冲突时直接拒绝，不静默选择其中一个。
- 响应同时返回权威 `work_run_id` 和兼容 `work_id`。该兼容层可在客户端全部升级并完成遥测确认后移除。
- 远程列表 schema 升为 v2；WebRTC 信令协议仍为 `hashmm.remote.v1`，本轮没有无必要地破坏既有客户端。

## 跨端请求语义

- HTTP 与生产 WebSocket 路径在创建工作前验证 scope、设备边界和请求 ID。
- 桌面远程查看器为一次显式连接生成稳定 UUID；握手失败前的网络重试复用该 ID。
- Android 对每个 host 保存当前连接请求 ID；收到 ready 或明确 pairFail 后清除，下一次用户显式连接会获得新 ID。
- 同一设备不能作为自己的 viewer；未知 scope 不会被当成只读权限；模型文本不能改变远程授权或工作状态。

## 已完成的确定性验证

- V421 定向后端回归：36 passed，覆盖 owner 绑定、不可枚举越权、兼容字段冲突、迁移、幂等创建、生命周期投影和生产 WebSocket 入口。
- Backend 全量：1401 passed，8 skipped；3 个警告均为测试依赖的已知弃用提示。
- Frontend：32 个测试文件、120 项测试通过；TypeScript 检查与 Next.js 生产构建通过。
- Desktop：远程会话安全 Node 回归通过，包含稳定 `clientRequestId` 静态门。
- Android：`:app:compileDebugKotlin` 通过，确认信令客户端修改可编译。
- Desktop release source gate：desktop 1.21.1、backend V421、内置运行时依赖指纹与 WebUI 完整性检查通过。

## 尚未完成、不能宣称完成的事项

- 没有两台真实公网设备和两种独立网络，不能宣称端到端远程已经通过真实设备验收。
- 没有实际可用的自有 TURN 域名、TLS 证书与 secret，不能宣称对称 NAT 下已经稳定中继。
- 没有真实等待连续 24 小时，不能宣称达到生产稳定性门槛。
- 本轮没有生成新的 Authenticode Windows 安装器。旧 `HashMM-Setup.release.json` 仍属于 V420/1.21.0 旧成品，不能改写成 V421；正式 EXE 必须重新走 `installer-native/build-all.bat` 并核对 EXE、`.sha256`、`.release.json` 三方一致。
- Android Release APK 仍需发布者私钥签名后才能公开分发；Debug 编译通过不等于商店发布验收。
