# HashMM V347 本轮说明

日期：2026-07-18

## 本轮完成

- 把长任务的“需要用户补充”从临时 UI 提升为可恢复协议 `hashmm.input-request.v1`。请求绑定真实 assistant message ID，包含问题、原因、最多三个去重选项和 `waiting_input` 状态。
- 后端所有主要 Chat 路径接入同一生命周期：意图澄清、答案规划、AgentLoop、子 Agent 编排、普通直答和 ReAct。不存在生成一条演示消息却未接入 Agent 主链的旁路。
- 等待状态持久化到现有 SQLite/Supabase 消息；Supabase `client_activity` 同步 `needs_input`。无需新增 SQL 字段，也没有放宽 RLS 或对象属主边界。
- 用户从桌面端或 App 在同一会话回复后，后端把未决请求转为 `resolved` 并清理待办活动；重开会话、刷新页面或换设备不会丢失问题。
- Desktop Chat 新增任务安全暂停卡，选项可直接回复；统一右栏显示同一待处理问题并把选项带入输入框。桌面 UI 使用图标，不新增 emoji。
- App Chat 新增同源暂停卡和可点选项；修复 `waiting_input` 被当成 streaming 而永久显示生成动画。动态页区分“正在生成”和“等待你的输入”，点击回到原 Chat 接管。
- 消除终态同步竞态：AgentLoop 与子 Agent 不再先向 Supabase 异步写 `complete` 再写 `waiting_input`；澄清解析完成后只提交一个权威终态。
- 对标依据为 OpenAI Codex 官方 app-server 的 user-input/server-request 生命周期及 Anthropic Claude Code 官方的权限模式、会话恢复和 turn 限制。HashMM 只迁移可验证的生命周期原则，未声称复制其内部实现。

## 部署注意

- 服务器、App 与桌面端需要同时升级，才能完整显示 V347 的跨端等待状态；旧客户端仍可读取文本，但不会呈现新的待处理卡片。
- `waiting_input` 表示 Agent 已安全暂停且没有继续执行副作用；`resolved` 只证明用户已提供下一轮输入，不证明任务最终完成。
- 本轮只更新 Windows 桌面发布源版本到 1.17.3，不把未重新构建的原生安装器宣称为发布产物；正式发布仍须运行 `installer-native/build-all.bat` 并核对 EXE、`.sha256` 与 `.release.json`。
