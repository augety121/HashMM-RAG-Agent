# HashMM V429 本轮说明

本轮把 V390–V425 中仍然容易“看起来接入、实际不可靠”的三条链路补成可验证实现：

- Work control 现在以 `append_event_once` 作为唯一事件写入入口。每个控制命令使用 `work-control:{command_id}:{event_type}` 幂等键，并携带 `expected_revision`；网络重试不会重复派发，版本冲突不会覆盖更新后的工作状态。执行器已经运行但结果事件无法持久化时，接口明确返回 `uncertain` 和 `action_applied`，不把不确定结果伪装成成功。
- Context Capsule 增加 `hashmm.provider-contract.v1`。工具、视觉、结构化输出、流式、推理、输入/输出上限和 wire API 都在调用前可确定协商；缺失能力不会 fail-open。契约只进入公开 manifest，不把检索正文写入持久化数据。
- App/桌面端增加 owner-scoped `hashmm.work-outbox.v1`。断网时只持久化控制元数据（命令 ID、run ID、动作和 revision），恢复网络、窗口可见或后端恢复事件触发有界 drain；服务端仍是唯一真相，冲突/权限失败不会后台无限重放。
- Agent Mesh 决策公开并行收益、协调成本、净收益和预计轮数，用户可以审阅调度理由；不改变显式 `parallel` / `pipeline` 选择优先级。

## 验证

本轮应以命令输出为准，不以模型描述替代证据：

- 后端新增 V429 provider/work-kernel 回归测试，并复跑 V374 工作控制与 V390 证据测试。
- 前端新增 outbox 测试；必须通过 `npm test`、`npm run typecheck` 和 `npm run build`。
- 发布前还必须运行桌面 Node 套件、`desktop/scripts/verify-release.py --source-only`，再用 `scripts/package-server.ps1` 生成服务器包。

## 未声称完成

真实公网多设备、对称 NAT、独立 TURN、24 小时稳定性、Authenticode 发布者身份仍需在真实部署环境验收；本地测试不能替代这些证据。
