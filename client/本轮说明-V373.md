# HashMM V373 本轮说明

## 本轮目标

把此前分散在 Chat、持久 Loop、多 Agent、浏览器、电脑任务、文件投送、桌面页面和 App 页面里的“任务状态”收束为一个真实的统一工作运行时。用户在任一端看到的运行、进度、证据与交付均来自同一个后端事实源；客户端缓存只用于快速启动与离线回看，不再制造演示状态。

## 核心变化

- 新增 `hashmm.work-run.v1`、`hashmm.work-event.v1`、`hashmm.work-feed.v1`，使用账号、会话、任务类型和真实来源 ID 关联运行。
- 运行创建幂等；事件、修订、运行状态和账号级变更游标在同一事务推进，支持 ETag、增量 feed 和增量事件分页。
- 普通 Chat 的 SSE、持久长任务和多 Agent 团队把真实生命周期投影到统一账本；恢复历史任务不会重放工具或副作用。
- App 的 Browser Use、Computer Use 和取文件请求与桌面执行器共享请求 ID；桌面领取、交付、失败会更新同一运行记录。
- 桌面右侧上下文的运行页、App 工作台和 App 运行详情读取同一服务端状态；App 使用账号隔离的加密本地快照，变化后才增量更新。
- 修复旧 `/api/chat/stream` 在数据库健康时反而未执行 Agent 的缩进缺陷，并避免重复写入用户消息。

## 严格边界

- 工作账本不是消息副本，也不是执行输入；为用户识别任务保留有界标题，但完整 prompt、token/thinking 流、工具参数、凭证、Cookie、文件正文和客户端上报结果正文不进入账本。
- 所有运行和来源 ID 都按账号所有权查询；缺失与越权对象使用同一 404 语义。账号游标不会暴露其他租户活动。
- “已交付”表示结果已经到达用户可查看的位置，不等同于确定性校验全部通过；最终完成仍由 `hashmm.completion-gate.v1` 和用户验收决定。
- 离线缓存只复用最后一次已验证的服务端投影；不能证明电脑在线、任务仍运行或外部页面仍有效。
- 外站真实登录、生产 Supabase、多设备网络切换、远程 MCP、Browser Use 和 Computer Use 的生产环境验收仍需在对应设备与账号上单独执行。

## 设计参考与不等同声明

- 参考 OpenAI Codex 的任务最佳实践与 subagent 隔离原则：主任务保留目标、决策和验收，专员使用隔离上下文并返回有界结果；参考链接为 <https://learn.chatgpt.com/guides/best-practices.md> 与 <https://learn.chatgpt.com/docs/agent-configuration/subagents.md>。
- 参考 Claude Code 官方 subagent、hooks 和 permissions 文档中的专员上下文、生命周期事件与权限收窄原则：<https://code.claude.com/docs/en/sub-agents>、<https://code.claude.com/docs/en/hooks>、<https://code.claude.com/docs/en/permissions>。
- HashMM 本轮实现是基于自身 Python/Electron/Android 架构的适配，并不声称复制、等同或兼容 Codex/Claude Code 的未公开内部实现。
