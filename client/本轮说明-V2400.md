# HashMM V2400 · DirectLink Remote Engine 5.0

## 本轮修复的真实故障

日志显示 host 与 Android viewer 都能完成 V3 WSS 注册，但没有 offer/answer、ICE 候选、选中路径和首帧证据；viewer 约 72 秒后以通用异常退出。App 的旧 HTTPS 帧轮询吞掉所有异常并每 200ms 重试，因此页面只能一直转圈。与此同时，桌面 host 在 PeerConnection 进入 connected 后停止 JPEG 推送，即使 viewer 实际没有渲染首帧。

V2400 将这些假成功状态拆开并逐项落证据：

- V4 规范端点与协议校验；
- 同账号审批会话上的 offer/answer/ICE/DTLS/track/first-frame 里程碑；
- Android 和桌面只在真实首帧后进入 STREAMING；
- 兼容预览由 viewer 显式请求，使用 Authorization header，不把 ticket 放在 URL；
- 8 秒无首帧结束为稳定错误，而不是无限等待；
- 指针快通道与可靠控制通道分离；
- Work 已终态后的迟到 socket close 按幂等观察处理。

## 服务器部署参数

HashMM 控制面继续使用当前 Cloudflare Tunnel：

```dotenv
HASHMM_ENV=production
HASHMM_PUBLIC_URL=https://hashmm.hashlens.org
HASHMM_REQUIRE_AUTH=1
HASHMM_REQUIRE_SECURE_REMOTE=1
HASHMM_PROXY_HEADERS=1
HASHMM_TRUSTED_PROXIES=127.0.0.1/32,::1/128
HASHMM_REMOTE_EDGE_MODE=cloudflare-tunnel
HASHMM_TURN_URLS=["turn:turn.example.com:3478?transport=udp","turn:turn.example.com:3478?transport=tcp","turns:turn.example.com:5349?transport=tcp"]
HASHMM_TURN_SHARED_SECRET=REPLACE_WITH_PRIVATE_RANDOM_SECRET
HASHMM_REMOTE_REQUIRE_TURN=1
```

必须把 `turn.example.com` 和占位 secret 换成真实部署值；示例文件不含真实凭据。Cloudflare 子域不会替代 coturn 的 UDP relay，不能把 `https://hashmm.hashlens.org` 当作 TURN 地址。
