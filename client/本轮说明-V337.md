# 本轮说明 · V337（2026-07-17）—— Codex 式托管 Worktree 与无损回收闸

V336 已补齐仓库指令、先计划后执行和证据型 Diff Review。V337 继续处理并行编码的核心差距：
同一仓库的多个任务不能继续共用一个可写目录。本轮按当前 Codex Worktrees 官方说明落地托管
worktree 的安全子集，并把“切换期间正在执行的 Agent/终端”纳入同一个工作区一致性边界。

HashMM 后端迭代号为 **V337**，桌面端与原生安装器版本为 **1.10.0**。

## 已完成

### 1. 托管 Worktree 生命周期

- 工作台“变更 / Review”新增 **Worktree** 页签，可枚举当前 Git 仓库的所有 checkout。
- 可从分支或提交创建 HashMM 托管 worktree；默认使用 detached HEAD，不污染分支命名空间。
- 支持切换工作区、在 detached worktree 原地创建分支、永久标记与安全回收。
- 托管目录固定由主进程在 Electron `userData/worktrees` 下生成。renderer 只能提交标签和 base ref，
  不能指定目标路径或托管根。
- 默认保留最近 15 个托管 worktree。自动回收范围故意收窄为 untouched、干净、非活动、非永久、
  未锁定、没有独有提交的 detached worktree。

### 2. 当前改动与 `.worktreeinclude`

- 用户显式选择后，可把当前 HEAD 上的 tracked staged/unstaged Diff 应用到新 worktree；暂存状态不
  伪装保留，复制后统一是未暂存改动。
- 普通 untracked 文件不会复制，界面会明确提示。
- `.worktreeinclude` 只从 Git 已忽略文件中选择；支持常用 Gitignore 式 glob 和后置 `!` 排除。
- ignored `AGENTS.override.md` 自动复制；来源 symlink 跳过，目标已有文件不覆盖。
- 复制上限：200 个文件、总计 50 MiB、单文件 10 MiB；规则文件最大 64 KiB，tracked patch 最大
  20 MiB。超过限制 fail closed。

### 3. 无损回收，不相信单一 `git status`

- Git 的普通 status 不显示 ignored 文件，因此“工作区干净”不能证明回收不会丢数据。
- HashMM 在创建时记录已复制 ignored 文件的路径、字节数与 SHA-256。回收前同时检查 worktree 副本
  和原 source 副本仍与创建时哈希一致。
- 任何新产生、被修改、缺少同哈希源副本的 ignored 文件都会阻止回收。
- tracked/untracked 改动、活动 worktree、永久/锁定标记、确认 ID 过期、detached 独有提交都会阻止
  回收；独有提交必须先“在此创建分支”锚定。
- 正常回收路径不使用 `git worktree remove --force`。只有“创建尚未成功且原改动仍完整留在 source”
  的内部失败清理可以 force 移除刚创建的临时副本。
- 托管根和每个 repo 子目录都经过 realpath 边界检查，预置 junction/symlink 不能把目标导向 HashMM
  数据目录之外。

### 4. 工作区租约与界面一致性

- 所有前端 Computer Use 运行都会获取工作区租约，并在 `finally` 中释放；租约存在时禁止切换。
- 主进程原生 AgentLoop和后台任务仍在运行时也禁止切换。
- 当前终端仍在运行命令、Codex 或 Claude Code 时拒绝切换；只存在空闲 shell 时，切换会重启终端到
  新 worktree，避免文件面板在新目录而终端仍写旧目录。
- 仓库切换后旧计划自动失效；重新计划时把准确 worktree 根、分支、HEAD、AGENTS 与 PLANS 注入。
- 提交图也跟随当前工作区，不再默认读取桌面进程启动目录。

## 仍然存在的边界

- 尚未实现 Codex 的 Local ↔ Worktree **Handoff**，也没有把某个对话永久绑定到同一个 worktree。
- 尚未实现回收前快照、历史任务一键恢复；因此有任何不可证明安全的文件时会拒绝回收，而不是自动删。
- Worktree 根目前固定在 Electron `userData/worktrees`，尚无“设置 → Worktrees”自定义位置界面。
- 尚未实现 local environment setup script。新 worktree 只有 Git checkout 和明确复制的 ignored 文件，
  `node_modules`、venv、构建缓存等仍需用户或 Agent 在该 worktree 中单独准备。
- `git status`、哈希与分支引用能证明删除边界，不证明代码业务正确；仍需测试、Review 与人工判断。
- 安装包 SHA-256 只证明完整性，不能替代 Authenticode 发布者身份。
