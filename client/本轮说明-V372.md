# HashMM V372 本轮说明

## 本轮目标

把 V370 的任务证据图和 V371 的执行前沿进一步收束为“证据门控完成”：不让模型高分、流畅回答、HTTP 成功或页面状态冒充任务完成，并把同一完成事实串入 Chat、RAG、长任务、多 Agent、Graph Engineering、桌面端、App 与在线质量评测。

## 核心变化

- 新增 `hashmm.completion-gate.v1`，提供可审计状态、必需条件统计、失败模式、工具/Agent 轨迹、最小下一动作、完整性边界和协议指纹。
- 多 Agent 成功条件改为真实成员交付；普通代码或 RAG 任务只检查契约明确要求的条件，不再追加无关条件。
- 长任务每轮持久化完成门；存在待用户验收但没有可执行修复路线时，以“已交付、待复核”停止无效循环，不冒充已验证。
- 任务所有者可在桌面端或 App 接受/退回交付；服务端统一鉴权、持久化并重建检查、证据图、执行前沿和完成门。
- Chat 右侧统一上下文先展示权威完成门，再展示任务图、前沿、契约和运行清单；运行检查通过不再等同于最终完成。
- 在线质量看板区分已验证、带限制交付、未闭环、受阻、不可用、重复调用、不安全完成声明和协议完整性异常。

## 严格边界

- 模型自评和 LLM judge 不能替代用户验收。
- `verified` 只证明当前可观察契约和轨迹闭环，不保证现实世界结论绝对正确。
- 接受、退回、重建门禁和查看状态都不会自动执行工具、恢复任务或扩大文件、网络、会话、MCP、Browser/Computer Use 和子 Agent 权限。
- 外站登录态、真实生产 Supabase、远程 MCP 和 Computer Use 仍需在对应生产环境单独验收。
