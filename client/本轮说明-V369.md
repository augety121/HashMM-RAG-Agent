# HashMM V369 本轮说明

## 目标

把“长任务、多 Agent、权限、RAG 证据”从互相独立的页面和运行时约定，收敛成后端可持久化、可恢复、可确定校验的任务边界。桌面端和 App 只提交用户选择并展示服务器事实，不自行推断任务是否完成。

## 已完成

- 新增 `hashmm.execution-scope.v1`。服务器在任务启动前绑定账号、会话、运行 ID、读写模式、工具集合、联网策略、站点白名单、子 Agent 开关与预算。
- 任务范围随后台循环持久化；服务重启后会对当前工具注册表重新取交集，旧快照或被修改的状态文件不能借机获得新增能力。
- 新增执行范围守卫并置于运行时权限守卫之前。任务范围与参数绑定权限必须同时放行；守卫异常按拒绝处理。
- 修复 Worker 只靠角色白名单、显式绕过 `PermissionSystem` 且清空会话 ID 的缺陷。Worker 现在继承同一账号和会话，工具集合只能缩小，且不能再次派生子 Agent。
- 后台长任务在执行前保存任务契约与用户完成标准；每轮记录输出、计划闭合、工具、交付物与用户标准的确定性校验，未闭合计划不会被模型自述升级为完成。
- 桌面端可为单个长任务选择只读/工作区写入、禁止联网/指定站点/公开网络和是否按需派生专员，并展示实际保存的工具范围和逐项验收状态。
- App“工作总览”不再把目标和完成标准塞进一个输入框；改为独立目标、完成标准和任务权限，调用与桌面端相同的 `/api/loops/goal` 契约。
- 新增 `hashmm.retrieval-result.v1`，统一报告候选数、最终证据数、可引用数、文档数、重排方法、来源方法、过滤数量和图证据扩展统计。
- RAG 主检索、公开 Search/RAG API、Agent 的 `kb_search` 工具和 Chat 运行轨迹复用同一检索事实；契约不包含模型自评分或虚构的“已通过”。

## 设计依据如何落地

- OpenAI 官方长任务模式落实为持久状态、终态、预算和暂停/恢复；上下文工程落实为任务契约与检索契约，而不是无限拼接历史。
- 官方多 Agent 建议落实为“只处理边界清晰的独立子任务、上下文隔离、主 Agent 汇总”，并用父子执行范围交集阻止权限扩张。
- 官方 guardrails/approvals 思路落实为两层判定：任务是否授予这类能力，以及当前具体参数是否已经获准。
- SAG 只采用可验证的机制：候选池与最终证据分离、混合检索、重排统计、来源边界和图证据回接；未复制未确认许可的实现，也未声称复现其性能数字。

## 明确限制

- 站点白名单会拒绝无法确定目标 URL 的泛搜索与浏览器动作；这是安全边界，不会降级成全网放行。
- 检索契约只能证明检索到了什么和来源是否可引用，不能单独证明最终自然语言答案正确；答案仍需引用完整性和任务验收。
- 远程团队频道、组织级 Access Bundle 和跨成员共享记忆尚未实现。本轮只实现私有、会话级任务范围，界面不会把概念包装成已完成能力。
- Windows 发布物若未做 Authenticode 签名，SHA-256 只证明完整性，不能证明发布者身份。
