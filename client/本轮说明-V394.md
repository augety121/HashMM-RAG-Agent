# HashMM V394 本轮说明

日期：2026-07-23

## 结果

本轮先逐项核对了《HashMM Evidence Fabric》方案，没有把已有页面或协议名称直接算作完成。审计确认六条主线已有核心骨架，但三平面原子 generation、自适应拓扑收益规划、全工具补偿目录和跨设备混沌验证仍未完成。随后补上当前最明确的生产断点：V393 的技能候选虽然已隔离、可审核、可回滚，却还没有真实历史任务回放和强制发布门。

V394 现在要求候选在进入生产 Chat 前，必须在同一模型上与基线完成成对回放，通过固定安全对抗、质量、退化、输出 Token、延迟和完整性门禁；自动门禁通过后仍需用户明确采用。

## 核心能力

1. 历史成对回放
   - 使用同一批案例、同一配置模型分别运行基线和候选，避免不同样本或不同模型造成不可比结果。
   - 只使用当前账号拥有的服务端反馈案例和技能来源样例；客户端不能提交评测正文。
   - 至少需要 2 条相关案例，否则状态为“证据不足”，生产技能保持不变。
2. 安全与资源发布门
   - 固定检查秘密诱导泄露、提示注入、审批绕过和无证据外部完成。
   - 要求平均质量提升、不出现明显单例退化、不发生候选安全回归。
   - 候选输出 Token 不得超过基线预算，延迟不得超过基线预算，所有调用必须完整返回。
3. 隐私与并发正确性
   - 评测表只保存内容哈希和有界指标，不复制问题、参考答案或生成回答正文。
   - 相关性筛选不能只靠一个中文字重合；显式来源只能优先当前 owner 已拥有的案例。
   - 模型调用前后均校验生产基线；回放期间技能变化会把运行标为 stale，评测不会落到错误版本上。
4. 人工最终发布
   - 评测通过只获得 `release_eligible`，不会自动晋升。
   - 采用仍执行 owner 校验、权限无扩大校验和基线哈希 compare-and-swap。
   - 未评测、证据不足、对抗失败或预算超限均由服务端拒绝采用。
5. 桌面端真实接线
   - 审核面板可启动服务端回放并显示历史/对抗案例数、质量差、Token、延迟和逐项门禁。
   - 未通过时“采用”保持禁用，失败原因和证据不足的补充路径可见。
   - 能力探测只有评测、生成、读取、采用、拒绝和回滚路由全部挂载时才标为可用。

## 明确限制

- 当前质量评分使用保守的词元 F1，适合阻断明显退化，不等同于领域专家裁决；小规模私有回放集不能证明候选在所有现实任务中更优。
- Token 为输出量估算，不是 Provider 账单；延迟是本次回放观测值。两者用于发布预算门，不作为跨 Provider 基准结论。
- 评测固定使用零工具离线调用，不能证明真实工具链任务成功；工具技能未来必须加入受控 Sandbox 回放和执行收据验证。
- 当前仍坚持人工最终采用，没有开放自动灰度。
- 附件中的跨设备零重复副作用、DOM 重定位率、约束保持率和多 Agent 显著性仍是目标，不是本轮已达成结论。
- 安装包若未配置代码签名证书将显示 `NotSigned`；SHA-256 不能替代发布者身份。
