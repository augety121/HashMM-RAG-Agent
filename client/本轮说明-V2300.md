# HashMM V2300 · Verified Remote Bootstrap

## 本轮解决的问题

此前服务器可以签发 host ticket，Cloudflare WSS 却在认证前以 `4403 secure_transport_rejected` 拒绝连接；桌面端仍显示“远程未注册”，App 只看到 viewer 自己。根因不是 Supabase 账号不同，而是客户端猜测旧 WSS 地址、代理后的 HTTP/WS 安全语义没有统一，以及失败事件没有与票据尝试关联。

V2300 把远程拆成三条相互独立但可追踪的链路：

1. 身份与控制面：Supabase access token 只向 HashMM HTTPS API 提交；服务端下发规范 V3 bootstrap。
2. 信令面：客户端申请 30–60 秒一次性票据，以 `attempt_id + trace_id` 连接规范 WSS；host 与 viewer 分别注册。
3. 媒体面：屏幕、音频和控制优先 WebRTC P2P，其次 TURN；用户已批准的 EasyTier 等私网可作为外部路径；均失败后才进入短时 ticket 保护的应急 HTTPS 帧。

## 已实现

- `GET /api/remote/v3/bootstrap`：账号鉴权、`no-store`、HTTPS/WSS 端点、协议、配置修订和 ICE 可用性。
- `POST /api/remote/v3/socket-ticket`、`WS /api/remote/v3/ws`、V3 devices/diagnostics；V2 路由继续存在，但 V2300 客户端不再使用。
- 可信代理安全上下文：ASGI secure scheme 优先；只有 `HASHMM_TRUSTED_PROXIES` 中的直接上游可声明 forwarded HTTPS/WSS。
- 可持久诊断状态机和匿名错误码；对象按 owner 查询，其他账号无法枚举尝试。
- Electron host supervisor、viewer 重领票、Android bootstrap/领票/关联 WSS 全部统一为 V3。
- 桌面设备页只展示 host；错误码翻译为用户可执行说明，并显示匿名 trace/attempt 方便对照服务器日志。
- EasyTier 外部适配器元数据与虚拟网卡发现；没有把上传压缩包源码或密钥加入产品包。

## 生产部署要求

```dotenv
HASHMM_ENV="production"
HASHMM_PUBLIC_URL="https://hashmm.hashlens.org"
HASHMM_REQUIRE_AUTH="1"
HASHMM_REQUIRE_SECURE_REMOTE="1"
HASHMM_PROXY_HEADERS="1"
HASHMM_TRUSTED_PROXIES="127.0.0.1/32,::1/128"
HASHMM_REMOTE_EDGE_MODE="cloudflare-tunnel"
```

`cloudflared` 与 HashMM 同机且回源 `http://127.0.0.1:6006` 时，上述 loopback trusted proxy 是正确边界；若新增 Nginx、容器网桥或远程负载均衡，必须把“直接连接到 Uvicorn 的代理地址段”精确加入 allowlist，不能写 `0.0.0.0/0`。

复杂 NAT 生产验收还需要独立 TURN：配置 `HASHMM_TURN_URLS` 与至少 32 字节 `HASHMM_TURN_SHARED_SECRET`，并验证 UDP、TCP/TLS、时钟同步、容量和凭证过期。

## 验收矩阵

- 自动：remote transport/bootstrap、票据与 owner 隔离、诊断状态机、hub、Electron supervisor 假 WebSocket与真实本机 WebSocket、viewer IPC 合约、网络适配器、前端测试/typecheck/build、Android unit test。
- 真实设备：同一账号 Windows host 与 Android viewer；Wi-Fi↔Wi-Fi、手机流量↔校园网、对称 NAT；记录 selected candidate type、协议、RTT、关闭码、trace id。
- 故障注入：错误公网 URL、非可信 forwarded header、过期/重放票据、token 续期、cloudflared 重启、桌面采集 renderer 崩溃、网络切换和休眠恢复。
- 长稳：至少 24 小时 host presence，确认页面切换、App 打开/关闭和 access token 刷新不会使桌面主机从同账号目录消失。

## 尚未冒充完成

- 本机自动测试不证明公网双设备已经选中 P2P 或 TURN；部署服务器包后仍需按矩阵实测。
- EasyTier 未被内嵌或自动启动，这是明确的安全与许可证边界，不是功能遗漏。
- Windows 安装器已经由 `installer-native/build-all.bat` 重建，EXE、`.sha256` 与 `.release.json` 一致；但未签 Authenticode。
