## 三、本轮（V332）已消除的差距

1. **CI 只认 5 个基准 → 11 个全矩阵**（gaia/tau2/humaneval/bfcl/kotlin/webvoyager 接入，
   短名映射经 registry 实证；别名 nodocker/all 三处同词汇由测试锁死）。
2. **跑分串行 → 双端双层并发**（桌面 run_for_comparison ThreadPool；CI bench_workers×concurrency；
   webvoyager 逐题并发、真浏览器模式因共享 Chromium 内核明确保持串行）。
3. **Terminal 50 题被 2h 硬编码掐死 → HASHMM_TB_TIMEOUT 可调**（workflow 给 5.5h）。
4. **workflow 文件缺失 →** 按 v326/327/328 全部断言重建随包。
5. **中文技能包目录跨平台乱码 →** 根因修复（内置包 ASCII 源目录名）。

## 四、仍然真实存在的缺口（可验证，按 ROI 排序）

1. **SDK / API-first 打包**：根目录无 `pyproject.toml`/`setup.py`，无法 `pip install hashmm`
   或三行代码嵌入别人应用——这是与 R2R/LightRAG 生态位对比的最大**叙事**缺口
   （`BENCHMARK_AND_ROADMAP_2026.md` 的这条结论今天仍成立）。工作量：中；不动核心代码。
2. **评测三坑的第 3 坑**（趋势文档 §四：厂商选择性发榜）：本项目 `bench/vs-frontier` 已有
   可比性门禁（≥50 题才进正式区），但**基线消融的常态化**还靠手动勾 workflow 的 baseline
   开关。建议后续把"agent 轮 vs 裸模型轮"做成同一次 CI 的成对产物，脚手架增益
   （趋势文档说的 30-50 分差距）就能逐版本追踪。工作量：小。
3. **OSWorld / WebArena 运行环境**：代码与数据接入位齐全（`webarena.py`/`osworld.py`），
   缺的是用户自备网站镜像/桌面 VM——设计如此，非代码缺口；CI 中已按"可选外部环境"SKIP。
4. **MCP Atlas 官方数据集**：`mcp_atlas.py` 接入位就绪，等官方放数据，外部依赖。

## 五、明确「不建议做」的（避免为对齐热点而伤架构）

- **多进程 Agent Teams（OpenClaw 式常驻集群）**：本项目桌面派活已有并发池与互斥锁
  （desktop/main.js `_dispatchInflight`/`_withBrowserLock`），单机多进程集群会引入
  跨进程状态同步成本，对单用户桌面产品 ROI 为负。
- **为 19.78% 那类"SWE 假解"风波加激进的自动重判**：本项目 SWE 走官方 harness 判分、
  predictions 全落 Artifact 可离线复核，已是正确姿势；再加一层自研判分反而引入新口径。

2. baseline 成对产物 + 趋势图叠加"脚手架增益"曲线（缺口 2，半天级）。
3. 桌面端跑分页给 parallel 旋钮 UI（后端/前端封装本轮已就位，只差控件接线）。
