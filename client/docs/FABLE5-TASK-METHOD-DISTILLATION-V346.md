# Fable5 任务完成方法蒸馏（V346）

## 范围与证据边界

本说明只蒸馏 `Desktop/121/1.docx` 至 `7.docx` 中反复出现的任务完成方法，不采纳其中旧项目事实、旧代码结论、密钥、路径或版本信息。方法同时受 HashMM 的运行时证据规则约束：模型文字不能证明命令、测试、检索、文件或外部事实已经发生。

本轮还对照了用户提供的 RAG/Agent 资料，以及本地 `codex-main.zip`、`openai-agents-python-main.zip` 中关于对话状态所有权、会话持久化、运行项生命周期、工具执行生命周期和语义事件协议的实现说明。对照的目的只是校验设计原则，最终行为以本仓库代码和测试为准。

2026-07-18 又核对了 OpenAI 官方 Codex app-server 文档：一轮任务以稳定的 thread/turn/item 身份流转；计划是带状态的结构化更新；命令和文件操作以 started、delta、completed 生命周期呈现；中断后必须落到 `interrupted` 终态，而不是把部分输出标成完成。HashMM 本轮据此给任务契约补入稳定 `run_id`，保留成对步骤 ID，并把客户端断开记录为受阻交付。来源：<https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md>。

## 可复用的任务完成方法

1. **先查真实状态。** 开始修改前先读取相关代码、路由、数据结构和已有能力，识别真正缺口；存在的能力优先复用，避免重复做一个看似相同但未接入主链路的功能。
2. **先定义完成，再执行。** 复杂任务建立可见的目标、完成条件和有依赖顺序的计划。计划不是展示文案；每一项必须有稳定状态，并在完成、跳过或阻塞时更新。
3. **按闭环批次推进。** 一批只解决一组可独立验证的问题。每批遵循“检查—修改—验证—记录”，避免大量修改后才发现最早的假设错误。
4. **把失败当诊断证据。** 编译、测试、接口或工具失败时，保留具体失败状态，定位根因并重跑同一验证；不能用另一段模型回答覆盖失败。
5. **用户指出遗漏时审计范围。** 先检查相关功能链路是否存在同类漏项，再处理表象，尤其关注稳定 ID、排序、持久化、恢复、取消和跨端字段丢失。
6. **完成必须可核对。** 工具执行、产物存在、引用有效、计划闭环和非空交付分别检查。不可自动核验的内容标记为限制，不能升级成“已通过”。
7. **交付要可继续。** 最终交付包含结果、已验证项、未验证或限制、下一步；长任务的状态和结果需要持久化，跨页面、跨端恢复时不能重放已确认输入。

## 明确不复制的行为

- 不复制重复的寒暄、状态口号或大段工具原始输出。
- 不在检查前承诺“全部完成”，不把语法平衡、打包成功或模型自评当作质量证明。
- 不暴露隐藏思维链；只向用户展示目标、计划、动作结果、证据和限制。
- 不从旧对话继承项目事实、账号权限、服务器状态或秘密信息。

## HashMM 落地映射

| 方法 | 运行时落点 | 用户可见结果 |
| --- | --- | --- |
| 目标与完成边界 | `hashmm.task-contract.v1` | Desktop 与 App 显示原始目标和完成条件 |
| 计划与进度 | SSE `task_contract`、`todo`、`progress`、`step_*` | 长任务执行中可见、离开页面后仍由应用级任务管理器继续 |
| 证据化完成 | `hashmm.run-manifest.v2` | 显示通过、未通过、待复核和下一动作 |
| 跨端持久化 | SQLite/Supabase `groundings`、`run_manifest` | App 重新进入历史消息后仍能看到证据与交付状态 |
| 真实停止 | 协程取消 + OkHttp `Call.cancel()` | “停止生成”中断真实 HTTP 流，不再只停止界面动画 |

## 完成状态语义

- `checks_passed`：本轮所有结构化检查都通过。
- `delivered_with_limits`：已交付，但存在运行时无法自动核验的项目。
- `needs_attention`：已产生结果，但至少一个必需检查失败。
- `blocked`：运行未以完成状态结束，可根据停止原因继续或重试。

这些状态只描述 HashMM 可观察到的运行事实，不证明模型结论在现实世界中必然为真。
