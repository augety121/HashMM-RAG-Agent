# 安装包保护说明（V203）

> 结论先行：**客户端拿到手 = 理论上可被逆向**，这是所有桌面软件的物理定律（微信、Steam 也一样）。
> 保护的目标不是"绝对防拆"，而是 ①挡住顺手牵羊 ②让抄袭成本高于自己写 ③把真正值钱的东西留在你控制的服务器上。
> 本次做了什么、没做什么、为什么，全部如实写在下面。

## 一、V203 已落地的保护

| 措施 | 状态 | 效果 |
|---|---|---|
| 前端源码 | 已保护 | Next.js 生产构建：压缩混淆 + **不产出 source map**（next.config 无 productionBrowserSourceMaps），拿到的是不可读的 chunk |
| asar 打包 | 已开启（electron-builder.yml `asar: true`） | 应用文件合并进 app.asar，挡住"打开安装目录直接翻文件"的顺手行为 |
| DevTools | **V203 新增**：正式包默认禁用（main.js `devTools: isDev \|\| HASHMM_DEVTOOLS==="1"`） | 挡住 Ctrl+Shift+I 直接看前端代码 / 内存中的令牌；排障时设 `HASHMM_DEVTOOLS=1` 启动即可恢复 |
| 密钥卫生 | 持续要求 | 安装包内**没有** service_role 等高权密钥（它们只在你服务器的 start-hashmm.sh 里）；客户端只含 publishable key（本就是可公开的） |

## 二、当前明确存在、且本次**没有**处理的暴露面（如实告知）

1. **Python 后端以源码随包**：electron-builder 把整个 `../hashmm` 作为 extraResources 打进安装包
   （本地知识库 sidecar 需要它运行）。已核实**不能**简单排除 training/evaluation/tools 子目录 ——
   运行时代码有真实 import（如 streaming.py 引 searchr1_policy、admin.py 引 RAGEvaluator），排除即崩。
2. **Electron 主进程 JS**（desktop/*.js）在 asar 内是明文可读的普通 JS。
3. asarUnpack 出来的原生模块与 localllm.js 在磁盘上可直接看到（运行时必需，无法收进 asar）。

## 三、为什么不上"看起来更狠"的方案（评估结论）

| 方案 | 结论 | 原因 |
|---|---|---|
| Python 只发 .pyc | 不做 | pyc 与解释器版本强绑定；客户端用"系统 Python + venv"或按需运行时，版本不受控，发 pyc = 大面积启动崩溃 |
| PyArmor 加密后端 | 暂缓（可自测后上） | 引入运行时依赖与平台适配风险，且本环境无法打包验证；若要上，先在你自己的 Windows 打包机全流程测通 |
| bytenode 编译主进程 | 暂缓（可自测后上） | V8 字节码绑 Electron 版本，升级 Electron 必须重编；同样属于"没测过就不进主干"的类别 |
| JS 混淆器（javascript-obfuscator）加主进程 | 暂缓 | 收益有限（核心逻辑在后端），却显著增大排障难度 |

## 四、真正有效的护城河（建议路线）

1. **价值上移服务器**：hashmm 后端部署在你的服务器（现状 AutoDL 即是），安装包里的那份只是"本地小模式"。
   核心索引、模型、路由策略永远不出服务器 —— 这是唯一不可被拆包绕过的保护。
2. 若要商业分发：加**许可校验**（启动时向你的服务器验签 + 定期心跳），把"复制安装包"变成"复制了也用不了"。
3. 发布前用 `npx asar extract` 自查一遍包内容，确认没有把 .env / 密钥 / 数据目录一起打进去（曾有先例的事故类型）。
