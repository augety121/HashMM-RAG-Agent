# 借鉴设计 V249 —— 四个开源项目借了什么、怎么适配进 HashMM

> 原则：**看思路、不搬代码**。每一条都注明"对方的做法 → 本项目的适配"，全部踩在
> HashMM 既有模块上（零新表、零新第三方依赖），未配置时行为与旧版完全一致。

## ① cognee（github.com/topoteretes/cognee）— AI Agent 长期记忆平台
**对方的做法**：ECL（Extract-Cognify-Load）管线把任意数据变成"向量+图谱"混合记忆层；
`search()` 混合召回；**执行后回写**——任务结束把结果写回记忆，"agent 不再重复同一个错误"；
时间线可重建、跨会话留存。

**本项目的适配**（`hashmm/memory/hub.py` + `/api/memory/recall|hub/stats|hub/remember`）：
HashMM 已有四路记忆但互不相通——MemoryService（显著度/衰减/强化）、episodic 经验回放、
user_memories 用户画像、KG 实体图。hub 不重建任何一路，只做**联邦召回**（一条查询四路并搜、
统一打分排序，单路故障降级为空）与**执行回写** `record_outcome()`：派活/团队任务终态自动写回
长期记忆——失败＝教训（importance 1.6，不易衰减）、成功＝可复用打法。挂点在
`dispatch /complete` 与 `agent/team.py` 收尾，永不拦截主链路。

## ② codebase-memory-mcp（github.com/DeusData/codebase-memory-mcp）— 代码库持久知识图谱
**对方的做法**：把代码库索引成持久图谱，agent 用一次结构化查询（trace_path / impact /
semantic_query）代替逐文件 grep——五次结构查询 ~3400 token vs 全文翻找 ~41 万 token；
**不内置 LLM**："正在对话的 agent 就是大脑"，工具只负责建图与查图。

**本项目的适配**：HashMM 的"库"不是代码而是知识/记忆，所以借的是**心智模型**——
把记忆做成"一次查询可召回"的持久层（上面的 /api/memory/recall 正是这个查询面），
App「记忆中心」新增召回搜索框、桌面端与 Agent 未来都能经同一端点取用；
不引入 LLM 参与召回本身（词面+显著度打分，零额外成本），与该项目"后端只管图、脑子在 agent"
一致。

## ③ OmniRoute（github.com/diegosouzapw/OmniRoute）— 一个端点统一多家模型
**对方的做法**：一个 OpenAI 兼容端点聚合 200+ providers；**auto-fallback combo**——
配额尽/失败/超时静默滑到链上下一个模型（"This is what makes OmniRoute unbreakable"）；
**每 provider 熔断器** CLOSED/OPEN/HALF_OPEN（失败到阈值熔断一段时间，冷却后放探针）；
多因子健康打分与成本记录。

**本项目的适配**（`hashmm/llm_failover.py` + `/api/admin/model-route/*`）：
HashMM 已有多模型配置表与唯一出口 `get_active_llm_fn()`——容灾链就包在这个出口上，
**全后端零调用点改动**即生效。链 = 默认模型 + settings『model_fallbacks』（JSON id 数组，
顺序即优先级，≤5）；熔断参数保守（连续 3 失败 → OPEN 60s → 探针）。只接管纯文本调用与
.chat/.quick_call；**流式与工具调用直通主模型**——流中途换模型会产生拼接幻觉，宁失败不造假。
未配置 fallbacks 时零变化。管理面：GET/PUT `/api/admin/model-route/fallbacks`、
GET `/api/admin/model-route/health`（每模型熔断态+计数+最近错误）。

## ④ herdr（github.com/ogulcancelik/herdr）— 终端里的多 Agent 编排
**对方的做法**：每个 agent 一个真实终端"格子"，sidebar 状态四色（blocked/working/done/idle）
一眼可判"谁需要你"；socket API 让 lead agent **可编程地 spawn helper → 监控 → 读输出 → 汇合**；
会话持久、断线重连。

**本项目的适配**（`hashmm/agent/team.py`，dispatch kind=`team`/`multi_agent`）：
不搬终端多路复用器，搬"**控制室**"心智模型：协调者 LLM 把目标拆成 2-4 个角色
（研究员/分析员/写作员…）→ 服务端**并行**执行（asyncio + threadpool，与既有 _do_plan 同纪律）→
汇总者合成 → 回帖会话。控制室直接用**工作画布**承载（复用任务树画布机制）：每角色一张卡，
状态四色（⚪等待 🟡执行中 🟢完成 🔴失败）实时着色、产出要点就地展开、汇总区收尾——
发布画布后团队同链接看直播。这让画布从"文档预览"升级成多智能体的观察窗，
与既有 subagents（检索型子查询）、plan（runner 串行任务树）互补成三种编排形态。
角色数 ≤4、单角色 ≤650 tok、总汇 ≤900 tok；LLM 走 ①③ 的容灾链；终态经 ① 回写记忆。

## 没有借的（有意做减法）
- OmniRoute 的压缩管线/隧道/配额池——与本项目"个人桌面后端"定位不符；
- cognee 的独立向量库依赖——本项目已有自己的检索栈，联邦层不重复建设；
- herdr 的 PTY/终端渲染——画布已是现成的可视化宿主；
- codebase-memory 的 tree-sitter 代码索引——本项目的图谱面向知识而非代码。
