# HashMM 大版本完善路线图（V230 →）

> 定位：从「个人 Agent 工作台」走向「组织级通用智能协作系统」。
> 每个纪元 5～8 个小版本；P0=纪元内必做，P1=顺手可做；全部绑定现有地基，不画空饼。
> 现有地基清单：画布 2.0（版本链/发布/Viewer/评论/模板）、dispatch 派活队列（desktop runner）、
> quality_monitor 质量抽检、kb 知识库+隔离闸、skills 技能包、audit 双流审计、App NativeUiKit。

---

## 纪元一 · V230s「协作纪元」——一张画布，一个团队
**为什么是下一步**：V226–V229 已把画布做成「可发布、可评论、可回流」的单人→多人半闭环；
缺的是"多人同时在场"的实时感与团队资产沉淀。
- **P0 评论线程化**：评论可回复成串（comments 加 parent_id，Viewer 树状渲染）；@提及者
  收到站内提醒（新表 notifications，App 动态页顶部小红点）。地基：canvas_share.comments 已存 mentions。
- **P0 组织模板库**：个人模板一键"升为组织模板"（templates 加 scope=org），全员起稿菜单可见；
  管理员可下架。地基：canvas_templates 侧车升级为 scope 字段。
- **P0 轻量共同编辑**：同一画布两人同时开，编辑权互斥锁（先到先得，另一人只读+实时刷新，
  15s 心跳释放）。不上 CRDT，先解决"互相覆盖"这个真问题。地基：wc:save 通道+shares 侧车加 lock。
- **P1 画布收件箱**：App/桌面统一"与我有关"流——被@、我发布的有新评论、锁被释放。
- **验收**：两账号实测评论线程回流、锁互斥不丢字；组织模板 20 人可见性一致。

## 纪元二 · V236s「记忆纪元」——系统越用越懂你
**为什么**：dispatch/画布产生大量过程数据，但系统对"这个用户/这个项目"没有长期画像；
每次会话仍近乎冷启动。
- **P0 项目档案自动沉淀**：按会话聚类出"项目"（标题+文件+画布），后台任务定期把结论性
  内容（画布最新版、已完成任务摘要）写入 kb 的项目命名空间；新会话可一键"带上项目记忆"。
  地基：kb 已有入库+隔离闸；scheduled 任务即可承载。
- **P0 用户偏好卡**：从历史交互提炼（常用目录、常派任务类型、写作风格），存
  data/user_profile/{uid}.json，注入系统提示词；设置页可查看/一键清除（隐私优先）。
- **P1 记忆引用可视化**：回答里标注"来自项目记忆《X》"，点击直达来源画布/文件。
- **验收**：同一项目第二次会话零重复背景解释；偏好卡可查可删；kb 污染率不升（隔离闸拦截量对比）。

## 纪元三 · V242s「主动纪元」——从被支使到主动汇报
**为什么**：定时任务只有"到点跑"；今日简报只有"你来看"。差一层"事件驱动+推送"。
- **P0 事件触发器**：文件夹变化（desktop runner chokidar 监听）、webhook 入口
  （POST /api/hooks/{id}）、邮件到达（可选 IMAP 连接器）→ 触发既有 dispatch 任务模板。
  地基：runner 循环与 dispatch 队列原样复用，只加触发源。
- **P0 晨报/晚报推送**：今日简报服务器端生成（复用 App 端聚合口径），经 App 推送
  （先做应用内通知中心，FCM 后置）；桌面托盘气泡同步。
- **P1 异常主动上报**：quality 弱依据率突增、任务连续失败 ≥3 → 自动生成一张"体检画布"并@管理员。
- **验收**：往监听目录丢文件 → 30s 内任务自动执行并回填；晨报每日 1 条不重复。

## 纪元四 · V248s「多模态纪元」——画布长出眼睛和图表
**为什么**：画布是文本+HTML；数据到图、语音到纪要、截图到理解仍靠人肉搬运。
- **P0 数据画布**：粘贴 CSV/表格 → 画布内一键生成图表块（前端 ECharts 离线包，模板加
  chart 组件；wc:apply 支持 mode=chart）。地基：canvasShell 注入式结构天然可扩组件。
- **P0 截屏直问**：桌面截屏（已有微信式框选）→ 直接进当前会话带图提问，一步到位。
  地基：cu:capture 产物已是 dataURL，补一条"发到对话"路径即可。
- **P1 语音会议纪要**：App 录音 → 转写 → 自动套"进度报告"模板起一张画布。
- **验收**：CSV→柱状图 ≤10s；截屏到提问 2 次点击内。

## 纪元五 · V254s「生态纪元」——能力可插拔、可分享
**为什么**：skills 技能包与模板导入导出已证明"能力即文件"可行，缺的是发现与分发。
- **P0 技能/模板市场（本地版）**：一个 registry.json 索引（可指向自建静态站），客户端
  内浏览、一键安装到 skills/ 或模板库；带作者/版本/校验和。
- **P0 MCP 工具接入**：后端实现 MCP client，外部工具（浏览器自动化、企业内网 API）以
  MCP server 形式挂载，经 tool_governance 同一审计/安全三档管辖。
- **P1 开放 API 密钥**：/api 面向第三方的 scoped token（只读/画布写/派活三档权限）。
- **验收**：从 registry 装一个技能全程 ≤1 分钟；MCP 工具调用出现在审计流且受 balanced 档管。

## 纪元六 · V260s「自治纪元」——多 Agent 分工与自我评测
**为什么**：单 Agent 长任务易跑偏；quality_monitor 已能事后打分，缺"事中纠偏"。
- **P0 任务树**：复杂目标拆解为子任务树（规划者），子任务走 dispatch 并行/串行执行
 （执行者），完成后审查者用 quality 口径打分，不达标自动重试一次并标注差异。
  地基：dispatch 的 seq 已是雏形；quality_monitor 评分函数复用。
- **P0 任务树可视化**：画布模板新增"任务树"（节点状态实时着色），发布给团队围观进度。
- **P1 失败案例库**：审查不通过的样本自动进 kb 隔离区旁的"复盘区"，供提示词迭代。
- **验收**：一个 5 子任务目标端到端自治完成率 ≥80%；每步在审计流可追溯。

### 执行原则（沿用现行工程纪律）
锚点断言、双向补丁、扁平包排除 data/ 与密钥、诚实标注未验证项。每纪元收口出一版
「体检画布」：用自己的画布功能给自己写进度报告——吃自己的狗粮，是最好的验收。
