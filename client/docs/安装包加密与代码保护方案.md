# 安装包加密与代码保护方案（V206）

目标：别人拿到你的 App 安装包（APK）或客户端后端包，无法用 AI/反编译轻易还原你的业务逻辑（RAG 检索融合、Agent 循环治理、五层指令、诊断等核心资产）。

分两侧，各有对应手段——移动端靠 R8 混淆，Python 后端靠 PyArmor 加密。

---

## 一、App 侧（Android / APK）：R8 激进混淆 + 加固

已在 `app/build.gradle.kts` 开启 `isMinifyEnabled = true`（R8），本轮把 `app/proguard-rules.pro` 从"宽松保留"改为"激进重命名 + 最小保留"：

- **全量重命名**：默认所有类/方法/字段重命名为 `a.a.a()`，反编译出来是无意义符号。
- **塌包**（`-repackageclasses '' / -flattenpackagehierarchy ''`）：`com.hashmm.app.agent.xxx` 这种能透露架构的包路径信息全部销毁，所有类塌进一个空包。
- **抹调试线索**（`-renamesourcefileattribute '' / 去 LocalVariableTable`）：反编译看不到源文件名、行号、局部变量名。
- **移除日志**（`-assumenosideeffects Log.*`）：连同参数计算一起删除，避免日志把业务字符串/流程泄露给逆向者。
- **最小 keep**：只对 WebRTC（JNI 反射）、kotlinx.serialization（`$$serializer` 反射）、Ktor/Supabase（引擎反射）、Hilt（生成代码）保留原名，其余全混淆。

出 release 包时（`build-all.bat` 走 release 构建）自动生效。debug 包不混淆（方便你自己调试）。

**进一步加固（可选，按需）**：
- 接第三方加固（腾讯乐固 / 360 加固保 / 梆梆）做 DEX 加壳 + 反调试 + 防脱壳，APK 上传加固平台一键处理，无需改代码。
- `mapping.txt`（R8 产出的符号映射表）务必**离线保存、不进包**——它是反混淆的钥匙，也是崩溃日志还原的依据。

## 二、客户端后端（Python）：PyArmor 字节码加密

Python 源码天然可读，是最大暴露面。方案：`build-encrypted.sh` 用 **PyArmor** 把整个 `hashmm/` 包加密成运行时解密的字节码壳。

**为什么选 PyArmor**（对比其它方案）：
- vs **Cython**（编译成 .so）：.so 仍可用 Ghidra/IDA 反汇编看逻辑；PyArmor 是字节码加密 + 内存解密，且支持绑定机器/到期。
- vs **Nuitka**（打成原生可执行）：体积大、依赖链重、跨平台麻烦；PyArmor 轻量，不改一行业务代码。
- 工业级：支持字节码加密、运行时内存解密、机器绑定、到期策略，大厂 Python 商业分发常用。

**用法**：
```bash
pip install pyarmor
./build-encrypted.sh
# 产出 dist/hashmm/（加密包）+ dist/start-hashmm.sh（加密版启动脚本）
# 部署：上传 dist/ 到服务器，用 dist/start-hashmm.sh 启动
```

**验证保护效果**：
```bash
# 行为不变：能正常 import、能启动、功能一致
python -c "import hashmm.retriever"
# 但源码不可读：
cat dist/hashmm/retriever.py    # 只能看到 PyArmor 加密壳，看不到 HybridRetriever 的融合逻辑
```

**加固建议**：
- 生产可加 `--mix-str`（字符串也混淆，prompt/密钥字面量不再明文）、机器绑定（`pyarmor gen --bind-device`，包只能在授权机器跑）。
- 真正的密钥（Supabase service_role、JWT secret）本就不该写死在代码里——已通过环境变量注入（`start-hashmm.sh`），加密只是再加一层。

## 三、威胁模型：什么能防、什么防不住

**能显著抬高门槛**：
- 直接把 APK/源码丢给 AI 分析 → App 是无意义符号、Python 是加密壳，AI 读不出业务逻辑（你之前实测"只能拿到一部分信息"就是混淆的效果，本轮强化后暴露面更小）。
- 普通反编译（jadx / 直接看 .py）→ 看到的是 `a.a.a()` 和加密字节码。

**防不住（任何方案都防不住，需配合运营手段）**：
- 有经验的逆向工程师 + 充足时间，仍可能动态调试还原部分逻辑（这是所有客户端软件的共性，包括大厂）。
- 真正的护城河是**服务端逻辑不下发**：最核心的资产（如训练好的检索策略权重、私有 KG、评测集）留在你的服务器，客户端只拿结果——这比任何加密都可靠。

**结论**：R8 强化 + PyArmor 加密解决"别人拿包用 AI 一键复制"这一层；配合"核心资产不下发客户端 + release 加固 + mapping.txt 离线保管"，达到大厂客户端的常规保护水位。
