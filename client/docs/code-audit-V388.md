# HashMM V388 代码审计与取舍

日期：2026-07-22

## 审计范围

本轮按“页面显示的事实是否由真实执行链支持”检查了 Python API 与 Agent 能力派生、Next.js 管理后台和文档工坊、Electron 版本/发布边界，以及 Android 工作台的能力同步与本地缓存。检查重点不是继续增加入口，而是发现实现较浅、错误被空数组或零值吞掉、缓存跨账号或跨服务复用、以及页面文案超过后端证据的问题。

## 已收口的高优先级问题

1. **运行能力误报**：过去画布和长任务只要路由模块能导入就可能显示就绪。现在必须同时满足依赖可用、功能开关开启、执行器存在和 API 路径已挂载；缺任一项即 fail-closed。
2. **App 缓存跨服务污染**：能力缓存过去只绑定用户。同一账号切换另一台 HashMM 服务器时，旧 ETag 和旧能力可能短时复用。现在缓存键加入规范化后端地址指纹，内存与磁盘遵循同一隔离规则。
3. **App 刷新竞态**：周期刷新与手动刷新可能并发，慢返回覆盖新结果。现在单例刷新任务会合并周期请求，并在强制刷新时取消旧任务。
4. **管理页虚构零值**：数据源失败会被 `0` 和空数组掩盖。现在四个来源独立报告成功或错误，未读到的值显示为未验证，同时保留最近成功数据及时间。
5. **文档上传一次性读入与路径语义**：上传现在使用有界流式暂存、扩展名白名单、安全叶文件名、内容哈希、原子替换和异常清理；文档 ID 在触碰文件系统前执行拒绝式校验。
6. **文档操作假成功**：前端逐项读取服务端回执；网关断开时不会再把批量重解析描述成后台必然继续，失败项目继续保留以便重试。
7. **基础设施路径泄露**：管理文档列表和扫描结果只返回来源是否存在，不再返回服务器绝对路径。

## 保留但仍需继续深化的部分

- `SkillsTab`、`MCPServersPanel`、`TemplatesTab`、`ToolsTab` 等较早管理页仍存在把部分读取异常归一为空列表的旧模式。它们需要分批迁移到统一的 loading / verified-empty / stale / permission / network 状态协议，不能在一次改动中盲目重写全部页面。
- 后端批量重解析仍是同步流程，且旧文档替换与新索引提交尚未形成“新代构建成功后切换”的事务边界。当前前端已经诚实显示未知结果；后续应增加持久 job receipt、代际目录和成功后原子切换。
- App 中还有少数旧 Repository 以 `null` 或空集合表达多种错误。需要继续统一为带来源、验证时间、可重试性和权限含义的结果类型。
- 本轮完成源码发布闸门，不把它等同于 Windows 正式发布。正式 EXE 仍必须走 `installer-native/build-all.bat`，并核对 EXE、`.sha256` 与 `.release.json` 三方一致。

## 事实边界

本轮没有接入新的第三方私有协议，也没有复制外部项目代码。所有“可用”“已验证”“上传成功”结论都要求本地测试、HTTP 回执或确定性内容哈希；页面存在、模型描述和缓存旧值都不作为当前运行成功的证据。
