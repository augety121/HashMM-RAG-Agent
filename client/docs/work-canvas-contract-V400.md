# HashMM V400 统一工作画布契约

## 目标

V400 把 Chat、长任务、多 Agent、Browser Use、Computer Use、画布和文档产物收敛为同一份面向用户的“工作”对象。桌面端和 App 不再分别猜测任务状态，也不把 Agent 内部字段直接暴露给普通用户。

统一投影使用 `hashmm.work-canvas.v1`，由服务端基于持久化 WorkRuntime 生成。客户端只负责渲染、缓存和提交带修订号的明确动作。

## 用户看到的四个层面

1. **概览**：目标、当前阶段、阻塞原因、下一步、验收可信度。
2. **过程**：阶段、分支、检查点和有界事件，不包含思维链、凭据、原始工具参数或文件正文。
3. **依据**：来源、检查、回执、失效原因，以及本次实际使用的技能 ID 与精确版本。
4. **成果**：文档、演示文稿、表格、PDF、图片、画布和代码等真实交付物，可复用既有右栏查看器打开。

## 完成与验收

- 模型文字不是执行证据。
- `verified` 只用于验收条件和证据均通过的工作。
- `accepted_with_limits` 表示用户接受了仍有明确限制的结果，不能冒充自动核验通过。
- `awaiting_review`、`completed_with_limits`、`blocked` 和 `not_ready` 保留不同语义。
- 接受成果或要求修改必须携带 `expected_revision`。
- 重复提交同一个 decision ID 只返回首次结果；陈旧修订号返回冲突。
- 要求修改必须填写说明，并重新打开完成收据。

## 失效与因果边界

- 结果通过 `evidence_node_id` 绑定因果证据。
- 某一来源或依赖变更时，只把由该节点支持的结果标记为过期。
- 没有因果关系的其他成果保持可用。
- 客户端不自行推断全量失效，也不会因为刷新失败把旧结果标记为最新。

## 技能治理

- 运行记录只保存实际使用的技能 ID、作用域和精确版本引用。
- 工作画布不暴露私有提示正文。
- 一次使用或用户接受不等于技能质量得到证明。
- 候选技能不得自动晋升；发布仍需同一批案例的成对回放、安全探针、成本门和人工采纳。
- 任一安全回归都会阻止晋升。

## 缓存与跨端一致性

- 工作画布响应支持私有 ETag 和 `304 Not Modified`。
- 桌面端使用 Electron `safeStorage` 加密整个缓存文件，不可加密时拒绝落盘，绝不回退为明文。
- 缓存命名空间由当前认证身份派生为不可逆哈希；切换账号会原子清除上一账号缓存。
- App 使用账号隔离的加密缓存和同一 ETag 语义。
- 命令或验收动作成功后，对应运行缓存立即失效，再从服务端重新校验。
- 离线时只展示最后一次已通过结构、运行 ID 和完整性校验的快照。

## 安全边界

- 运行、工作区和 decision 都执行 owner 校验；缺失与越权保持不可枚举。
- `next_actions` 是受治理建议，不是自动执行清单；服务端固定返回 `auto_execute=false`。
- 外部页面、上传文件、工具输出和模型文字继续视为不可信数据。
- 普通工作画布不扩大文件、网络、Shell、MCP、Browser Use 或 Computer Use 权限。
