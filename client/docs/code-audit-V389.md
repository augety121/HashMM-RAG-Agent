# HashMM V389 代码审计与继续深化清单

日期：2026-07-22

## 本轮发现的确定性缺陷

1. 管理后台模板新建接口调用数据库中不存在的 `save_template`，属于页面存在但主动作不可用。
2. 模板编辑先删除旧记录再创建新记录，创建失败会造成不可逆数据丢失，并重置 ID、使用次数与创建时间。
3. 工具分类批量切换吞掉单项失败，随后把整类本地状态改成成功，形成与服务端不一致的假成功。
4. 技能、自定义工具和 MCP 列表吞掉读取异常，以空数组展示“暂无”，无法区分真实空态、权限错误和网络错误。
5. App 动态页的并行子任务位于普通 `coroutineScope`；任一未捕获异常会取消其他来源，首次加载还可能一直保持进行中。
6. App 只有请求数或 token 大于零才保存用量，把真实的零使用量错误地归类为未读取。

## 已完成的机制修复

- 模板创建、原地更新、删除、使用形成同一数据库契约；对象 ID 与输入均有界，所有管理路由统一执行管理员校验与审计。
- 管理页采用“本次已验证 / 最近成功结果 / 未取得可验证列表”三态，并在变更操作收到服务端回执前保持原界面状态。
- 批量工具开关使用逐项结果集合，只提交已确认项目到本地状态；失败项目保留并可再次操作。
- App 动态页使用监督式并行刷新和按来源错误状态，零值用量被保留，失败刷新不会覆盖最近成功快照。

## 下一批仍需优先处理

- 文档重解析仍会先删除旧切片、索引与图数据再重新入库。V388 已修正界面假回执，但后端仍需要“新代预构建、验证、原子切换、失败回滚”和持久 job receipt。
- `EvalPanel` 的轮询允许网络抖动继续，但初始评测、质量、模型和数据集读取仍混用静默空态；应引入与本轮相同的逐来源状态，同时保留长任务网关超时与真正启动失败的区别。
- 画布协作中的旧后端兼容分支仍有若干 fail-open 静默路径，例如锁端点缺失时直接放行。需要按本地编辑、共享编辑和组织协作分别制定兼容策略，不能统一放行。
- 部分 App Repository 仍使用 `null`/空集合同时表示无数据、未登录、权限不足和网络错误，后续应继续迁移到带 freshness、verifiedAt、errorKind 和 retryable 的统一结果契约。

## 事实边界

这份清单来自本地代码和可执行回归，不代表整个项目已不存在缺陷。本轮没有接入第三方私有协议，也没有把测试通过解释为模型回答正确；管理动作的成功只由数据库事务或 HTTP 回执确认。
