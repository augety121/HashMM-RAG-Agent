# HashMM App 逐页能力审计（V376）

审计日期：2026-07-22

本审计按“页面是否能完成真实用户任务”检查，而不是按卡片数量或页面是否能打开检查。结论只来自当前源码、接口契约和自动化测试；没有实际执行证据的能力不会标记为已完成。

## 产品边界

App 是桌面端和服务器任务的移动协作面，不是桌面管理后台的缩小复制：

- “动态”用于审批、查看新进展和处理需要用户介入的事项。
- “工作台”用于继续真实工作、创建结构化任务和查看跨端交付。
- “对话”是统一入口；复杂任务、文档、浏览器、电脑操作和多智能体最终都回到同一会话和运行记录。
- 手机端不直接扩大桌面文件、浏览器或电脑控制权限。需要电脑的动作进入受认证队列，由在线桌面运行器按任务权限执行。

## 本轮发现的系统性问题

1. `StudioRepository` 的 GET 读取原先把 401、403、404、网络错误、空响应和格式错误都折叠成 `null/emptyList`，导致多个页面把失败显示成“暂无内容”。V376 新增带错误的读取结果，并在 UI 中拆分 loading / empty / error。
2. 文档工坊生成文件名含动作路径分隔符时，服务端会写入不存在的子目录，随后仍以 200 返回原始 HTML。V376 改为安全叶文件名、工作区边界检查、临时文件原子替换；保存失败返回 500，成功返回结构化 artifact。
3. 手机照片请求固定每 5 秒轮询一次，即使长期无请求也持续打服务器。V376 改为空闲 5→10→20→30 秒退避，有请求立即恢复 5 秒。
4. 总控中枢固定每 4 秒读取多组状态，空闲和离线时也不降频。V376 改为按运行状态自适应，并保留最后成功状态。
5. 画布原先允许任意绝对下载地址进入带原生保存桥的 WebView。V376 在加载前做 scheme/host/port 同源校验，失败关闭原生桥路径。

## 仍然保留的边界

- App 画布目前适合查看和轻量编辑 HTML 产物；复杂版式、版本对比和发布设置仍以桌面端为主。
- 手机端 Office 文件交给系统已注册应用打开；第三方应用中的编辑不会静默覆盖服务器原件。
- 没有桌面运行器在线时，App 可以聊天、查看服务器结果和安排任务，但不能绕过桌面权限直接操作电脑。
- vivo 办公、UU 远程均没有可审计的公开私有 SDK。本项目只使用标准文件关联和自有 WebRTC/权限协议，不声明私有协议兼容。
