# HashMM Graph Engineering

## 定义与边界

HashMM 的 Graph Engineering 不是“让模型先编一张图”，也不是把所有工作都改成图数据库。当前发布实现的是查询时证据图：

`用户问题 -> 实体/关系检索 -> chunk_id 支撑边 -> 原始索引切片 -> ACL -> 有界上下文 -> Chat 来源与运行清单`

节点和边只负责发现与解释关联；进入模型上下文的事实仍必须来自可读取的原始切片。图谱摘要不能替代证据，模型文本也不能反向充当执行或检索成功证明。

## 已接入的真实链路

1. `KGRetriever` 为本次查询收集实体、关系及其真实 `source_ids`，产出确定排序的 `evidence`。
2. `expand_graph_evidence` 以 `chunk_id` 回接向量索引的原始元数据，去重并限制最多加入 12 条，默认 4 条。
3. 文档允许列表在初始检索、图证据扩展和最终提示词边界重复执行；过滤异常时有权限的路径返回空结果，不回退到未过滤内容。
4. 显式 ACL 存在时，不注入可能聚合多个文档的全局实体或关系摘要，只使用通过 ACL 的原始证据块。
5. Chat 来源返回 `method=graph_evidence`、`chunk_id`、`doc_id` 和 `graph_support`；桌面端与 App 显示“图关联”，但不会把标签当成真实性证明。
6. 运行清单记录图证据数量和证据保留策略；管理后台的“图工程”读取后端真实就绪状态、证据上限与回接方式。

## 配置

- `HASHMM_GRAPH_ENGINEERING=0`：关闭查询时图证据扩展。
- `HASHMM_GRAPH_EVIDENCE_LIMIT=4`：单次查询最多补充的图证据数，合法范围 0 到 12。

## 与外部项目的关系

- SAG 的事件/实体组织、查询时动态关联和证据验证对本设计有启发；本轮没有复制其代码，也没有声称已实现论文中的 SQL 动态超边算法。
- `baby-lovable-main.zip` 未发现许可文件，因此没有复制代码；其服务端单调版本投影只作为以后跨端同步的设计参考。
- `fanbox-master` 的工作收件箱、会话恢复和文件溯源与 HashMM 已有任务、缓存、产物和审计机制相近，本轮没有重复建设第二套状态系统。
