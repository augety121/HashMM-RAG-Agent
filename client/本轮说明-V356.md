# HashMM V356 本轮说明

日期：2026-07-19  
版本：Backend `V356`，Desktop / MCP / Native `1.17.12`

## 本轮解决的问题

1. 右侧浏览器批准 Bing 后仍为空白，并显示 `ERR_FAILED (-2)`。
2. 右栏被拖宽后，中间 Chat 会缩成极窄列，模型名称和欢迎卡片逐字换行。
3. 空问答框异常变高，按钮沉在底部，窄空间下视觉比例失衡。
4. 浏览器内部错误直接暴露给用户，失败后缺少明确的恢复动作。

## 浏览器修复

- 已用独立 Chromium `WebContentsView` 复现确认：Bing 本身可加载，并会从 `https://www.bing.com/` 跳转到 `https://cn.bing.com/`。
- 根因是导航守卫把这个地域规范跳转当成未授权跨站并取消，取消事件随后被 Electron 表现为 `ERR_FAILED (-2)`；不是服务器、React 或 Chromium 无法联网。
- 本轮允许经过严格判定的 `www → 同服务节点` 规范跳转，并把目标主机限制在当前右栏这次显式导航中。不同站点、普通根域到未知子域和多租户兄弟站不会继承授权。
- 主进程把 Chromium 错误码翻译为简短说明；右栏错误卡可直接重试或交给 Google Chrome，外部打开仍只接受无账号密码的 HTTP/HTTPS URL。

## Chat 布局与输入框

- 统一检查器为 `320–900px` 的用户可调区域，但计算时必须给 Chat 留出 `440px`；260px 展开侧栏与 52px 收起侧栏均纳入计算。
- 保存过大的旧宽度会在启动、窗口缩放和侧栏开合时自动收敛，避免历史设置再次挤坏页面。
- 欢迎卡片使用 Chat 容器查询：空间不足时单列，足够时两列；模型名称保持单行并省略。
- 问答框空态 `32px`，最多增长到 `120px`；发送或清空后立即恢复紧凑状态。工具按钮在容器变窄时只显示图标。

## 安全边界

- 页面阻止列表优先于规范跳转；没有把同后缀简单等同于同站，回归测试明确拒绝 `foo.github.io → bar.github.io`。
- 右栏页面继续运行在 `persist:browser-use` 隔离分区，`sandbox=true`、`nodeIntegration=false`，没有 preload 和 HashMM IPC。
- 网页可见内容仍不是 Agent 证据；“交给 Agent”后必须由受控 Browser Use 重新读取并形成轨迹。
