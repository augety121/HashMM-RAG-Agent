# HashMM V591–V601 本轮说明

日期：2026-07-27  
Backend：V601  
Desktop / MCP / Native：1.36.0

## 本轮目标

本轮把“没有公网 IP 时如何继续电脑工作”做成设备接力的一部分，同时重新组织用户最常进入的工作页面。实现遵守两条边界：

1. 组网、RDP 和游戏串流都属于独立的高权限软件。HashMM 可以发现和显式交接，但不能静默替用户安装、入网、开启系统服务或保管组网密钥。
2. EasyTier 等组网软件会优先尝试 NAT 穿透和点对点连接，但直连失败时可能使用中继节点。产品必须显示真实链路边界，不能承诺“服务器永远只握手”。

## V591–V597：没有公网地址的设备接力

- 参考 EasyTier 官方源码、使用说明、P2P 优化和隐私边界，采用“外部组网服务归外部软件管理，HashMM 只做用户批准后的工作交接”的集成方式。
- 桌面主进程发现 EasyTier、WireGuard、Tailscale、ZeroTier 等常见虚拟网卡，以及本机 RDP、Moonlight 和 EasyTier 客户端是否存在。
- 用户填写目标私网 IP 或设备名后，可显式选择：
  - HashMM 控制：打开沙箱化查看端，继续使用短时配对码、逐次授权和已有审计；
  - 远程办公：通过参数数组交给系统远程桌面；
  - 低延迟画面：交给 Moonlight，主机仍需先安装 Sunshine 并完成配对。
- 目标、端口和 Moonlight 应用名均在主进程再次校验；子进程不使用 Shell，网页窗口限制协议、主机和端口，新窗口请求被拒绝。
- 未把 EasyTier 二进制复制进安装器。本轮避免引入 LGPL 再分发义务、虚拟网卡驱动和系统服务生命周期风险；用户通过官方渠道安装并拥有自己的网络配置。

## V598–V600：用户工作入口

- “今天”页不再展示内部 Agent、检索或运行统计，改为最值得处理、快速开始、等待你和后台继续。
- “项目”页使用目标、交付物和验收标准解释何时建立长期项目，并保留真实的新建项目和进入 Chat/进度动作。
- “资料库”支持选择多份当前账号有权读取且已进入检索系统的资料，再创建同一 Chat 中的提问、比较或成果任务。没有资料、加载失败和权限缺口不会伪装成成功。

## V601：画布与协作

- 画布和协作成为左侧稳定入口，问答栏不再用遮挡式弹层承载这两项长期工作。
- 画布提供空白、进度报告、方案对比、数据看板和协作画布起稿；有服务器时保存为当前对话的真实 HTML 文件，没有服务器时明确打开“本地草稿”而不是假装已保存。
- 画布继续复用当前对话文件、版本、模板和右侧 Artifact 检查器，不创建第二套孤立数据。
- 协作继续调用现有团队运行接口；新对话进入本地会话列表，失败显示实际错误，完成后可回到原对话继续验收。

## 明确限制

- 尚未在两台真实异地设备、对称 NAT、企业防火墙或 24 小时连续运行环境中验收。
- 当前只发现虚拟网卡和客户端，不读取 EasyTier 实际 Peer 路径，因此不能在 HashMM 中断言某次连接一定是 P2P 或一定经过中继。
- RDP 需要目标 Windows 版本、账号、网络级别验证和防火墙策略允许；Moonlight 需要 Sunshine 主机与首次配对。
- HashMM 自带控制仍依赖用户显式开启宿主、短时配对和现有权限审计；私有网络只改变寻址路径，不自动扩大远程权限。
- SHA-256 只能证明构建产物完整性，不能替代 Windows Authenticode 发布者身份。
