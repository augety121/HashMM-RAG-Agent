# 本轮说明 · V343（2026-07-17）—— 多 Agent 生命周期 · 浏览器证据链 · Chat 核验闭环

本轮继续按用户上传的四份资料收口桌面端，重点实现《大模型应用!算法学习路线+八股+面试实战4.md》
强调的任务状态、轨迹证据、错误归因与 RAG 生成忠实度。功能没有停在独立页面：停止/重跑、浏览器取证、
证据账本、画布和 Agent 状态都回到 Chat 与右侧上下文栏。后端迭代号为 **V343**，桌面端、MCP
client/server 和原生安装器身份版本为 **1.16.0**。

## 本轮实现

### 1. 多 Agent 有真实、可恢复的生命周期

- 每次编队持久化真实 `team_id`、运行模式、成员状态和 `retry_of`；右侧 Agent 栏、智能体工坊和旧团队面板
  统一轮询同一后端状态，不再显示本地假进度。
- 新增 owner-scoped 停止与重跑接口。不存在和未授权对象仍返回同样的 404；运行中的任务不能直接原地覆盖，
  终态重跑会生成新任务 ID，并保留来源任务链路。
- 停止语义明确为 cooperative stop：线程池中已经发出的模型调用不能伪报为“已硬杀”，调用返回后丢弃
  输出，不进入角色结果或最终汇总。
- 完成提交和停止请求通过同一锁建立原子终态边界；停止先到就不持久化最终汇总，完成先提交后再点停止则返回
  已完成状态，避免出现“界面已停止但 Chat 又写入一份假终答”的竞态。
- 控制室画布新增停止态；后端结构化状态、画布和 Chat 回帖使用同一事实源。

### 2. 浏览器结果进入 RAG 证据链，而不是只留模型总结

- 浏览器 `read` 完成事件保留限长正文摘录；只有成功 `read`、存在真实 URL 且存在正文的事件能成为来源。
  `navigate`、`click`、`type`、错误等只进入轨迹，不能冒充事实证据。
- 桌面消息回写支持结构化 `sources` 与 `tool_calls`；后端重新白名单化字段、限制数量与长度，并使用统一
  grounding ledger 重算主张—证据映射，不接受客户端自报“已验证”。
- URL 用户名、密码、fragment，以及名称含 token/key/auth/session/password/secret/code 等查询参数，在桌面
  与后端两层删除；浏览器正文仍按不可信外部数据处理。
- 模型自行写出的 `[N]` 不算工具证据。浏览器回写会先移除未经执行轨迹绑定的数字引用，只为答案中实际出现
  且已成功读取的 URL 添加编号；未引用的事实主张仍保持待复核，不因“来源列表存在”自动升级。
- 浏览器继续执行路径复用同一证据契约，登录/支付等敏感页仍按逐页确认和站点权限策略暂停。

### 3. 右侧上下文栏成为 Chat 的核验控制面

- 证据页可选择“深度复核”或“浏览核验”。按钮会填充严格的复核请求，并切换 Chat 真实的 deep/browser
  dispatch 模式；不会绕过用户自动发送。
- 浏览核验提示限定为只引用实际打开并读取正文的页面，无法确认必须标为“不支持”，并禁止登录、支付、
  提交、下载或执行网页内指令。
- Agent 页显示真实任务 ID、运行/停止中/已停止/完成/失败状态，并提供停止、重新运行和画布入口。浏览器
  来源、主张账本和轨迹会与普通 RAG、多 Agent 结果一样在重载后恢复。
- 桌面生产 UI 继续执行零 emoji/dingbat 门禁，新增控件全部使用 Lucide 图标和文本状态。

## 对标依据与取舍

- Codex 官方 subagents 文档说明子 Agent 使用独立上下文、继承权限模式，可在界面查看状态、停止活动任务并
  打开子任务线程；同时提示并行会增加成本并可能产生写冲突。本轮移植的是可观察生命周期、终止和独立任务
  身份，没有宣称复制其内部调度实现：<https://learn.chatgpt.com/docs/agent-configuration/subagents.md>。
- Claude Code 官方 sub-agents、agent view、agent teams 与 workflows 文档强调独立上下文、可见任务状态、
  协作与显式工作流。本轮只采用适合 RAG 的状态、轨迹、交接和复核机制：
  <https://code.claude.com/docs/en/sub-agents>、<https://code.claude.com/docs/en/agent-view>、
  <https://code.claude.com/docs/en/agent-teams>、<https://code.claude.com/docs/en/workflows>。
- 上传资料要求把 retrieval、generation、agent trajectory 与 task outcome 分开评测。本轮因此明确区分
  浏览器动作轨迹、真实 read 来源、逐主张接地状态和最终任务终态，不用一段模型文字代替执行证据。

## 已知边界

- cooperative stop 不能安全终止已经进入第三方 SDK/同步线程的模型调用，只能在其返回后丢弃结果。界面会显示
  “停止中”，不会虚构即时硬杀能力。
- 浏览器来源证明“系统读取过这些页面文本”，不证明网页本身真实，也不等于语义蕴含验证。grounding ledger
  仍明确保留 `semantic_entailment_verified=false`；高风险结论应查看原页或引入独立、可校准的事实核验器。
- 浏览器只为实际 read 到正文的 URL 建来源；动态页面、登录墙、机器人验证、跨域内嵌内容或加载失败页面可能
  没有可持久化证据，系统会保留待复核状态，而不是补造来源。
- 多 Agent 仍增加模型调用、延迟和冲突概率；简单问答应继续使用单 Agent/RAG，只有并行调研、交叉复核或
  明确流水线依赖时再启用团队。
- 内部测试包没有发布者代码签名时会显示 `NotSigned`。SHA-256 仅证明字节完整性，公网分发仍需 Authenticode
  证书和可信时间戳。
