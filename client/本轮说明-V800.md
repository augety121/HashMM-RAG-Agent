# HashMM V800 本轮说明

## 目标

V800 将此前已经存在但分散的 Chat、项目、附件、审批、运行状态、OCR、检索证据和评测能力收口为可恢复、可审计的 Chat Kernel 2.0。本轮不复制或展示任何模型隐藏思维链，只持久化用户可核验的目标、计划、工具动作、审批、证据、检查点、交付和验收状态。

## 已实现

1. **安装目录 ProjectVault**：默认数据根为 `<HashMM 安装目录>\HashMM Data`，不写死 C 盘。`local-backend` 只保存运行时、venv 和本机密钥；数据库、对话附件、资源缓存、索引和备份全部进入 ProjectVault。
2. **安全迁移**：首次启动从旧 `local-backend\data` 复制数据，校验逐文件 SHA-256、数量和字节数后原子启用新目录；旧数据保持原位，不做静默删除。已有非空 ProjectVault 不会被旧目录覆盖。
3. **完整“最近”**：项目会话不再从“最近”中排除；列表按更新时间显示全部有效对话并渐进加载。同步会遍历 owner-scoped 服务端分页，离线缓存保留完整会话元数据索引，避免第 121 条以后消失。
4. **扫描 PDF OCR**：持久 OCR worker 对扫描 PDF 逐页渲染和识别，保存 `p.N` 证据锚点、页数、可读页数和内容寻址缓存；失败继续沿用持久重试与 Chat 重试界面。
5. **Agent 执行闭环**：显式附件成为关闭的私有资料作用域；全局知识库、跨任务记忆和未选择文档不能混入。审批按指纹、原工具和原参数一次性消费；客户端重连后可从持久批准状态续接。没有真实成果、工具回执或验收证据时，完成门拒绝宣称完成。
6. **证据演化与评测**：沿用已接入的 Expected Gain 检索决策、受治理知识演化隔离区和 LoHoSearch L0–L3 harness。候选知识必须有来源与 SHA-256，经人工审查、冲突处理和评测门后才能提升；没有官方数据快照时不声称官方分数。

## 真实边界

- 供应商模型进程崩溃后不能从供应商内部 token 光标无损续写；HashMM 恢复的是已持久化事件、审批、检查点和安全重试边界。
- OCR 真实准确率取决于服务器实际安装的 Tesseract/PaddleOCR、语言包和扫描质量；没有 OCR 引擎时作业会失败并显示可重试错误，不会伪造正文。
- LoHoSearch 官方数据不随代码分发；未提供官方快照和清单时只运行本地 smoke/contract 验证，不声明可比成绩。
- 公网日志中的 HTTP 警告仍必须由部署者通过 HTTPS/WSS 反向代理和 `HASHMM_REQUIRE_SECURE_REMOTE=1` 解决；代码包不会替部署环境伪造 TLS。
- 安装包若未提供 Authenticode 证书，只能提供 SHA-256 完整性证据，不能声称具有受信任发布者身份。
