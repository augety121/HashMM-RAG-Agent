# HashMM V360 本轮说明

日期：2026-07-19

## 本轮结果

本轮把 Codex 风格的“任务运行中继续协作”接入了 HashMM 的真实 Chat 主链。桌面端和 App 不再只能等待长任务结束：用户可以在任务运行时追加指令，也可以精确停止当前轮次；服务端、消息持久层和 AgentLoop 共同决定真实状态。

## 关键改进

- 每个会话只有一个活动轮次，追加指令与停止都绑定属主和精确 `turn_id`，冲突、过期和旧轮次请求明确拒绝。
- 追加指令先持久化为真实用户消息，再在 AgentLoop 安全边界中消费；既不会丢失，也不会成为绕过工具权限的系统指令。
- 最终回答提交与追加指令采用原子竞态保护；已接受的追加指令在 AgentLoop 失败回退时仍进入直接生成上下文。
- 用户停止会中止真实运行，保留部分输出并标记 `interrupted`，跳过建议、偏好学习、演化和其他完成后副作用。
- Desktop 和 App 均允许在长任务运行时继续输入，并提供独立停止入口；App 使用与桌面端相同的会话富流式协议。
- 移动端不再在不确定网络失败后盲目重发旧请求，避免重复计费、重复消息和重复工具执行。

## 已知边界

- 活动轮次协调器当前是单个服务进程内状态，适用于现有单进程部署。未来若启用多 worker，需要引入 Redis 等分布式协调器或粘性路由，不能假装跨进程实时追加已经成立。
- 已接受的追加指令是持久化消息；正在执行的 Python 协程不是跨进程重启可恢复对象。服务重启后用户消息仍在，需从同一会话继续，但旧运行不会伪装为仍在后台执行。
- Debug APK 不是应用商店正式签名包。SHA-256 只能证明制品完整性；未配置 Authenticode 时，桌面 EXE 也不能宣称具有发布者身份签名。
