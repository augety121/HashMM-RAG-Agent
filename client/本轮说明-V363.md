# HashMM V363 本轮说明

发布日期：2026-07-19

## 本轮结果

- 截图中的“浏览器站点权限”旧 Windows 蓝色框已经从实现源头删除，改为 HashMM 主界面内的“隐私保护”审批弹层。
- Browser Use、Computer Use、检查点回滚、危险工作区提示和更新确认共用同一结构化审批协议，不再各自维护不一致的系统弹窗。
- 审批弹层明确显示目标、操作说明和权限边界；默认焦点落在取消项，Esc、点关闭、点遮罩、超时或主界面不可用都不会批准操作。
- 检查点回滚原先在系统弹窗失败时会直接执行，本轮改为 fail-closed：没有明确批准就不覆盖文件。
- 主进程维护请求 ID 与审批队列，渲染器刷新后通过 ready 握手重放同一请求；未知 ID 或请求未提供的决定不能生效。
- Electron preload 只开放结构化审批订阅、ready 和按请求 ID 回传决定；决定通道纳入 sender 来源校验。
- 应用菜单“关于 HashMM”改为打开新版设置“关于”页。普通消息框只保留启动崩溃兜底；文件和目录选择器仍保留系统原生交互。

## Codex 参考边界

- 本轮只采用本地 `codex-main (1).zip` 中可由源码验证的结构化审批机制：请求类型、请求 ID、候选决定、队列、取消和已解决请求匹配。
- 官方在线手册当前连接失败，因此没有声称 HashMM 的视觉细节与某个未验证的 Codex 桌面版本完全相同，也没有把模型描述当执行证据。
