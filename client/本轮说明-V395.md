# HashMM V395 本轮说明

日期：2026-07-23

## 本轮定位

本轮不是继续增加孤立入口，而是建立第一版面向用户的统一工作投影：后端仍由 RAG、AgentLoop、浏览器、电脑操作、多智能体、权限和工具系统执行，桌面端与 App 统一围绕“正在做什么、为什么需要我、产出了什么、能否继续”展示。

本轮完整落地 V395，并完成了 V396、V398 的第一阶段。未完成的后续版本在本文末尾明确列出，不把设计方案或静态页面描述成已实现能力。

## 已完成

### 1. 统一 WorkPresentation

- 新增 `hashmm.work-presentation.v1`，由服务端把内部运行状态投影为用户可理解的标题、阶段、当前步骤、下一步、交付物、证据和同步状态。
- 进度只在存在明确验收项时显示 `已通过 / 总数`；缺少客观依据时只显示阶段，不虚构百分比。
- 桌面端、右侧上下文和 Android App 使用同一份展示投影，避免各端自行猜测状态。
- 对旧服务端响应保留保守兼容：字段缺失时可以展示，但不会误判为“已完成”。

### 2. 统一 ActionInbox

- 新增 `hashmm.action-inbox.v1`，只汇总真正需要用户处理的授权、澄清、阻塞和交付物。
- 待办查询按账号隔离，并独立于增量游标查询；即使本轮没有新事件，尚未处理的待办仍会返回。
- 增加账号隔离、安静游标、优先级和展示语义回归测试。

### 3. 桌面端第一阶段收束

- 主导航收束为“新建工作 / 进行中 / 成果 / 资料”，浏览器、Computer Use、多智能体等执行能力不再直接占据普通用户的主导航。
- 新增用户工作总览，区分待处理、进行中与成果；显示真实阶段、验收项、交付物和证据。
- 暂停、继续、重试只在服务端明确声明可执行动作时出现，不提供无后端能力的演示按钮。
- Chat 输入区默认只保留高频入口；浏览器、深度检索、模型、多智能体、画布、电脑操作等放入“更多”，同时仍可被 Agent 按任务需要调用。
- 右侧上下文不再把 revision、event cursor 等内部字段直接展示给普通用户。

### 4. Android App 第一阶段重构

- 底部导航调整为“对话 / 待办 / 工作 / 我的”。
- “待办”改为读取与桌面端同源的 ActionInbox，不再预取旧动态页的用量、Feed、能力与实时活动。
- “工作”展示用户标题、状态、当前步骤和下一步，保留真实可用的暂停、继续、重试与对话接力。
- 服务端读取失败会明确提示，不再伪装成“暂无待办”。
- 修复内存工作缓存没有绑定账号的问题：账号切换时先清空内存快照，再读取当前账号的加密持久化缓存或服务端增量，避免跨账号短时串数据。

## 尚未完成

- V396 只完成了主导航、工作总览、输入区和右侧上下文的第一阶段；旧管理后台、帮助、设置等所有页面尚未全部迁移到统一用户工作模型。
- V397 的完整工作画布还未完成。当前已有统一工作总览，但“概览 / 过程 / 证据 / 成果”四个连续视图、可恢复检查点和可视化依赖关系仍需继续实现。
- V398 只完成了 App 的待办与工作主路径。旧页面代码虽已停止展示和请求，但尚未全部物理删除；所有卡片的手机原生交互也未在本轮逐页重做。
- V399 的统一 Office 成果模型、完成回执、跨端增量缓存失效协议尚未完成。
- V400 的受治理主动智能尚未完成；本轮不宣称 AGI，也没有把模型推断当作真实完成证据。
- 本轮没有进行真实 Supabase 双设备、外部 Browser Use 或 Computer Use 的人工端到端验收；已完成的是确定性的单元、集成、构建与发布流水线验证。
- Windows EXE 当前未做 Authenticode 签名；Release APK 当前未用正式产品发布密钥签名。现有 SHA-256 能证明文件完整性，不能替代发布者身份。
