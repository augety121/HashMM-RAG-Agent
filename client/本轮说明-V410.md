# HashMM V410 本轮说明

V410 的目标不是再增加一组孤立页面，而是把登录、长任务、多 Agent、浏览器画布、Office 成果和 App 接力收敛到同一套可恢复、可核验的工作协议。本说明只记录已经落到代码并经过确定性验证的内容；路线图中的长期指标不冒充本轮已完成事实。

## 用户可见变化

- 修复 AutoDL 启动回归：服务器明确监听 `0.0.0.0:6006`，不再出现容器内健康、桌面端和 App 却无法连接并误弹登录的情况。
- 修复真实旧 SQLite 数据库升级阻断：完整建表脚本不再抢在 V24 补列前创建 `idempotency_key` 唯一索引；启动时会先以可重复、不中断旧数据的方式补齐 WorkRuntime 新列，再建立索引。V23 旧库和“版本号已到 24、列尚未落完”的中断升级状态都可自愈。
- 修复 Supabase 统一身份与本地兼容账号策略不一致：Supabase-only 模式不再因不可登录的 `admin/admin123` 误判为启动失败，本地注册入口同时关闭；若明确启用本地登录，默认密码仍会阻断生产启动。安全门已前移到 FastAPI 接收请求之前，不再产生“服务已就绪后后台任务抛异常”的假健康状态。
- 修复 V410 首次生成强 `HASHMM_SECRET` 后历史模型 Key 无法解密：仅当旧 Fernet 密文能通过历史密钥的完整性认证时，自动重新加密到当前强密钥，并同步模型镜像；不猜测明文、不记录密钥，显式轮换可通过 `HASHMM_SECRET_PREVIOUS` 完成。
- 恢复管理员完整控制面而不把内部架构重新暴露给普通用户：普通用户仍只进入个人模型、个人记录和消息渠道；管理员后台现在直接承载真实的 Agent 编排、模型路由、工具与 MCP、凭据与 Hooks、计划任务、运行轨迹、质量看板、权限审计、测试中枢、记忆治理、跨 Agent 协作和服务连接。这里复用已接后端的生产组件，不是另做一组无数据演示卡。
- 修复管理后台的角色投影边界：身份尚未验证时不再短暂闪出管理员导航；服务端明确拒绝令牌后也不会信任本地缓存的管理员角色。只有后端确实离线时才使用缓存角色展示离线骨架，所有管理 API 仍由服务端独立鉴权。
- 旧 `start-hashmm1` 中的 Supabase/JWT 配置不再硬编码进新脚本。新启动器把旧脚本当作不可信文本，只迁移白名单静态变量到 `.env`，不执行旧脚本、不打印密钥，并保留已有非占位配置。
- 根据真实 AutoDL 首次部署回执补强配置恢复：启动器会把模板中的开发模式、占位 JWT、缺失数据密钥、空/通配 CORS 修复为持久化的生产安全基线，并把 Linux `.env` 权限收紧为 `0600`；Supabase 常见旧变量名会归一化。Supabase URL 和 publishable key 属于外部账号事实，仍只从用户原有 `.env`、进程环境或显式旧脚本迁移取得。
- 根据第二次真实启动回执继续修复迁移边界：旧脚本中的可选占位密钥不再写入 `.env`，缺少可选 benchmark token 只表示关闭该能力，不能阻断主服务启动。
- 桌面登录在保存会话前验证后端确实接受 Supabase session；后端明确返回 401/403 时，不再绕过后端直接刷新 Supabase 并形成反复登录循环。
- 长工作使用原子 WorkEvent、服务端 revision、幂等键和 generation。桌面端和 App 看到的是同一运行、同一事件顺序和同一当前代次。
- 多 Agent 的 `auto` 模式按并行收益、协调成本、共享写风险和依赖风险确定采用流水线还是并行执行；用户明确选择的模式仍然优先。
- 浏览器证据、工作画布和 Office 输出登记为内容寻址的 ArtifactRevision。相同内容幂等复用，内容改变产生新修订，owner 或旧 revision 不能越界写入。
- App 命令与成果验收在发送前进入账户隔离加密 outbox。超时、断网或不兼容响应只用原 ID 做幂等核对并指数退避，不重新生成可能重复执行的动作。

## 核心协议与数据

- 数据库 schema：24。
- WorkEvent：owner-bound、revision-bound、idempotency-bound；事件、快照、generation、账户游标在同一事务提交。
- WorkGeneration：Knowledge / Work / Evidence 三平面只保存有界元数据、引用和哈希，不复制来源正文。
- ArtifactRevision：保存内容 SHA-256、媒体类型、大小、定位信息、验证状态和递增修订；Artifact、事件、generation 与工作快照原子切换。
- Agent Mesh：输出稳定的 `hashmm.agent-mesh-decision.v1` 决策证据，不使用模型自评冒充调度依据。
- App outbox：稳定 `command_id` / `decision_id`、账户隔离加密存储、有上限指数退避和确定响应后出队。

## 安全边界

- 上传文件、网页、工具输出、旧启动脚本和模型文字始终是不可信数据。
- 旧脚本迁移仅解析白名单静态赋值，拒绝命令替换和动态 Shell 语义；正常启动不再自动安装依赖。
- 缺失与越权工作对象继续使用不可枚举响应；Artifact 和 generation 写入必须通过 owner 与 revision 检查。
- App 离线重试不会绕过服务端权限、审批、revision 或幂等准入。
- 模型文字、页面进度和 UI 动画都不构成执行或完成证据。
