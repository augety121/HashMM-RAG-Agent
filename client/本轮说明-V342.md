## 本轮解决的真实缺口

### 1. 多 Agent 不再脱离 RAG 各说各话

- 团队启动后先通过现有 `ChatRetrieval` 建立一次限量共享证据包，所有角色和汇总者共用同一组 `[N]`
  引用编号，避免每个角色自行生成含义冲突的 `[1]`。
- 检索片段按不可信数据处理并经过注入内容清洗；角色提示明确禁止遵循证据中的命令、角色设定或越权要求。
- 事实、数字和外部结论必须引用共享证据；没有命中、路由跳过或检索失败时，角色必须写明“未由当前知识库
  验证”，不得补造来源。
- 并行模式使用真实 `asyncio.gather`；有前后依赖时保留流水线模式，后一角色获得前序产出。单角色失败不会
  拖垮整个团队，失败原因和耗时进入轨迹。
- 汇总者不得把角色意见升级成已验证事实，也不得创建共享证据里不存在的编号。

### 2. 多 Agent 的结果真正回到 Chat，并可在重启后恢复

- 团队完成消息持久化真实 `sources`、逐主张 `groundings`、角色编制、角色耗时和检索/执行/汇总轨迹。
- orchestration 快照与 trace 一起进入 assistant 消息的结构化 `tool_calls`；前端从服务端历史、重新挂接和
  跨设备同步三条入口统一恢复，避免刷新后只剩一段汇总文字。
- 团队状态接口按 authenticated uid 做 owner check；不存在与未授权团队均返回同样的 404，防止对象枚举。
- 团队控制室画布新增共享证据状态、命中数和失败边界；画布状态、角色结果和最终汇总仍由后端真实执行更新。

### 3. Chat 右侧上下文栏统一承接证据、Agent 和文件

- 新增会话级右栏，分为“证据 / Agent / 文件”三页，不再要求用户离开对话去多个孤立面板寻找上下文。
- 证据页展示覆盖率、supported/inferred/unsupported 计数、来源列表和待复核状态。
- “复核未支持主张”只把深度核验要求填入输入框，不会绕过用户自动发送，也不会假装已经核验。
- Agent 页展示编排策略、角色状态、待办和执行时间线；支持 pending、running、done、failed、blocked、
  waiting_input 等显式状态。
- 文件页复用现有 artifact/canvas 打开链路；右栏与产物面板共用可拖动宽度并持久化，避免两套割裂布局。

### 4. 桌面生产界面执行零 emoji 门禁

- 前端生产组件和 Electron 自有页面/脚本中的 emoji、彩色符号、dingbat 均替换为 Lucide 图标或 ASCII 语义
  标识；附件、Computer Use、导出和旧历史兼容仍保留机器可解析语义。
- 新增 `desktop/tests-node/test_no_emoji_ui.js`，扫描 `frontend-next/components`、`frontend-next/lib` 和桌面生产
  源码；后续任何 emoji 回流都会让桌面测试和发布流水线失败。
- 第三方运行时、测试样本和历史 changelog 不冒充产品 UI，因此不纳入生产界面门禁；构建产物由本轮前端
  重新生成。

## 已知边界

- 逐主张账本仍是显式引用加确定性词面支持代理，`semantic_entailment_verified=false`；它提供可追溯性，
  不承诺自然语言事实核查或绝对无幻觉。高风险结论仍应查看原文，或后续接入可校准的独立 judge。
- 团队共享证据当前是一份最多 6 条来源的本地知识库检索包；团队不会在后台擅自启动开放网络搜索。需要
  新鲜网页事实时，应在 Chat 中经现有浏览器/Deep Search 权限链路检索后再派团队复核。
- 多 Agent 增加模型调用、延迟和冲突概率；应只在并行调研、交叉复核或明确流水线依赖时使用，简单问题继续
  走单 Agent/RAG 主链。
- 安装包为内部测试包且 Authenticode 状态为 **NotSigned**。SHA-256 只能证明字节完整性；公网分发仍需用户
  自己的代码签名证书和可信时间戳。
