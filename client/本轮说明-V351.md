# HashMM V351 本轮说明

日期：2026-07-19

## 本轮目标

本轮把桌面端和 App 从“展示底层模块与开发术语”进一步改成面向最终用户的工作体验，并优先修复 App“团队管理只有管理员一个账号、用量始终为 0”与桌面端数据不一致的问题。所有统计继续遵守不造数原则：接口失败、权限不足、旧版本和解析失败必须显式报错，不能展示成可信的 0。

## 真实接线修复

1. 新增 `GET /api/admin/usage/overview` 与响应契约 `hashmm.usage-overview.v1`。
   - 管理员：服务端返回整个团队的真实用量汇总。
   - 普通用户：只返回当前用户数据，不暴露其他成员。
   - 两个范围使用同一字段结构，Desktop 和 App 共用。
2. App 不再固定请求 `/usage/me`；因此管理员不会再把个人统计误当成管理统计。
3. App 对 401、404、网络失败、空响应和契约版本不兼容分别提示，不再把失败解析成 0。
4. `/api/admin/users` 先使用当前 Supabase 管理员的 bearer token 调用 `list_all_profiles` RPC，与桌面端使用同一身份目录。该令牌只转发给同一 Supabase 项目，服务端不会把 service-role 下发到客户端。
5. 成员数据补齐 email、display name、身份来源、注册时间和最近登录；RPC 失败时保留 service-role profile / 本地用户回退，不影响纯本地部署。

## 面向用户的双端重构

- App 工作台标题改为“帮你完成”，主要分区改为“让电脑帮忙、复杂工作、任务与进度、更多能力”。
- “智能体工坊、总控中枢、权限审计、质量看板、测试中枢、上下文透视”等默认入口改成用户任务语言；底层名称不再占据第一层。
- App “团队管理”增加团队一览、成员角色、云端同步说明、最近登录和用户化安全记录。
- App “使用概览”增加团队/个人范围标识、真实空状态、完成次数、处理量、输入/生成、估算花费、按成员与按模型下钻。
- Desktop 左侧入口改为“当前工作、资料与创作、复杂任务、任务与进度、电脑与连接”。
- Desktop “团队与服务”替代默认“管理后台”，导航按“团队与服务、资料与知识、能力设置”组织。
- Desktop “使用概览”默认展示 HashMM 对话与长任务的结果；本机 Claude Code/Codex 统计保留在折叠的“本机开发工具用量”，不干扰普通用户。
- 桌面端 UI 仍保持零 emoji，图标继续使用 Lucide。

## 明确限制

- 团队成员完整目录依赖 Supabase 已部署 `list_all_profiles` RPC；这是桌面端当前已经使用的同一 RPC。未部署时会回退 service-role profiles 或本地用户，并显示真实结果，不会伪造成员。
- 使用概览只统计经过 HashMM 服务端生成链路并写入 `usage_log` 的调用；手机直连第三方模型和纯本机 Claude Code/Codex 不属于团队账单。桌面端仅把后两者放在折叠的开发信息中。
- 估算花费来自服务端模型单价表，不是供应商最终账单；页面已明确标注“估算”。
- 本轮完成了工作台、团队与服务、用量这些高频表面的用户化重构，不声称所有高级管理页已经全部完成终端用户化。
- 服务器 ZIP 排除了 `frontend-next`、`desktop`、`installer-native`、tests、本地数据、模型、索引、缓存、密钥和历史归档。本轮没有生成新的正式签名 Native EXE；APK 为 debug 构建。
