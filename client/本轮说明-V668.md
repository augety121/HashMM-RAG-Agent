# 本轮说明 V668

## 本轮目标

V628–V668 不是 41 个彼此孤立的页面版本，而是一轮围绕同一条 Chat/长任务主链完成的协议与运行时升级。目标是让桌面端、App、自动任务、RAG、代码工作、多 Agent 和成果画布消费同一份可验证工作事实，同时明确哪些结论来自真实执行、哪些只是模型建议。

## V628–V633：统一工作协议

- 新增 `hashmm.work-protocol.v3`。`WorkSpec`、动作、观察、证据回执和成果引用使用类型化结构，并生成稳定指纹。
- 公共投影有界、脱敏，不包含源文件正文、工具私密参数、密钥或模型私有推理。
- 工作画布从运行账本确定性生成协议投影。只有受执行器约束的已知事件会成为动作；普通模型文本不会被升级成执行证据。

## V634–V639：上下文编译器

- 新增 `hashmm.context-compiler.v3`，按来源类型、可信级别、证据质量、新鲜度和令牌预算选择上下文。
- 支持注入供应商官方计数器；缺少官方计数器时使用明确标注为估算的保守多语言回退，不伪称精确 token。
- 不可信网页、检索结果和外部输出以边界标记包裹，并记录被丢弃内容的损失台账。
- 当输出保留量已经耗尽模型窗口时失败关闭，不会把零预算误解释为无限预算。

## V640–V645：Agent Fabric

- 多 Agent 委派改为显式 `DelegationContract`：目标、交付物、成功标准、预算、允许工具和最小权限范围均可检查。
- 使用收益、成本和重叠度做委派准入；第一项有效任务正常准入，后续高度重复任务被拒绝，避免用重复 Agent 浪费 token。
- 子 Agent 权限从父范围派生，不能自行扩大工具、路径或联网权限；公共结果不暴露私有思维链。

## V646–V651：能力运行时与生命周期

- 能力快照增加面向用户的能力清单：可用性、依赖、健康状态、副作用、审批要求和可见入口由同一事实投影。
- Hooks 扩展到会话、用户输入、工具、权限、压缩、子 Agent 和停止等生命周期；关键策略 Hook 失败关闭，观察型 Hook 失败会被记录但不破坏主流程。
- 继续复用现有权限、沙箱和 IPC 边界，没有为追求“自动化”静默扩大文件、网络或桌面控制权限。

## V652–V657：跨端增量同步

- 数据库 schema 升至 31，新增账号隔离的 `work_sync_changes` 游标日志。
- 运行、事件、成果修订、决定、放置选择、租约和标注都会产生有界公共变更；同步记录不包含提示词、文件正文或工具参数。
- 新增 owner-bound 增量同步 API。服务端事实负责权限与共享，客户端仍可维护本地项目连续性；这不是客户端任意事件上传或覆盖服务端事实的接口。

## V658–V663：代码工作运行时

- 新增有界仓库地图：遵守工作区边界、不跟随符号链接逃逸，输出文件哈希、语言、符号和依赖摘要。
- Python 使用 AST；其他语言使用保守语法提取器并在结果中标明 parser contract，不把正则扫描伪装成完整语义索引。
- 新增带预期哈希前置条件、原子替换、事务日志和回滚校验的文件事务。
- `repository_map` 作为只读工具进入统一工具注册表和权限分类，供 Chat/长代码任务按需调用。

## V664–V668：用户投影与发布一致性

- 桌面工作画布“证据”区域增加可核验工作记录：动作、观察、证据回执、协议指纹以及“不包含正文/私有推理”的隐私说明。
- 桌面、MCP 和 Native source 统一为 1.39.0；Backend 统一为 V668；数据库 schema 为 31。
- App 本轮没有在当前仓库中重新构建 UI。它可消费 owner-bound 增量同步协议，但实际 App 页面接入、弱网恢复和多设备体验必须在 App 工程及真实设备上继续验收，不能写成已经完成。

## 明确边界

- 本轮不复制或展示 Codex、Claude Code 的私有思维链。可见的是计划、动作、观察、证据、决定与结果。
- 本轮没有训练新基础模型；长代码与长任务能力提升来自上下文、工具、委派、事务和验证 Harness。
- 仓库地图不是完整语言服务器；供应商 token 回退不是官方精确计数；两者都会把能力边界写入结果。
- 尚未完成真实公网多设备、对称 NAT、自有 TURN、24 小时稳定性、Android 实机 UI、Windows Authenticode 和生产密钥环境验收。
