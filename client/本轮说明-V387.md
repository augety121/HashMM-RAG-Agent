# HashMM V387 本轮说明

日期：2026-07-22

## 结果

本轮把远程连接、办公文件回写和会话文件缓存接入了统一 Chat/长任务事实链，重点解决“页面显示了能力，但状态不真实或没有闭环”的问题。

桌面端远程执行器现在持续上报经过裁剪的连接质量：RTT、丢包、可用带宽、FPS、质量档位和调整原因。主进程只接收受信远程窗口的有界 schema，页面可以把这些事实附加给 Chat 做诊断，但不会自动发送，也不会携带 SDP、候选地址或原始 RTCStats。Android App 直接读取自己的 WebRTC 统计并用确定性阈值显示质量，不再把桌面状态或静态文案当作测量结果。

Office 文件交接不再只依赖大小与修改时间。桌面端稳定读取文件内容、计算 SHA-256、上传到属主会话并校验服务器落盘哈希，最后用同一哈希确认本地 revision；如果用户在上传过程中继续编辑，系统会明确报告版本冲突，不会误标为已同步。后端会话文件列表隐藏绝对路径，提供 ETag 和 revision；前端按账号/会话持久缓存，先显示缓存，再做条件校验，只有数据变化才刷新页面。

这些能力继续运行在 V386 建立的 `hashmm.agent-harness.v1`、冻结作用域、真实 capability 交集、属主检查、上下文检查点和不可信 RAG 边界内，不是新增一套割裂的演示页面。详细参考与取舍见 `docs/reference-audit-V387.md`。

## 明确限制

- 本轮没有生成新的 Windows 安装程序。源码发布闸门通过不等于正式 EXE 发布完成；正式发布仍须运行 `installer-native/build-all.bat` 并核对 EXE、`.sha256`、`.release.json` 三方一致。
- Android 交付物是 debug-signed APK，不是应用商店正式签名包。
- HashMM 没有复制或接入 UU 远程、vivo 办公套件的私有协议，也不声称硬件级隐私屏能力；只独立实现了可审计的质量反馈、系统文件关联和内容版本握手。
- 远程质量只在连接存活并取得 RTCStats 时有意义；未测量状态不会被推断为“良好”。
- 会话文件缓存减少正文和列表重复传输，但版本确认仍会发起轻量条件请求；离线缓存不是服务器最新状态的证明。
- SHA-256 证明同步的是同一字节版本，不证明文档内容真实、正确或安全；外部文件与 RAG 内容仍按不可信数据处理。
