# HashMM V391 本轮说明

日期：2026-07-23

## 结果

本轮把浏览器、画布、RAG 证据、长任务因果图和完成门收束为一条真实运行链路，不再把“打开网页”“生成画布”和“任务完成”作为彼此割裂的页面功能。

新增协议与关键能力：

1. `hashmm.evidence-ref.v1`
   - 浏览器选区生成内容寻址证据引用，记录规范 URL、页面标题、选择器、上下文、内容哈希、观察时间、来源信任和新鲜度。
   - 后续可回到真实 WebContents 重新定位并复核；页面变化、定位失败或不可达均明确变为 `stale` / `unavailable`。
2. 浏览器—画布语义双生
   - 浏览器选区可直接链接到画布块；画布中可以查看来源状态、回到原网页和解除关联。
   - 画布发布前核验全部关联证据，旧证据或不可用来源会阻断发布，不再让过期内容以“已验证”状态传播。
3. 画布精确修订协议
   - 整体保存支持 `base_sha256 + lock_session`，服务端同时校验会话属主、活租约和基线修订。
   - HTML 画布新增块级补丁；只接受唯一精确锚点，全部操作原子提交。基线、租约或锚点冲突都会拒绝覆盖。
   - Agent 使用同一 `canvas_block_patch` 工具，并进入权限表、能力探测、统一审计和提示词约束。
4. 因果新鲜度完成门
   - EvidenceRef 进入 `hashmm.causal-work-graph.v1`，形成来源到产物的确定性依赖。
   - 来源变化只失效下游闭包，不清空无关工作；进程恢复后仍保留失效状态。
   - 完成门检测到陈旧依赖或无效执行回执时保持关闭，模型不能仅凭文字声称任务已经验证完成。
5. 右栏可见状态
   - 上下文右栏跨页签显示陈旧依赖和无效回执提示，并引导到运行证据页。
   - 画布预览显示来源状态和最近核验时间，用户能够判断“这段内容来自哪里、是否仍然有效、需要重做什么”。

## 真实接线

- Electron 主进程负责真实页面选区、DOM 定位、哈希复核和回到来源；renderer 只接收有界证据元数据。
- EvidenceRef 由后端按用户和会话隔离、原子落盘；URL、选择器、标题、上下文与长度均经过边界校验。
- 会话文件整体保存、块级补丁、画布锁、证据链接、发布门、Agent 工具和运行能力探测使用同一服务端契约。
- 因果工作图、run manifest、Team、可恢复循环和完成门消费同一证据新鲜度，不由各页面分别猜测。
- `canvas_block_patch` 已登记为工作区写权限；未登记或不可调用时画布能力按 fail-closed 显示不可用。

## 安全与正确性边界

- 外部网页与选区始终是 `untrusted_data`，不能覆盖系统或用户指令。
- 证据哈希只能证明两次观察到的内容是否相同，不能证明网页主张天然真实。
- 页面重新定位采用精确选择器和内容复核；不做模糊猜测，也不把定位失败当作“仍然有效”。
- 画布并发写入必须满足属主、活租约和基线修订三项条件；冲突时保留原文件并返回明确失败。
- 块级补丁审计只保存动作、长度和哈希，不保存替换正文、凭据或隐藏思维链。
- SHA-256 是完整性证据，不等同于 Authenticode 发布者身份。

## 明确限制

- Android App 位于当前可写工作区之外，本轮没有修改 App 原生页面。服务端新增字段均为向后兼容字段，App 仍可继续读取旧 WorkRuntime 契约；若要在 App 原生展示 EvidenceRef 与因果过期状态，需要在 Android 工程中增加对应类型和界面。
- 当前来源复核覆盖由 HashMM 嵌入浏览器实际观察到的页面。被登录墙、验证码、站点 CSP 或网络策略阻断的页面会诚实标记为不可用，不会伪造已读取状态。
- 画布块补丁当前针对 HTML Artifact；Office 二进制产物继续使用既有内容修订与哈希同步协议。
- 安装包已通过完整性校验，但在配置正式代码签名证书前，Windows 仍无法验证发布者身份。
