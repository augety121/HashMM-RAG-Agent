# 本轮说明 · V336（2026-07-16）—— Codex 式仓库上下文、确认式执行与证据型 Review

这一轮按当前 Codex 官方手册重新核对桌面工作流，优先补的是会直接影响正确性与可审计性的闭环，
不是只改外观：仓库持久指令、复杂任务先计划、用户确认后才执行、统一 Diff，以及不能脱离补丁证据
的代码审查。HashMM 后端迭代号为 **V336**，桌面端与原生安装器版本为 **1.9.0**。

## 已完成

### 1. 仓库指令链与执行计划

- 桌面端新增 `desktop/services/repo-intelligence.js`，按 global → 仓库根 → 当前目录加载
  `AGENTS.override.md`、`AGENTS.md` 和兼容 fallback；同目录只取首个非空文件，更具体目录的内容后置。
- HashMM 全局指令位于 `~/.hashmm/`，与 Codex 自身的 `~/.codex/` 隔离，避免两个产品互相污染配置。
- 指令总量硬限 32 KiB，`PLANS.md` 限 16 KiB；真实路径逃出仓库边界的 symlink 指令文件会被拒绝。
- 非 Git 目录仍加载当前目录的 `AGENTS.md` 与最近 `PLANS.md`，但不会伪造分支、HEAD 或 Diff。
- Computer Use 驾驶舱由“输入即执行”改为“先计划 → 展示逐步验收条件 → 用户确认执行”。完成、停止或
  重放后计划失效，必须重新读取仓库状态，避免拿旧计划盲目执行新工作区。
- 仓库根新增真实 `AGENTS.md` 与 `PLANS.md`，固化架构边界、安全规则、测试门禁和发布证据格式。

### 2. 工作台变更与 Review 面板

- 工作台右栏新增“变更 / Review”，展示分支、HEAD、Git porcelain 状态、staged/unstaged 分文件 Diff、
  指令来源层级与最近计划模板。
- Git 只通过 Node `execFile` 参数数组调用，不拼接 shell；`git:` IPC 已纳入可信 renderer 安全闸。
- Diff 单区最多 350 KiB，超限会明确标记；未跟踪文件只列名，不伪称进入审查。
- Review 前明确提示：显示中的 Diff 与 AGENTS 会发送到当前模型后端；远程后端意味着代码离开本机。

### 3. 证据型代码审查 API

- 新增 `POST /api/repo/plan` 与 `POST /api/repo/review`，都需要登录。
- 后端不接收任意本机路径、不执行 Git，只接收有上限的目标、指令、状态或统一补丁文本。
- Git 状态和补丁都被标记为不可信数据，代码注释中的提示注入不能覆盖计划器/审查器规则。
- 模型 Review 候选必须同时满足：文件真实存在于补丁、行号是真实新增行、至少 8 字符的证据能在
  对应文件补丁中精确匹配。否则确定性丢弃并返回 `discarded_findings`，不展示成事实。
- 严重度限制为 P0–P3，结构化 JSON 解析失败按 502 fail closed，不从含糊 prose 猜结果。

## 仍然存在的边界

- HashMM 现在补齐了仓库上下文、计划确认和 Diff Review，但还没有 Codex App 的隔离 worktree 创建、
  切换与归并体验；并行改同一仓库时仍需用户自己管理分支或独立目录。
- “证据已锚定”只证明模型引用的是补丁真实位置，不证明它对业务语义的判断一定正确；Review 仍必须结合
  测试、类型检查和人工判断，空 findings 也不等于形式化证明无缺陷。
- 未跟踪文件必须先加入 Git 才会进入统一 Diff；每个 staged/unstaged 区超过 350 KiB 的后半部分不审查。
- 计划确认约束的是 HashMM 驾驶舱入口；外部终端中用户自己启动的 Codex/Claude Code 仍遵循各自权限系统。
- 安装包 SHA-256 提供完整性证据，不提供发布者身份。没有 Authenticode 签名时不能对外宣称可信发布者。
