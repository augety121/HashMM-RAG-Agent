# HashMM V364 本轮说明

发布日期：2026-07-20

## 本轮结果

- 桌面端新增任务级敏感操作确认中心，Browser Use、Computer Use、检查点、浏览器导航、危险工作区和软件更新的确认不再只依赖当前弹窗。
- 确认请求绑定稳定请求 ID、来源和不可变 `taskId`。用户切换 Chat 后，后台长任务的确认仍归属于原任务，不会错误显示成新 Chat 的操作。
- 右侧统一“运行”页现在显示所有待确认操作和当前 Chat 的最近确认历史；其他 Chat 的待办会标明来源，可重新打开详情处理。
- 关闭、Esc 或点遮罩只表示“稍后处理”，不会把长期任务误判成拒绝；只有明确按钮才提交决定。渲染器刷新后可重新呈现同一请求。
- 新增本机有界审批日志，使用临时文件加原子替换持久化，最多保留 300 条。应用异常退出后仍处于 pending 的旧请求会恢复为 `interrupted/cancel`，不会在重启后批准已经消失的操作。
- Computer Use 执行和评估截图都携带启动时捕获的任务 ID；即使用户同时切换会话，后续检查点和敏感动作也不会串到别的 Chat。
- 新 IPC 查询、呈现与检查点通道均纳入 sender 守卫，preload 只开放窄接口；未知决定、未知请求和渲染器不可用继续 fail-closed。

## Codex 参考边界

- 本轮只参考用户提供的解压源码 `D:/sheji/codex-main` 中可直接核对的机制：`pending_thread_approvals.rs` 的跨线程待确认列表、`approval_overlay.rs` 的队列与线程归属、`history_cell/approvals.rs` 的历史记录呈现。
- HashMM 按自身 Electron、Chat 和长任务架构重新实现，没有复制 Codex 私有服务，也没有声称视觉或未公开能力完全一致。
- 官方在线手册在本轮运行环境中连接失败，因此没有使用无法验证的在线描述补齐结论。

## 明确限制

- 本机审批日志用于恢复可见性和审计，不会在应用重启后恢复已经消失的 Electron 回调；这类请求会安全标记为中断，用户需从原任务重新发起。
- 安装器尚未配置 Authenticode 发布者证书。SHA-256 证明文件完整性，但不等价于发布者身份签名。
