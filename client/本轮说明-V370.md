# HashMM V370 本轮说明

## 本轮目标

把 Graph Engineering 从独立知识图谱页面推进为贯穿 Chat、长任务、多 Agent、产物、验证、桌面端和 App 的真实任务协议。图只连接可验证的运行事实，不让模型文本、界面卡片或节点数量冒充完成证据。

## 任务证据图

- 新增 `hashmm.task-evidence-graph.v1`。一张图统一表达目标、完成标准、执行范围、来源、主张、工具调用、Agent、Artifact 和确定性检查。
- 所有边都由运行清单中的结构化事实生成；模型推断边固定为 0。工具参数只保存指纹，不复制原始参数、账号数据、密钥或用户文件内容。
- 未引用主张、失败或未授权工具、失败 Agent、缺失 Artifact 和未通过检查会生成阻塞项与可执行下一步。
- 图有节点和边的硬上限，旧运行清单缺图时如实计入 `missing_graph_runs`，不补造历史。

## Chat、长对话与 RAG

- Assistant 运行清单持久化同一任务证据图；下一轮只能通过显式的不可信数据边界读取图摘要，不能扩大权限或覆盖用户的新指令。
- 只有“继续/继续做”等准确短续写会把上一轮目标和阻塞节点补入检索查询；新的具体问题始终使用本轮用户输入，不被旧任务劫持。
- 检索仍沿用候选、证据、可引用来源、重排、权限过滤和图扩展契约；任务图只连接已有证据，不创造来源。

## 长任务与多 Agent

- 持久循环每轮依据真实 attempt、工具结果、产物和检查重建任务图，并把阻塞项反馈给下一轮；恢复旧循环时不重放工具。
- 多 Agent 的角色状态、共享来源、主张台账、画布产物和验收结果汇入同一图；停止、失败和成功都写回当前 Chat 的运行清单。
- 子 Agent 继续继承更窄的用户、会话、工具和联网范围；证据图不参与授权决策，不成为权限旁路。

## 桌面端与 App

- 桌面端统一上下文的“证据/运行”页展示实际图 ID、状态、节点、边、阻塞、主张证据覆盖和下一步，并可把精确续做指令放回当前 Chat。
- 长任务页展示当前循环的图闭环状态；质量看板展示图追踪覆盖、阻塞运行、未清阻塞、主张证据连接和完整性违规，明确图密度不是质量分。
- App 的对话完成卡、长任务、多 Agent 和质量页读取同一服务端协议；没有服务端数据时不显示演示状态。

## 严格边界

- 任务图用于可观察性、续做和验收反馈，不是访问控制器，也不是模型答案正确性的证明。
- 主张证据覆盖率只统计显式 `source -> claim` 连接；没有引用的回答不会因为节点很多而得到高分。
- Authenticode 发布者身份、真实外部 MCP/浏览器站点行为和生产 Supabase 数据仍需在对应生产环境独立验证。
