# HashMM V700 本轮说明

## 结论

本轮收口的是 Chat 核心，不是继续堆叠独立页面。项目、插件、自动任务、知识检索和长任务都回到同一条用户工作链：

`账号隔离的项目/最近对话 → 受控资料范围 → 可中断 Agent 执行 → 公开过程与证据 → 可恢复交付`

任何“已执行、已验证、已完成”状态都必须来自服务端状态、工具回执或确定性检查；模型文字和隐藏思维过程不作为证据。

## 已完成

### 1. 项目与最近对话

- 项目内对话只出现在所属项目下，未绑定项目的对话进入“最近”。
- 每个项目条目都有独立的“新建项目对话”入口；新对话在创建时原子绑定项目，同一项目可以持续拥有多条对话，不会覆盖已有 Chat。
- Chat 输入框的文件与文件夹附件改为“先持久化、后进入消息”：新会话先由服务端创建，再上传真实文件并保存真实下载地址；只有整个持久化步骤成功后才清空草稿。上传失败会保留文字与附件供用户重试，不再生成并不存在的 `/api/files/...` 占位链接。
- 选择了项目但当前 Chat 尚未归类时，发送前通过 owner-scoped API 原子绑定项目；服务端写入失败不会用本地状态伪装成功。
- 文件夹选择保留相对路径语义，并生成安全、可重复的扁平上传名；批量上传受文件数量、总体积和并发上限约束。
- 项目绑定为 owner-scoped 原子写操作；不存在、无权限和跨账号对象不会被客户端本地状态掩盖。
- 项目下的对话支持继续、重命名、归档和删除，并复用普通 Chat 的同一数据模型。
- 本地投影按账号隔离；切换账号不会清空其他账号的本地记录，也不会把记录暴露给当前账号。

### 2. 长任务停止与恢复

- 停止按钮等待服务端确认，再结束本地活动状态。
- 中断后主动重新读取活动 turn，解决网络重试和迟到事件导致的界面/后端状态分裂。
- 重复停止保持幂等。
- 运行清单保存可公开步骤、任务清单、工具结果摘要与恢复状态；每份清单携带稳定 `manifest_id` 和单调递增 `revision`，重连或迟到事件不能用旧版本覆盖新进度。
- 停止后保存已产生的部分正文、公开时间线和任务清单；客户端短轮询服务端活动 turn 做最终对账，避免“按钮已停、后端仍跑”或停止按钮无反馈。
- 客户端将内部协议事件折叠为面向用户的公共任务时间线；旧消息重新打开时也会经过相同归一化，不再显示 `turn_admitted`、`context_assembled` 等原始协议噪声。
- 不持久化供应商原始 reasoning、隐藏 Chain of Thought 或模型内部推理文本。

### 3. 资料范围与 RAG

- 选中资料先与 owner 可访问集合求交，再进入预检索、Agent 工具检索和 SearchR1。
- 精确文档集合不会因旧检索桥接而扩大为全库检索。
- owner 信息缺失且无法证明授权时失败关闭。
- 查询改写和检索回退仍受同一资料边界约束。

### 4. 证据审计与日志

- 运行时状态、澄清问题、界面提示不再进入逐主张外部证据审计。
- 工具失败会以运行状态呈现，不再被包装成需要外部引用的事实主张。
- 高频心跳成功请求静默；异常响应仍保留日志，避免重要错误被轮询噪声覆盖。

### 5. 插件、自动任务与 Harness

- 插件和公众号工作入口继续返回 Chat，不创建第二套聊天系统。
- 自动任务保持 owner 隔离、可立即运行、可启停和回写原对话。
- “AI 公众号简报工作室”由服务端强制执行六阶段交付契约：五方向发现、打开原始来源核验、候选池分级、Markdown、公众号兼容 HTML、交付前自检与最终发布确认。
- 没有附件或显式资料范围时，公众号简报任务不会扫描整个私有资料库；Markdown 与 HTML 必须由真实文件工具创建，否则运行以“交付不完整”结束，不会把模型口头承诺伪装成成果。
- DeepSeek thinking 模式的多轮 continuation 会按供应商协议回传上一轮 `reasoning_content`；该字段只用于供应商请求连续性，不进入公共时间线或持久化消息正文。
- AgentLoop、通用 SSE 与旧 Handler 三条兼容链路统一经过公开进度投影：供应商原始 reasoning 与 `<think>` 内容不会进入 SSE、消息 thinking 字段或客户端状态；界面只显示固定的分析状态，以及可验证的清单、工具、审批、证据和交付事件。
- 长任务在普通迭代预算之外保留有界“交付收尾”预算；收尾阶段只允许更新清单、读取/修改已有文件和创建交付文件，不允许再次无限扩张联网检索或工具搜索。清单或双文件交付仍未满足时返回结构化 `delivery_incomplete`，不再以“接下来我会生成”冒充完成。
- 运行清单新增五阶段工作闭环：任务理解、受控执行、变更验证、可靠交付、经验沉淀。
- 五阶段状态只根据真实事件和验证结果投影；“代码里配置了某机制”不等于“本次运行使用并验证了该机制”。

## 协议与兼容性

- Backend：V700。
- Desktop/MCP/Native source：1.42.0。
- 工作协议保持 `hashmm.work-protocol.v3`：本轮新增运行清单的可选投影字段，对旧客户端向后兼容，没有改变既有动作、权限或错误语义。
- 数据库 schema 与 Android 版本未变化。

## 真实性边界

- 本地测试不能证明真实供应商配额、跨公网断线恢复、24 小时稳定性或第三方平台发布成功。
- Windows 安装器不得通过手工修改 `.release.json` 冒充新成品；只有完整运行 `installer-native/build-all.bat`、实算 SHA-256 与清单一致后才是可交付的 V700 安装器。
- 服务器 ZIP 不包含前端、桌面端、安装器、测试、用户数据、日志、模型、索引、私有 `.env` 或密钥文件。

## 验证

本节只记录在 V700 源码状态上实际执行的结果：

- 本轮新增 Agent 事件协议定向回归：15 项通过，覆盖 DeepSeek `reasoning_content` 连续性与公开投影隔离、公众号 Markdown/HTML 真实文件交付、缺失交付失败关闭，以及任务清单稳定 ID/单调 revision。
- 前端全量：51 个测试文件、192 项通过；包含附件上传顺序、项目绑定顺序、草稿清空时机、文件夹名净化和迟到任务清单拒绝回归。
- 前端 TypeScript 检查：通过。
- 前端生产构建：通过。
- 桌面 Node：71 个测试脚本全部通过。
- 桌面发布源码门禁：通过，确认 Desktop 1.42.0、Backend V700、运行时与 WebUI 来源一致。
- 当前 Windows 系统 Python 未安装 `fastapi`，因此本轮无法重新收集后端全量测试；未用已打包桌面运行时临时安装 pytest，也未把此前 V700 的全量结果冒充为本轮结果。受影响范围已由上述定向回归、语法编译、前端全量、桌面全量与发布源门禁覆盖，服务器部署环境仍应补跑 `python -m pytest -q tests`。
- 服务器包必须由 `scripts/package-server.ps1` 从最终源码状态生成；成品名称、大小、条目审计与实算 SHA-256 记录在交付说明及同名 `.sha256` 旁置文件中，不把会随源码变化而失效的成品哈希写回源码。
