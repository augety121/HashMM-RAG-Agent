# HashMM V1400 本轮说明

日期：2026-08-10  
主题：多账号远程真值、Android 个人 API 与原生安装升级闭环

## 现场根因

1. `/api/dispatch/runners/heartbeat` 在 Cloudflare 转发期间读取 JSON 请求体，客户端先断开时 Starlette 抛出 `ClientDisconnect`，全局异常处理又把它记为 500。
2. 桌面端此前只要账号远程隐藏窗口存在就返回 `on=true`；它没有证明 WebSocket 已认证并注册，因此同账号 App 可能看不到电脑。
3. Android 模型页请求 `/api/admin/models*`，导致管理员可用、普通账号固定 403；个人模型后端路由其实已经存在但 App 没有使用。
4. App 旧手动地址优先级高于 Supabase 同步地址，曾保存的校园网 HTTP IP 会永久遮住新的 HTTPS Tunnel。
5. 原生安装器丢弃已安装版本字段，外层单文件 EXE 也没有随发行更新的 Windows VERSIONINFO，所以升级包仍表现为“重新安装”且资源管理器版本不变。

## 实施结果

- 心跳支持 query presence 和旧 JSON 两种请求；新桌面不再发送 body。断连按 499 分类，只记录简短信息日志。
- 远程 host 将 `connecting/authenticating/registered/rejected/disconnected` 回传主进程；状态接口显式返回 `registered`，前端不再把窗口存活当在线。
- 任务 runner 与远程 host 复用相同稳定 device ID；服务端 `/api/remote/status` 按 owner 合并 dispatch/remote 能力。
- App 模型页切换为普通用户接口并新增“我的 API 与模型”入口；`direct_llm` 云端密钥同步彻底移除，个人密钥只通过认证后的 owner-scoped 后端保存。
- 默认后端为 `https://hashmm.hashlens.org`；只清理已知旧地址 `http://111.115.7.14:20014`，不覆盖用户选择的其他服务器。
- 安装器比较安装标记版本与当前包版本，区分升级、同版修复和防降级；内层 Qt EXE 与外层 SFX 共用 CMake 生成的版本资源。

## 安全边界

- 未放宽 Supabase 认证、owner 校验、HTTPS 门、CORS 或代理信任。
- 远程注册状态不授予权限；每次控制会话仍走独立审批和作用域。
- API Key 不写入 `app_config`、日志、测试夹具或客户端明文 DataStore。
- SHA-256 只证明文件完整性；公开发布的开发者身份仍需要 Authenticode 证书。
