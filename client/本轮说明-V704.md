# HashMM V704 本轮说明

## 本轮解决的问题

V704 把上一轮已经完成一部分的 Chat 改造继续收口为可运行、可恢复、可审计的服务端能力：

1. 上传文件无法直接提取正文时，不再只返回一次性的 `needs_ocr`。服务端创建 owner-scoped 持久化 OCR 作业，后台领取、重试、退避并保存结果；进程异常后可回收超时租约。
2. 等待审批的 AgentLoop 在暂停前保存安全检查点；WorkRun 统一投影任务状态并公开检查点列表，使界面和恢复入口读取同一份服务端事实。
3. 论文复现 Harness 增加 L0–L3 确定性门禁，分别检查契约、重放、故障终态和证据闭环；缺少执行证据不能被标记为完成。
4. 右侧任务面板显示统一任务状态和检查点数量；OCR 失败可在原 Chat 中查看状态并重试，不建立第二套任务系统。
5. 服务器发布包新增逐文件 SHA-256 清单与打包后审计，明确证明关键 V704 能力已进入 ZIP，并拒绝重复条目、路径穿越、重解析点、桌面端、测试、用户数据、密钥和旧归档。

## 从 Codex 工作方式继承的约束

- Chat 是主要工作入口，项目只提供上下文和归属；任务面板、附件、审批、自动任务与成果都回到同一 Chat 事实源。
- 长任务持久化目标、约束、公开计划、行动、证据、审批、检查点、未完成步骤和交付状态。
- 不保存或展示模型隐藏思维链、供应商原始 reasoning 或 `<think>`；用户看到的是可核验的公开任务链。
- 模型文字不是执行证据。文件、命令、测试、外部事实与完成状态必须由工具回执或确定性验证支持。
- 缺少权限、附件、OCR、验证或成果时保持明确的可恢复状态，不提前写成“已完成”。

## 版本与兼容性

- Backend：V704。
- Desktop/MCP/Native source：1.42.4。
- 工作协议仍为 `hashmm.work-protocol.v3`；新增字段均为向后兼容的可选投影。
- 数据库在现有迁移路径上新增 `ocr_jobs` 与 `run_checkpoints`，不要求删除旧数据。
- 旧 V702 Windows 安装器及其 `.release.json` 保留原样。本轮没有运行完整原生安装器流水线，因此不会把旧 EXE 冒充为 V704 成品。

## 服务器包验收口径

- 必须包含 OCR 路由与队列、统一任务状态、Harness L0–L3 和 AI 新闻雷达插件。
- 必须包含 `SERVER-PACKAGE.txt` 与 `SERVER-PACKAGE.json`；JSON 清单记录每个源码文件的相对路径、字节数和 SHA-256。
- ZIP 中不得出现重复条目、路径穿越、前端/桌面/安装器/测试目录、用户数据、日志、模型、索引、数据库、私钥或旧归档。
- 最终 ZIP 另附独立 `.sha256`，交付前重新计算并与 sidecar 比对。

## 仍然诚实保留的边界

- 检查点已经持久化等待审批前的安全恢复事实，但服务进程在模型流式生成中途崩溃后，不能从供应商内部 token 位置无损续写；恢复从最后一个安全检查点重新进入。
- OCR 的真实识别质量仍取决于部署环境中安装的解析/OCR 能力；队列、重试和状态恢复不等于自动获得新的 OCR 引擎。
- 真实公网模型额度、浏览器站点、第三方搜索、微信公众号发布和多机故障切换仍需部署环境验收。
