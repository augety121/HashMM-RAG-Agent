# 本轮说明：HashMM V2500 / Evidence Workbench 5.0

本轮完成了 Provider Fabric、Chat 专注/能力感知、统一插件能力清单、Team Run 任务契约和 Canvas 增量操作日志的首个生产闭环。

## 已落地

- 新增账号隔离的 `/api/provider-fabric`：连接、加密凭据、模型通道、健康样本、熔断状态、租约、尝试与用量表；支持官方 API、获授权 Sub2API、兼容网关和显式本地运行时。
- Provider 列表不返回密钥；公网 URL 强制 HTTPS 并执行 SSRF 拒绝；检查连接前再次解析 DNS；用户需明确点击“用于 Chat”才改变模型偏好。
- 普通用户控制台新增 Provider Fabric 工作区，可添加、检查、激活和删除连接。
- Chat 工具入口读取服务端真实能力清单；不可执行的浏览器、电脑、Canvas 和多 Agent 不再只因本地开关打开而显示。
- Chat 新增专注模式：压缩过程活动但保留右侧证据与完整运行轨迹。
- 插件清单统一加入 skills、connectors、hooks、UI、scheduled tasks 与兼容性，并输出稳定生命周期状态。
- Team Run 保存 `hashmm.agent-task.v1`；写入型 Team 必须绑定受管工作区，工具权限取契约白名单交集。
- Canvas 新增 revision/op_id 幂等操作日志和 SHA-256 快照回执，陈旧写入返回冲突。

## 尚需真实环境验收

- 外部 Sub2API/官方模型的账号权限、费率、配额、限流和公网稳定性必须使用用户自己的已授权账号验证。
- 跨 Base URL 加权路由和多 API 实例共享租约需要 Redis/Postgres 生产部署；当前单服务实例的持久控制面与显式 Chat 激活已经可用。
- Python 插件仍是精确摘要子进程隔离而非 OS 沙箱；Canvas 操作日志是单账号多设备顺序合并，不是多人 CRDT。
- Windows EXE 已通过完整原生构建和三方 SHA-256 校验，但尚未配置 Authenticode 发行者签名；SHA-256 证明完整性，不代表发行者身份。
