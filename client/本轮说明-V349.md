# HashMM V349 本轮说明

日期：2026-07-19

## 本轮目标

本轮以《大模型应用!算法学习路线+八股+面试实战4.md》的评估驱动开发方法为主参考，不停留在增加一个“点赞/点踩按钮”，而是把线上真实失败接成可审计、可人工复核、可进入回归集的质量闭环。资料中对应的关键方法包括：先定义成功标准；分别评测 RAG、工具调用和规划等组件；再做任务结果与轨迹集成评测；线上发现的新问题回灌评测集；MCP/工具接口使用最小而严格的 Schema、结构化输出、明确错误和 Human-in-the-loop。

## 已完成的真实链路

1. Chat 消息反馈不再信任客户端提交的问题和答案。后端根据用户、会话和消息的属主关系，从服务端消息记录读取用户问题、助手答案、来源、groundings、工具调用、运行清单和 Token，生成 `hashmm.feedback-case.v1`。
2. 负反馈必须选择明确失败类型：事实错误、证据不足、检索遗漏、工具错误、任务未完成、指令偏离、安全风险、响应过慢或其他；可附加说明。正反馈和撤销也走同一条服务端链路。
3. 负反馈只进入 `pending` 候选，不会把失败答案自动当成 Golden。管理员必须填写人工核验后的可信参考答案，才会生成 `split=heldout` 的回归用例；失败答案仅作诊断证据。
4. 复核过程增加数据库原子认领和过期恢复。两个管理员同时处理同一候选时只有一个能继续；写入评测集失败会释放认领，避免重复、覆盖和假成功。
5. Desktop Chat 接入结构化反馈面板；管理后台质量评测页接入真实候选列表、失败证据、可信参考答案、驳回和加入回归集操作，并提供真实空状态。
6. App 首页 Chat 与详情 Chat 使用同一接口、同一失败分类和同一服务端消息状态。手机直连模型没有服务端权威运行证据，因此有意隐藏反馈入口，不伪造已进入质量闭环。
7. 旧的按消息序号反馈接口继续兼容，但客户端传入的 query/message_content 已不再被采信，关闭了通过旧客户端污染学习数据的路径。

## 数据、接口与权限

- SQLite schema 升级到 15，新增 `message_feedback_cases`、复核状态和索引；启动时自动迁移。
- 用户接口：`POST /api/conversations/{conv_id}/messages/{message_id}/review`。
- 管理员接口：`GET /api/admin/eval/feedback-candidates`、`POST /api/admin/eval/feedback-candidates/{candidate_id}`。
- 会话和消息必须属于当前用户；不存在与无权限对象统一按不可枚举方式处理。管理员复核接口只接受服务端管理员身份。
- 线上失败、上传文件、工具输出和模型文本均不是可信标准答案。只有人工填写的参考答案可进入 held-out 集。

## 明确限制

- 本轮服务器包按部署用途排除了 `frontend-next`、`desktop`、`installer-native`、测试、本地数据、模型、索引和旧压缩包；桌面端源码已完成并验证，但没有在本轮重新生成正式 Native EXE。
