# HashMM V366 本轮说明

## 目标

把“支持多家模型”从界面文案变成运行时协议能力，并把 App 的动态和工作台从桌面功能索引改为面向用户的移动任务入口。

## 已完成

- 后端统一厂商策略、端点校验、协议选择、能力声明、参数隔离和错误归类。
- OpenAI Responses 原生适配到 HashMM AgentLoop 的文本、流式和工具调用契约。
- 管理员与个人模型创建均保存 `wire_api`，桌面端与 App 使用同一注册表。
- 桌面端模型管理不再猜测账号可用模型。
- App 动态任务卡、工作摘要、渐进式治理入口和多厂商模型底部表单均为原生 Compose，并接真实接口。

## 安全与兼容

- 现有模型默认协议不变；新协议必须显式选择。
- 远程模型只允许 HTTPS，本机 loopback 模型可使用 HTTP。
- 厂商扩展参数不能覆盖模型、消息、工具、token 上限等核心请求字段。
- API Key 不写入日志或厂商清单；客户端缓存键使用不可逆 SHA-256 指纹。

## 明确限制

- 厂商策略覆盖的是公开协议形态和端点规则，不承诺某个账号已开通任何具体模型；模型或部署 ID 必须以对应控制台为准，HashMM 不伪造“可用模型”列表。
- OpenAI Responses、Chat Completions 与 Anthropic Messages 已进入统一 AgentLoop；厂商私有、非兼容参数仍需通过受控扩展字段显式配置，且不能覆盖核心请求字段。
- Windows 安装器当前 Authenticode 状态为 `NotSigned`。SHA-256 能证明产物完整性，但不能代替发布者身份签名，公开分发前仍应配置代码签名证书。
