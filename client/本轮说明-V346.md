# HashMM V346 本轮说明

日期：2026-07-18

## 本轮完成

- 蒸馏 `Desktop/121/1.docx` 至 `7.docx` 中可复用的任务完成方法，明确排除旧项目事实、秘密信息和未经验证的历史结论。方法说明见 `docs/FABLE5-TASK-METHOD-DISTILLATION-V346.md`。
- 新增任务契约与完成交接：复杂 Chat 在执行前公开原始目标、完成条件和计划边界，执行后由外部确定性检查给出 `checks_passed`、`delivered_with_limits`、`needs_attention` 或 `blocked`。
- 对照 OpenAI 官方 Codex app-server 的稳定 turn/item 生命周期、计划状态和中断终态，为 HashMM 契约补入稳定 `run_id`，保留步骤 ID，并把客户端断开落为 `interrupted`。
- Desktop 的 Chat 与统一右栏接收 `task_contract`，展示实时契约和最终 handoff；没有运行证据时不会显示“已通过”。
- App 首页与详情 Chat 统一改用 `LiveChatManager`；任务切页后继续运行，任务目标、待办、进度和步骤数可见，结束后从 `run_manifest` 显示完成检查。
- App 历史消息模型补齐 `groundings`、`run_manifest`、tool calls、files、sources、suggestions 和 tokens，Supabase 与桌面端保存的同一条消息不再在 App 端降级。
- App 停止按钮同时取消应用级协程与真实 OkHttp transport，覆盖后端服务模式和手机直连模型模式；空占位删除、部分输出保留为未完成，不能再把手动中断显示成完成。
- 后端普通直答从“完整收集后再返回”改为逐事件队列；客户端断开会停止同步 provider 迭代、跳过质量后处理和文件生成，并把部分回答保存为 `interrupted`。

## 部署注意

- 服务器与 App 必须同时升级，App 才能显示 V346 的完整任务契约和完成证据；旧服务端仍可回答，但不会产生这些新语义事件。
- `delivered_with_limits` 表示已交付但存在无法由运行时自动核验的内容，不等价于事实正确；用户仍应复核高风险结论。
- 本轮只更新 Windows 桌面发布源版本到 1.17.2，没有重新构建原生安装器 EXE；正式发布仍需运行 `installer-native/build-all.bat` 并核对 EXE、`.sha256` 和 `.release.json`。
