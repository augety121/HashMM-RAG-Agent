# HashMM V374 本轮说明

## 本轮结果

这轮把 V373 的“统一可观察运行”继续向下做成真实控制面。Chat、桌面右栏和 App 不再只显示长任务状态，而是由服务端根据执行器和当前 revision 发布真实可用动作，并统一处理暂停、继续、停止和重新派发。

核心协议为：

- `hashmm.work-control.v1`：当前 revision、可用动作和副作用边界；
- `hashmm.work-command.v1`：账号绑定的命令 ID、期望 revision、执行状态和有界结果；
- SQLite schema 17 的 `work_commands`：先持久化认领，再进行本地分派。

## 真正接通的执行器

- Loop：运行/排队时可暂停或停止；阻塞时可从原检查点继续。恢复不扩大原任务权限和范围。
- 多 Agent：运行时协作式停止；当前模型调用返回后丢弃未授权输出。终态重试创建一个新的关联 Team/Work Run，旧记录不覆盖。
- Browser Use、Computer Use、取文件：只在 `file_requests.status='pending'` 时原子取消。桌面端已经领取后返回冲突，不伪装成取消成功。
- 普通 Chat、Artifact 和没有控制执行器的 Workflow：保持只读，不显示摆设按钮。

命令以 `(owner, run_id, command_id, expected_revision)` 约束。重复命令只返回第一次结果；陈旧页面被 revision 冲突拒绝；缺失与其他用户对象统一不可枚举。进程中断导致命令结果不确定时，读取投影为 `uncertain`，系统不会自动重放外部副作用。

## 桌面端与 App

- 桌面右侧“运行”显示状态版本、执行器边界、动态动作、忙碌/错误以及断线待确认提示。操作结果立即替换同一运行和事件，失败后重新读取服务端事实。
- App 原生“运行轨迹”使用同一协议；命令 UUID 只生成一次，不在网络歧义时偷偷重试。服务端返回的运行与事件写回账号隔离加密缓存，并清除明细 ETag 后重新校验。
- 两端都不根据文案猜测任务能力，也不会在后端不支持时显示控制按钮。

## 设计参考与不等同声明

- Codex 的长期任务和 app-server 机制把 resume、interrupt、状态变化与权限边界做成明确协议；HashMM 借鉴的是“控制必须是运行事实，而不是模型文案”。官方参考：<https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md>。
- Claude Code 的 checkpoint/session 文档明确指出文件编辑检查点不覆盖 Bash、外部数据库和外部 API 副作用；subagent 的工具与权限也需要收窄。HashMM 因此没有提供一个名不副实的“全部回滚”按钮。官方参考：<https://code.claude.com/docs/en/checkpointing>、<https://code.claude.com/docs/en/sessions>、<https://code.claude.com/docs/en/sub-agents>。
- HashMM 本轮实现是基于自身 Python、SQLite、Electron 与 Android 架构的独立适配，不声称复制、等同或兼容 Codex/Claude Code 的未公开内部实现。

## 已知边界

- “命令幂等”保证恰好一次接纳与至多一次本地分派，不等价于外部 API 恰好执行一次；要获得更强保证，需要外部服务也接受同一幂等键。
- 多 Agent 当前模型调用无法安全硬杀，只能请求停止并在调用返回后丢弃结果。
- Browser/Computer 请求被桌面端领取后不能伪装为已撤销；后续要实现强终止，需要桌面执行器提供逐步检查点和各工具自己的补偿语义。
- Windows 安装器当前 `Authenticode` 状态仍为 `NotSigned`。SHA-256 证明完整性，不代表发布者身份；公开发布前仍应配置代码签名证书。
