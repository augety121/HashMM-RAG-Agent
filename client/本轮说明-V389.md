# HashMM V389 本轮说明

日期：2026-07-22

## 结果

本轮继续按“页面展示必须对应真实能力、写操作必须取得可核对回执、读取失败不能伪装成空数据”的标准检查桌面端、后端与 Android App，并修复了一个会直接导致管理后台模板创建失败的真实断点。

提示词模板接口原来调用了数据库中不存在的 `save_template` 方法；现在创建使用实际数据库契约并返回模板 ID 与对象回执。编辑改为原地 `PATCH`，不再先删除旧模板再创建，因此更新失败不会丢失旧模板，模板 ID、创建时间、作者和使用次数也会保留。模板名称、正文、分类、变量和对象 ID 均增加有界校验，创建、更新、删除和使用都要求管理员身份，缺失对象不会被报告为成功。

管理后台的工具、技能、自定义 API 工具和 MCP 页面统一为真实回执状态。批量工具开关逐项等待服务端结果，只更新成功项，失败项保留原状态；列表读取失败保留最近一次已验证数据，从未成功读取时显示不可验证状态，不再用空数组渲染“暂无数据”。保存、刷新、删除、反馈等动作均有忙碌、错误和最近验证时间，网络失败不会自动清空编辑内容或关闭窗口。

Android 动态页把实时工作、用量、动态流、能力和订阅状态拆成独立来源并监督式并行刷新。单一来源异常不会取消其余请求或让首屏一直加载；零请求和零 token 是合法的已验证快照；刷新失败时保留上一份成功结果，并明确显示失败来源而不是把旧值包装成本次成功。

完整审计、已修问题与仍需继续深化的边界见 `docs/code-audit-V389.md`。

## 明确限制

- 本轮没有生成新的 Windows 正式安装程序。源码发布闸门通过不等于 EXE 发布完成；正式版本仍须执行 `installer-native/build-all.bat`，并核对 EXE、`.sha256` 与 `.release.json` 三方一致。
- APK 是 debug-signed 测试包，不是应用商店正式签名包。
- 文档重解析后端目前仍会在新索引完全建成前删除旧 chunks、索引和知识图谱。界面已经如实显示结果，但新一轮仍应实现“新代预构建、验证、原子切换、失败回滚”和持久 job receipt，才能消除数据重建窗口。
- `EvalPanel` 的部分初始读取、较早的 Artifact 锁兼容分支以及部分 App Repository 仍需迁移到统一的加载、真实空态、缓存旧值、权限错误和网络错误协议；本轮审计没有把未改区域宣称为已完成。
- SHA-256 只能证明交付字节一致，不能代替 Authenticode 发布者身份，也不能证明外部文件内容可信；网页、上传文件、命令输出和仓库差异仍按不可信数据处理。
