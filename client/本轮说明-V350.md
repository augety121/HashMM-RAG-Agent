# HashMM V350 本轮说明

日期：2026-07-19

## 本轮依据与目标

本轮继续以《大模型应用!算法学习路线+八股+面试实战4.md》为主参考，落实其中 3.3.3.3“工具调用评测”和 3.3.4.2“轨迹评测”的要求：不能只看最终回答，也不能只检查“参数字段存在”；必须分别判断工具选择、必填参数、参数值、多余臆造参数、调用顺序和“不该调用工具”的反例。同时遵循资料中的口径边界：内置业务用例用于项目回归，只有官方 BFCL 数据与官方判分脚本产生的结果才允许参与公开榜单比较。

## 已完成的真实能力

1. 新增无副作用、可复现的统一判分协议 `hashmm.tool-call-eval.v1`。判分器只读取期望调用、实际调用和工具 Schema，不执行工具，不信任模型自评分。
2. 判分维度统一为：工具选择、必填参数、参数值、多余参数、调用顺序和不调用克制；失败项输出稳定错误分类与具体调用位置。
3. 参数规则支持精确值、包含、候选集合和正则；工具 Schema 可声明 required、properties 和 additionalProperties，未声明参数默认判为臆造参数。
4. 三条原本口径不一致的路径已共用同一个判分器：内置工具调用基准、Agent 工具决策套件、深度质量工具套件。Agent 轨迹的 `match_args=True` 也改为严格键集合匹配，不再放过额外臆造参数。
5. 内置工具基准仍明确标记为 `builtin`、不可与 leaderboard 比较；逐题结果现在保留期望工具、实际工具、维度分和失败分类，方便定位而不是只给总分。
6. 线上质量大盘新增服务端权威运行清单聚合：可评估工具运行、工具调用数、失败调用数、执行成功率、失败运行数和人工标记“工具错误”的反馈数。
7. 线上“执行成功率”明确不是“工具选择正确率”。选择、参数和顺序只能由有标准答案的严格离线评测或人工复核判断，页面不会把工具返回成功伪装成 Agent 决策正确。
8. Desktop 管理后台质量页和 App 原生质量看板读取同一个 `/api/admin/quality/dashboard` 响应。没有 RAG 样本或工具运行时保留“不可评估”，不填演示分数；发现工具失败或人工工具错误反馈时直接进入复核状态。

## 统计与安全边界

- 线上工具指标来自持久化 `hashmm.run-manifest.v2` 的确定性 `tool_execution` 检查，不从模型正文猜测执行状态。
- 质量大盘最多读取最近 10000 条运行清单，达到上限会返回 `truncated=true`，Desktop/App 均提示统计范围。
- 人工“工具错误”只统计 V349 结构化负反馈中仍待复核、复核中或已批准的记录。
- 严格离线判分不会真实执行 shell、文件、浏览器或联网副作用；工具实现本身是否正确仍由单元/集成测试验证。

## 明确限制

- 内置 10 题工具集只是项目回归红线，不是官方 BFCL，不得用它声称超过 Claude Code、Codex 或其他产品。安装官方 BFCL 数据与判分器后才进入可比口径。
- 线上运行清单只能证明工具返回状态，无法凭空知道模型是否选对工具；这正是严格离线金标用例和 V349 人工反馈闭环存在的原因。
- App 质量看板需要管理员登录并连接 backend V350；手机直连模型没有中心运行清单，不能产生这组权威指标。
- 服务器 ZIP 按部署用途排除了 `frontend-next`、`desktop`、`installer-native`、测试、本地数据、模型和索引。桌面端源码已构建验证，本轮没有重新生成正式签名 Native EXE；APK 为 debug 构建。
