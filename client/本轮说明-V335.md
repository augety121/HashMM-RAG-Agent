# 本轮说明 · V335（2026-07-16）—— 可恢复长任务与证据型 Agent

这一轮不是给旧“循环工程”换名字，而是替换其执行内核。V334 之前的 `/goal` 只会反复调用
模型生成文本，再让同一模型评分；它不会进入 HashMM 的 ReAct 工具链，进程重启后也不会加载
快照。结果是任务可能声称“已检查、已修改”，但没有真实工具证据，也无法成为类似 Codex 的
长时间工作任务。

## 已完成

### 1. 目标循环接入真实 AgentLoop

- 每轮经 `hashmm.agent.loop.AgentLoop` 执行，能使用 RAG、记忆、文件、搜索和经授权的工具。
- 每轮记录工具名、状态、耗时、生成文件、运行轨迹与模型返回的 usage。
- 不持久化工具参数和完整工具输出，避免把密钥或大段不可信内容复制进任务快照。
- 目标、验收条件与上一轮独立反馈始终重新注入，长任务不会只记得最近一步。

### 2. 证据型验收，阻止“模型说完成就算完成”

- 评估器只能根据候选产出和实际工具/文件轨迹评分。
- “检查、核实、测试、最新、报告、代码”等任务如果没有工具证据，分数确定性封顶 60，不能达标。
- 写入型目标在工作区模式下没有写工具或文件证据时不能通过。
- 评估输出解析失败按 0 分处理；不会用模糊文本猜一个及格分。
- UI 同时展示分数和“证据通过/不足”，避免把 LLM judge 分数伪装成客观真值。

### 3. 持久化、暂停与恢复

- 每次状态迁移写入 `data/agent-loops.json`，采用同目录临时文件、`fsync`、原子替换；旧
  `loops.json` 可一次性迁移。
- 支持 `queued/running/paused/done/fail/stopped`，并新增详情、暂停、继续、停止接口。
- 只读任务在服务重启后自动继续；可能写入的任务恢复为“已暂停”，必须由用户确认继续，避免
  崩溃发生在副作用落地后又自动重放。
- 轮次、历史、Token、活跃耗时、下次定时运行时间和停止原因都会恢复。

### 4. 权限与预算

- 每个任务绑定不可变用户 uid；列表、详情、暂停、恢复和停止都做对象级权限校验。
- 任务若绑定 `conv_id`，创建前必须再通过会话所有权检查，不能把后台工具指向他人的会话工作区。
- 未授权与不存在统一返回 404，避免用任务 ID 探测他人任务。
- 默认“只读安全”模式只保留明确标注 `read_only` 的工具；未知 MCP/自定义工具不会被猜成只读。
- “工作区写入”是显式授权，仍受 HashMM 原有 PermissionSystem 的系统/删除/高风险参数闸约束。
- 每个目标任务有独立最大轮数、Token 与活跃时间预算；Token 口径明确标注为
  “Agent usage 实测 + judge 保守估算”，不伪称账单级精确。

### 5. 桌面端

- “循环工程”升级为“可恢复长任务”。
- 可设置原始目标、可验收条件、最大轮数、分钟预算、Token 预算和授权模式。
- 列表展示运行状态、证据状态、工具轨迹、文件、停止原因和预算使用量。
- 支持暂停、从保存进度继续、停止；重启恢复的写任务有明确警示。

### 6. 用户实际启动入口

- 项目内 `hashmm-start.sh`、`scripts/hashmm_launcher.py` 与用户指定的
  `D:\edge downloads\start-hashmm1.sh` 已同步标记 V335。
- 启动诊断最低后端版本提升为 V335，避免把旧后端误认为已经具备本轮长任务安全边界。

## 新增 API

- `GET /api/loops`：当前用户任务（管理员可审计全部）。
- `GET /api/loops/{id}`：任务详情。
- `POST /api/loops/goal`：创建证据型目标任务。
- `POST /api/loops/interval`：创建可恢复定时任务。
- `POST /api/loops/{id}/pause`：暂停并保存进度。
- `POST /api/loops/{id}/resume`：从保存进度继续。
- `POST /api/loops/{id}/stop`：终止任务。

## 为什么这样对标，而不是照抄宣传文案

- NousResearch Hermes Agent 的官方仓库把持久记忆、可复用 skills、定时自动化和后台任务列为
  agent 的核心闭环；V335 先补 HashMM 最缺的“后台任务可执行、可恢复、可审计”。
- OpenAI 的 Codex 长任务资料强调长时间运行与上下文压缩；HashMM 复用已有 AgentLoop 的目标锚、
  上下文压缩和工具安全边界，而不是再造一条只会写文本的旁路。
- 官方安全说明也明确：批准启发式规则不是隔离边界。因此 V335 默认只读，写任务重启后不自动
  重放；这比“全自动恢复一切”慢一步，但不会拿用户数据赌幂等性。

## 仍然存在的边界（不做虚假承诺）

- 当前持久调度器针对桌面版单 API 进程；多副本服务器部署仍需 PostgreSQL/Redis 队列、租约和
  fencing token，不能让两个进程同时恢复同一任务。
- 暂停发生在 Agent 事件边界；已经进入的单次模型请求或同步工具调用不能被硬中断，只能在它返回后
  丢弃该代结果。下一阶段应给执行器增加可取消子进程与每工具 deadline。
- LLM judge 不是数学证明。V335 用确定性证据闸阻止最危险的空口达标，但代码任务仍应把项目测试、
  schema 校验和文件哈希等确定性 verifier 接成按任务类型选择的验收器。
- 安装包的 SHA-256 只能校验完整性。公开分发仍需用户自己的 Authenticode 证书；没有证书时流水线
  会继续明确标记为未签名内部包，不能宣称已完成发布者身份认证。
