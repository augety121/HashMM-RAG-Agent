# HashMM V358 本轮说明

日期：2026-07-19  
版本：Backend `V358`，Desktop / MCP / Native `1.17.14`，App `1.10.62`（versionCode `103`）

## 本轮结果

1. 长对话不再只依赖最近 80 条消息。服务端为每个会话维护持久化压缩检查点，把早期目标、显式约束、阶段要求、已报告进度和文件线索折叠为可继续工作的结构化上下文，同时保留最近对话原文。
2. 压缩检查点是派生数据，完整消息不会被删除。检查点跨进程重启保存，并按消息游标增量推进；回退、截断、删除或云端导入会失效并重建，避免旧摘要污染新分支。
3. AgentLoop、TokenBudgetBuilder、直接流式路径和右侧“上下文 → 系统”统一消费同一个检查点。运行轨迹会显示折叠消息数量、估算工作 Token 和“完整原文未删除”，不再把模型摘要当作执行证据。
4. 重新打开长会话时默认返回最新 500 条，并按时间正序显示；消息轮询默认返回最新一页，支持向前翻页，修复超过 100 条后最新轮次在桌面端和 App 消失的问题。
5. 修复桌面端登录一段时间后被误清除：前端区分“刷新令牌已明确失效”和“Supabase 暂时不可达/限流/5xx”；只有明确拒绝才退出登录，网络波动保留本地会话并提示重试。
6. 后端已验证的 Supabase JWT 在其有效期内缓存身份（最长一小时）。远端验签服务短暂不可用时，不会把已验证且未过期的同一不可变令牌重新判成 401；缓存不能建立新身份，也不会越过令牌到期时间。
7. App 服务端 Chat 同步读取最新 500 条；手机直连模型的离线模式也加入确定性上下文压缩，保留初始目标、阶段要求和最近 10 轮原文，不增加额外模型调用。
8. SQLite 新增 `conversation_compactions` 派生表；重复执行旧迁移时，已存在列会被幂等标记为完成，不再每次启动重复打印 `duplicate column` 警告。

## 安全与正确性边界

- 压缩摘要只用于续接上下文，不是命令执行证据；其中“已完成”内容明确标为用户或历史回复所报告，仍需工具结果或确定性校验确认。
- 未验证过的新 Supabase token 仍必须通过 JWKS 或远端用户接口验证；网络故障不会让任意 token 获得缓存身份。
- 服务器日志表明当前线上仍运行 V357，且 `HASHMM_SUPABASE_SERVICE_KEY` 未配置。上传并启动 V358 后，仍必须在服务器环境中填入真实 service-role secret，跨端 Supabase 同步才会工作；密钥不得写入仓库或日志。
- 日志还显示默认 JWT 密钥和默认管理员密码，公开部署前必须分别轮换。代码修复不能代替生产密钥配置。
