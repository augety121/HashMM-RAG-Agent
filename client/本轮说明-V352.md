# HashMM V352 本轮说明

日期：2026-07-19

## 本轮目标

修复 App“团队管理无法读取成员”的真实数据链路，并清理桌面端重复的“关于 HashMM”入口。实现以失败可诊断、部分成功可保留、权限不放宽为前提，不用空列表或假数据掩盖接口故障。

## 团队目录修复

1. App 不再把整份成员响应强制反序列化为固定字符串 DTO。
   - 兼容本地 SQLite 数字时间戳与 Supabase ISO 时间。
   - 非对象、缺少 ID 的坏行单独跳过，不拖垮其他成员。
2. App 并行读取两个受控来源：
   - `GET /api/admin/users`：HashMM 本地账号和服务端已同步账号。
   - Supabase `list_all_profiles` RPC：使用当前登录用户的 access token 与可公开 publishable key，RPC 内部继续执行管理员校验；没有引入或下发 service-role。
3. 两路成员按规范化的 `sb_<uuid>` ID 合并；显示名、邮箱、最近登录、管理员状态和身份来源互补。
4. 一路失败时显示“部分同步”及具体原因，同时保留另一路真实成员；两路都失败时才进入错误空状态。
5. 后端成员响应经过字段白名单，所有时间字段稳定输出为字符串，不允许密码哈希或未来内部字段随数据库字典透出。
6. Desktop 团队成员页同步增加来源状态、刷新入口和失败说明，不再把请求失败静默呈现为“0 人”。

## 桌面端关于页

- 删除用户菜单中的独立“关于 HashMM”和 `AboutModal`，只保留“设置 → 关于”。
- 设置关于页合并桌面版本、平台、检查更新、当前模型、模型连接、索引规模、当前账号、服务条款、隐私政策与本地数据/权限边界说明。
- 版本直接读取 Electron 主进程，不再显示长期写死的旧版 `HashMM V252`。
- 桌面 UI 没有新增 emoji，继续使用 Lucide 图标。

## 明确限制

- Supabase 完整成员目录仍依赖服务器已经执行 `sql/hashmm-profiles-models.sql` 中的 `list_all_profiles`。未部署时 App 会明确提示，并保留 HashMM 后端成员，不会伪造云端成员。
- 当前管理员 token 必须包含服务端控制的 `app_metadata.role=admin`；App 不从可由用户修改的 `user_metadata` 推断管理员权限。
- 本轮没有生成新的正式签名 Native EXE；桌面正式安装包仍必须由 `installer-native/build-all.bat` 生成并核验签名、SHA-256 和 release metadata。
