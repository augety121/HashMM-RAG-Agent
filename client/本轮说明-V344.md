# 本轮说明 · V344（2026-07-18）—— Chat 运行清单 · 可复现 RAG · 外部校验 · 右栏运行诊断

本轮继续按四份资料落地，但只实现可以由代码、数据库和测试证明的部分：不把模型自评当作完成证据，不虚构评测分数，不把独立功能做成脱离 Chat 的装饰页。后端迭代号为 **V344**，桌面端、MCP client/server 和原生安装器身份版本为 **1.17.0**。

## 本轮实现

### 1. 每次 Chat 主链路都有统一运行清单

- 标准 RAG、Agent Loop、子 Agent 编排和 ReAct 分支统一生成 `hashmm.run-manifest.v1`。
- 清单记录实际模型标识、任务类型、执行路径、检索模式/深度/策略、检索配置指纹、索引快照状态、证据集合指纹、阶段耗时、停止原因、迭代次数和 token 是否为估算值。
- 索引存在 `index_meta.json` 时使用真实构建身份；旧索引没有构建身份时明确标为 `evidence_only`，只复现本轮证据集合，不冒充完整语料版本。
- 清单持久化进 SQLite `messages.run_manifest`，旧数据库自动迁移到 schema version 13；Supabase 同步提供新增列迁移和无列回退。

### 2. 完成判定改为外部、可审计检查

- 主张证据、引用编号、工具执行和文件交付分别检查；失败项会进入清单的 `failed_checks`。
- `artifact_delivery` 只有在会话工作区真实存在文件时才通过；只出现文件名或下载链接不算交付证据。
- 没有检索来源的直接回答显示 `not_evaluable`，不会被错误标成“已由知识库证实”。
- 清单显式记录 `model_self_score_used=false`，不接受模型在正文中自报“完成/准确”来改变判定。

### 3. 右侧上下文栏新增“运行”页

- 与现有证据、Agent、文件页共用同一条 Chat 消息数据；刷新桌面端后仍可查看。
- 展示外部校验状态、执行模式、模型、停止原因、迭代次数、总耗时、语料/证据/配置指纹、阶段耗时和每项校验详情。
- 不改变证据页的复核、浏览器核验、画布和多 Agent 控制入口。

### 4. 启动器安全修复

- 删除仓库 `start-hashmm.sh`、`start-hashmm1.sh` 中的明文 JWT、Supabase service-role、Serper API key 和基准摄取 token。
- 启动器继续从 `.env` 或进程环境读取敏感值；已在历史脚本、聊天或日志中出现过的密钥必须在对应控制台轮换，删除文本不会自动吊销它们。

### 5. App 动态与工作台接入真实长任务闭环

- “动态”的浏览器调研、从电脑取文件、新建对话、查看电脑屏幕统一为同一种入口；远程屏幕进入真实 WebRTC/中继设备页，不再用后台截图冒充远程页面。
- 浏览器、取文件、只读盘点和多步任务统一进入任务创建页；页面选择的调研深度、交付格式、目录范围、筛选条件、只读约束和审批要求都会写入真实任务，不是本地演示状态。
- 电脑任务创建时先确保会话归属，再持久化用户请求和任务 ID；App 重进会话后从服务器恢复 pending / processing / done / error，不再只靠内存徽章。
- 智能体工坊、文档工坊补齐会话创建失败处理和“回到对话继续”入口；总控中枢删除空回调假按钮。
- 任务状态更新同时校验 `request_id` 与登录用户；不存在和越权任务统一返回 404，避免跨账号修改任务状态。
- 本轮按本地 `openai-agents-python-main` 的 conversation state ownership、session persistence、run item lifecycle 约束复核：会话历史由后端持久层单一持有，任务状态与 UI 展示分层，重进不重复派发。

- 本轮未把 GAIA、OSWorld、SWE-bench 等外部榜单的数字写进产品；只有使用真实数据集和可复现实验后才应产生分数。
