# HashMM V1000 本轮说明

日期：2026-08-09  
主题：会话连续性、唯一归属、可验证接力与统一控制平面

## 已完成

- 修复桌面历史仅保留少量记录的问题：历史采用服务端权威的持久内容标记、稳定游标和最多 10,000 条分页同步。
- 修复“项目”和“最近”重复：项目 Chat 只在所属项目，最近只包含未归属且已有持久内容的 Chat。
- 增加 revision、同步状态、删除墓碑和旧 Supabase schema 回退，防止旧云端副本覆盖较新归属或复活删除会话。
- 增加公开、脱敏、带哈希并可检测 stale 的 Chat handoff；桌面支持“在新 Chat 中继续”、接收、确认和拒绝。
- 增加 owner/project 隔离的 Chat mailbox 后端协议与前端 SDK；消息不传递审批或执行权限。
- WorkRuntime 增加统一任务迁移谱系和 `completed_with_limits`。
- 管理后台归并为 10 个治理域；设置页扩展为带 revision 和服务端回执的账号/设备控制面。
- 保留 V900 插件供应链和现有持久 OCR 队列；本轮未改变 pip 安装包。

## 验证事实

- V1000 连续性回归：8 passed。
- 任务运行时相关回归：19 passed，4 skipped。
- 前端：57 个测试文件、215 个测试通过；TypeScript 类型检查和 Next.js 生产构建通过。
- 后端全部 216 个测试文件在隔离进程组中完成：1,646 passed，8 skipped，无功能失败。
- 单进程全量 pytest 会受旧测试夹具把共享 SQLite 连接池恢复为空队列的顺序耦合影响而等待；因此本轮没有把“一次单进程全量通过”写成事实。隔离组均为退出码 0。

## 诚实边界

- Chat mailbox 目前完成 API 与前端 SDK，没有完整收件人发现/统一收件箱 UI。
- `followup_mode=queue` 已有账号设置契约，但没有跨重启耐久执行队列。
- 工作区/Git 新鲜度必须由接收端桌面在真实 ProjectVault 路径复核。
- SHA-256 是完整性证据，不是 Authenticode 发布者身份证明。
- 本轮没有新增 PaddleOCR、Unlimited-OCR 或其他 pip 依赖，也不会把运行环境可选 provider 写成必然存在。
