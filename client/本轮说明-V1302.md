# HashMM V1302 本轮说明

日期：2026-08-10  
主题：Cloudflare Tunnel 部署下的 dotenv 监听配置优先级修复

## 现场证据

- Cloudflare Tunnel `hashmm-autodl` 已建立四条 QUIC 连接并报告 Healthy。
- 远程配置已下发 `hashmm.hashlens.org -> http://127.0.0.1:6006`。
- V1301 安全诊断已接受 HTTPS 公网 URL 与安全远程配置，但仍打印 `0.0.0.0:6006`；代码检查确认 AutoDL shell wrapper 在 Python dotenv 解析前导出了监听默认值。

## 根因与修复

`python-dotenv` 使用 `override=False`，确保显式进程环境不会被配置文件篡改。V1301 的 AutoDL wrapper 却把 profile 默认值也写成进程环境，导致安全默认值和运维显式值无法区分。

V1302 不再由 wrapper 导出 `HASHMM_HOST`/`HASHMM_PORT`。Python 启动器先安全解析私有 `.env`，再通过 `setdefault` 补充 AutoDL 默认值，因此配置优先级为：

1. 运维显式进程环境；
2. 私有 `.env`；
3. AutoDL profile 默认 `0.0.0.0:6006`；
4. 非服务器 profile 默认 `127.0.0.1:6006`。

Cloudflare Tunnel 部署使用 `.env` 的 `HASHMM_HOST=127.0.0.1`，避免继续依赖 AutoDL 公开端口映射。传统未配置 Tunnel 的 AutoDL 部署行为保持不变。

## 安全边界

- 未启用或推荐 `HASHMM_ALLOW_INSECURE`。
- 未修改 Supabase 密钥、模型密钥、JWT 密钥或 Tunnel Token。
- Tunnel Token 继续只保存在服务器 mode 0600 文件中，不进入 `.env`、ZIP、日志或仓库。
- Cloudflare 只新增精确主机名 `hashmm.hashlens.org`，不修改 HashLens 根域名、`www`、`api` 或 Vercel 业务。
