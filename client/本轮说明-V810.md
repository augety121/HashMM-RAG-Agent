# HashMM V810 本轮说明

## 目标

V810 把上一轮仍未完全串联的项目契约、Chat 持久提示、附件资源、后台 OCR、任务检查点、右侧状态投影和 `/v1` 终态一致性收成同一条可恢复、可审计链路。隐藏思维链不进入数据库、SSE、任务面板或训练材料。

详细产品和协议规范见 `docs/CHAT_AGENT_V810_SPEC.md`。

## 已实现

1. **项目契约进入执行准入**：项目 goal、deliverable、custom prompt、success criteria、permission mode 与 revision 在创建 WorkRun 时冻结；项目标准进入确定性完成门。
2. **Chat 检查点 v2**：准入、计划、步骤、steer、审批/输入等待、中断和完成均产生带 generation/cursor 的公开检查点，重启恢复基于持久事实。
3. **资源与项目成员关系**：上传只在 owner 会话中执行一次，SHA-256 内容寻址；同名不同字节自动生成冲突安全文件名。Project 资源新增 owner 校验后的增删查接口。
4. **OCR v2**：默认 PaddleOCR，安装状态与真实 canary 分离；扫描 PDF 逐页 300 DPI、页级进度与 page anchor；队列支持租约、心跳、回收、取消、退避重试、源字节校验、partial/failed/blank 核算以及多 Chat 结果投影。
5. **Unlimited OCR 隔离契约**：默认关闭，只允许受大小限制的字节请求和 SHA-256，不向 sidecar 发送服务器路径；非 loopback 地址必须显式允许。主服务没有安装或升级任何 pip 包。
6. **任务链原子终态**：`/v1/responses` 的 completed 行与 `response.completed` 可重放事件在同一 SQLite 事务提交，消除快速轮询竞态。
7. **界面闭环**：Chat 附件显示 OCR 排队、进度、部分成功、失败、重试和取消；右侧 Work Inspector 汇总当前会话 OCR；对话自定义提示改为 owner-scoped 后端持久化。
8. **ProjectVault 与最近记录**：保持默认位于用户选择的安装目录 `HashMM Data`，不写死 C 盘；服务端分页仍是“最近”的权威源，本地只做离线投影。

## 真实边界

- 当前本机内置桌面 Python 运行时不包含 PaddleOCR；服务器上传的 pip 清单显示已有 PaddleOCR/PaddlePaddle，但仍必须在服务器通过 `capabilities?probe=true` 的真实推理 canary 后才能报告 ready。
- Unlimited OCR sidecar 未随主服务打包，也未在本机进行真实外部模型验收；协议与安全边界已实现，部署能力仍为 unavailable。
- LoHoSearch 官方数据不随代码分发；没有带来源、快照 ID、544 条样本和 SHA-256 的官方数据时，只能运行 smoke/contract，不能声明官方成绩。
- HashMM 提供预算预留、结算和 owner 用量账本，但没有接入真实 Cloudflare Wallet/x402 账户，不能声称已经发生真实支付。
- 公网 HTTPS/WSS、TURN、多设备 24 小时稳定性、OCR GPU 精度和 Authenticode 发布者身份仍需真实部署环境验收。
