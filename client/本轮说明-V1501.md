# HashMM V1501 修复交付说明

## 根因与修复

服务器日志证明 V1500 doctor 的 Supabase 统一身份配置完整，且 `/api/auth/identity-contract` 返回 200。桌面端仍显示“服务器统一身份配置不完整”的根因，是客户端在调用真实鉴权接口之前，先把可选诊断字段当作授权判据；V1501 保留显式 Supabase 项目不一致的前置拒绝，其他场景以 `/api/auth/me` 的真实验签结果为最终依据。

App 的“没有找到或无权查看”不是服务端权限证据。旧实现把无网络、无 token、401、403、404、5xx、解析失败全部压成 null。V1501 增加结构化工作画布读取结果，分别呈现失败原因；401 通过 Supabase SDK 的单飞刷新轮换会话后重试一次，写操作不重放。

服务器端同时修复同一 token 冷缓存时的并发校验风暴：同账号请求共享一次远程 Supabase 校验，不同账号继续并行。桌面心跳改用 query-only 和 8 秒 deadline，旧 JSON 心跳断连被安全吸收。

## 仍需部署环境确认

- 服务器必须上传 V1501 包并重启，桌面端必须安装 6.0.1，App 必须安装 3.0.1；混用 V1500 客户端不会获得本轮客户端修复。
- Windows 安装器当前 Authenticode 为 `NotSigned`；Android Release APK 未提供发布者 keystore，因此仍为 unsigned。Debug APK 可用于验收。
- App 若收到真实 403，V1501 会明确显示“当前账号无权查看这项工作”；这时应使用服务端 request id 和 run id 检查 owner，而不能扩大对象权限或跨账号兜底。
