# HashMM V393 本轮说明

日期：2026-07-23

## 结果

本轮修复的是一条此前“看起来有自我进化、实际上没有进入生产 Chat”的断链。旧实现会随机选择 A/B 变体，并可能根据很少的反馈自动晋升；候选由模型生成失败时还会退化成模板拼接，无法证明改进真实发生。V393 将其替换为受治理的技能版本链：候选永远隔离，只有属主明确审核后才进入 Chat，运行时记录实际使用的版本哈希，真实用户反馈才能回写该版本，并可在没有后续覆盖时精确回滚。

## 核心能力

1. `hashmm.governed-skill-evolution.v1`
   - 每次改进保存基线哈希、候选哈希、来源运行、确定性评估和权限差异。
   - 没有真实模型时明确不可生成；不再用内置句式伪造“AI 已改进”。
   - 候选默认 `is_active=0`，随机 A/B 与自动晋升被永久关闭。
2. 确定性审核与并发安全
   - 候选必须通过长度、差异、意图相关、凭据泄露和权限绕过检查。
   - 采用时使用基线哈希 compare-and-swap；技能在审核期间被修改则拒绝覆盖。
   - 回滚只允许从当前采用版本精确回到本次基线，后续编辑不会被历史审核误伤。
3. 真正接入 Chat
   - 普通问答、AgentLoop、多智能体综合与 ReAct 共用同一命中技能方法。
   - 技能采用后下一轮 Chat 直接使用新提示；拒绝和未审核候选不会影响回答。
   - 运行清单只持久化技能 ID、名称、作用域与 SHA-256，不复制私有提示正文。
4. 版本级效果归因
   - 点赞/点踩从服务端保存的 assistant 运行清单读取技能版本，不接受客户端指定技能 ID 或版本。
   - 反馈只更新同一属主、同一技能、同一哈希且仍为线上状态的版本。
   - 跨账号猜测技能 ID 或哈希不会改变计数，也不会泄露对象是否存在。
5. 统一工作与桌面审核
   - 提案、采用、拒绝和回滚同步写入 WorkRuntime，供桌面与 App 读取同一事实。
   - 桌面端显示安全检查、权限扩大结果、候选内容、基线哈希和运行账本；采用操作以服务端回执为准。
   - 能力探测只有在真实 API 全部挂载后才宣称功能可用。

## 安全与正确性边界

- 候选生成输入中的现有技能提示被明确包裹为不可信数据；候选不得扩大工具、网络、文件、子 Agent 或审批权限。
- 技能、进化运行和候选的读取及决策均执行属主/管理员校验；不存在与无权访问使用相同的非枚举响应。
- WorkRuntime、运行清单和审计记录不保存候选提示正文、模型隐藏推理或凭据。
- 确定性检查只能证明结构、安全边界和版本关系，不能证明候选在现实任务上一定更优；因此系统不自动晋升。
- SHA-256 用于内容寻址和完整性比较，不等同于现实效果证明，也不等同于 Authenticode 发布者身份。

## 明确限制

- 当前技能候选由已配置模型生成，但质量门只做确定性安全与结构检查；候选是否提升真实任务效果仍需要用户审核和后续版本级反馈。
- 版本反馈是回答级结果归因，不是因果实验结论；同一回答可能同时受模型、检索、工具和上下文影响。
- 当前候选权限清单针对提示型技能，默认没有独立工具授权。未来引入可执行技能时必须扩展为工具级权限 diff，不能沿用“提示无权限”的假设。
- Android App 工程不在当前可写根内，本轮没有宣称重新编译或发布 App。
- 安装包若未配置代码签名证书将显示 `NotSigned`；SHA-256 不能替代发布者签名。
