# HashMM V2000 本轮说明

## 版本

- Backend/SDK：V2000 / 2.0.0（服务版本 20.0.0）
- Desktop、WebUI、MCP、Native Installer：11.0.0
- Android：8.0.0（versionCode 200）
- 远程协议：`hashmm.remote.v2`（只增加可选诊断字段，保持 wire compatibility）

## 已完成闭环

1. 统一身份：路由不再读取 provider-specific `id`；Supabase/HashMM principal 统一解析并 fail closed。
2. 远程诊断：host ticket、host socket、viewer ticket 与 routable lease 分层，提供不含 token/IP/SDP 的尝试关联号。
3. App 单连接：ticket 请求和 WebSocket 使用 generation fencing，旧回调不再覆盖新连接；自动重试保留累计预算。
4. 远程可用真值：App 在 `remote_ready` 缺失时默认 false；只有 live host lease 才允许进入桌面。
5. Agent Workspace：285 个角色通过普通侧栏可发现；团队分工可搜索并绑定角色库身份，权限仍由运行作用域决定。
6. 能力入口：Composer 尊重 Browser/Computer/Canvas/Team 开关；无显式插件选择时不制造虚假已启用状态。

## 尚需真实环境验收

- `https://hashmm.hashlens.org` 下 Desktop host 注册、Android viewer 发现、审批、WebRTC 与断线恢复的跨网络 E2E。
- 有效 TURN 凭据下的对称 NAT/校园网 relay 验收和 24 小时 soak；没有该证据时不得写“公网远控已稳定”。
- 多实例部署必须先实现并验证共享 presence/signaling broker；环境变量名称本身不构成实现。
- 正式公网分发仍需 Authenticode；当前 SHA-256 只证明本次生成物完整性，不证明发布者身份。

## 安全说明

- `attempt_id` 是随机诊断关联号，不包含账号、设备原始标识或凭据。
- 角色库内容属于不可信提示资料；绑定角色不自动授予文件、网络、Shell 或审批权限。
- 设备不存在与无权访问继续使用不可枚举的 owner-scoped 查询边界。
