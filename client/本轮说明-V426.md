# HashMM V426 本轮说明

日期：2026-07-26  
版本：Backend V426 / Desktop、MCP、Native source 1.23.0 / Android 1.15.0（132）/ database schema 27

## 本轮目标

从 V390 开始逐段核对“方案是否真的进入主链”，修复隐藏的 fail-open、执行证据缺口和桌面端登录连续性问题，并把可验证结果与外部环境门禁分开记录。

## 实际修改

- `run_manifest` 对每个观测到的工具步骤要求明确 `call_id`、同一 `run_id` 的结构化执行回执和工具绑定；缺回执、重复回执、错工具、错运行或无调用 ID 均不能标记完成。
- 交付质量检查器、RAG 回答验证器、Tool governance、严格计划 Hook、浏览器语义定位在异常时不再给出成功或弱匹配结果。
- 浏览器/画布证据定位保存有界 fingerprint，并返回 confidence/match reason；弱匹配拒绝执行。
- Electron 身份刷新使用主进程加密 vault 和 compare-and-swap 轮换，渲染器不持有 refresh token，过期刷新不会覆盖更新的会话。
- 删除未接入主执行链的 `HASHMM_VERIFIER` feature preset 广告，保留底层模块以兼容历史配置。
- 补齐 V346 旧契约测试中的 proof-carrying receipt，避免测试样例绕过当前回执门禁。

## 验证与交付

验证结果写入 `docs/V390-V425-contract-audit-V426.md`。服务器压缩包只包含后端、SQL、启动脚本、skills/plugins/clients/tools/deploy 和模板配置，不包含 `frontend-next`、`desktop`、`installer-native`、测试、用户数据、日志、模型、缓存或密钥。

真实公网、多设备、对称 NAT、TURN、24 小时稳定性和 Windows 签名安装包仍需用户部署环境验收，本轮不以单元测试替代。
