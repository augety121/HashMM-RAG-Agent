# HashMM V392 本轮说明

日期：2026-07-23

## 结果

本轮没有再增加孤立的“多智能体页面”，而是把 Team、Worker、AgentSession、统一工作账本和 Chat 交付收束为一个持久 Agent Mesh。它面向长对话和长任务：任务可以并行或按依赖接力，用户可以在执行途中纠正指定子 Agent，进程重启后所有控制面会一致恢复为真实状态，最终结果必须经过独立验收并成功写回原 Chat 才能宣称闭环。

## 核心能力

1. `hashmm.agent-mesh.v1`
   - 持久保存协调根节点、角色节点、汇总、独立验证和交付节点，以及节点间的确定性依赖。
   - 并行与流水线使用不同 DAG；上游失败会保留在下游的 `upstream_failures`，不会被汇总文字掩盖。
   - 任务终态不可覆盖。失败后的重新执行必须创建新 Team/代次，历史证据保持可审计。
2. `hashmm.agent-mail.v1`
   - 纠正、角色结果、控制与验证消息支持幂等键、租约、确认、释放、超时重投和死信。
   - 邮箱正文有长度边界并对明显凭据值脱敏；跨端 WorkRuntime 只保存计数和哈希，不保存正文。
   - Worker 只在模型回合前租用消息，模型调用成功后才确认；调用失败会释放重试。调用期间到达的新纠正会阻止旧答案提交。
3. 统一 AgentSession 与 WorkRuntime
   - 协调者、角色 Worker 和独立验证器拥有属主隔离的持久会话树，并共享同一个团队 WorkRuntime ID。
   - 进程重启时，无法继续的内存模型调用、Agent Mesh 节点和 WorkRuntime 一致进入 `interrupted`；外部副作用明确不可自动重放。
4. 独立验收与交付门
   - 独立验证器使用单独会话，工具集为空、网络关闭、不可再派子 Agent。
   - 它只读取目标、候选结果、公开来源元数据与执行回执元数据，不读取执行 Agent 自评或隐藏推理。
   - 候选为空、角色未完成、引用账本未通过等确定性硬检查不能被模型判词覆盖。
   - 完成门要求独立验证通过，并要求 Agent Mesh 的交付节点确认结果已经写回原 Chat。
5. 桌面右栏控制面
   - Agent 页展示任务网进度、阻塞、邮箱待送达数和独立验证结论。
   - 展开指定子 Agent 后可以追加约束或纠正方向，也可以协作式停止该 Agent。
   - 操作走属主校验的服务端 API；右栏不会通过本地状态伪造成功。

## 安全与正确性边界

- Team ID、会话 ID 和消息目标都执行属主校验；不存在与无权访问使用相同 404，避免对象枚举。
- 公开 Team 状态使用字段白名单，不返回 `uid`、登录名、完整执行范围或未来新增的私有控制面字段。
- Agent 间消息一律作为不可信协作数据包裹，不能覆盖系统和用户指令；只有 `sender_kind=user` 的纠正按最新用户要求进入下一模型回合。
- WorkRuntime 不保存邮箱正文、工具正文、参数或隐藏推理，只保存有界生命周期、计数、哈希和状态。
- 因果失效只由来源、回执、工具、产物、上下文胶囊、权限等执行输入/观察变化触发。正常检查从“待评估”推进到“通过”不会反过来制造永久过期。
- 独立验证是额外门禁，不是现实世界真理证明；没有可观察证据时仍必须明确限制。
- SHA-256 是完整性证据，不等同于 Authenticode 发布者身份。

## 明确限制

- 本轮实现的是服务端、Web/桌面 UI 与 Electron 发布链内的持久 Agent Mesh。相邻 Android App 工程不在当前可写根内，因此没有把未修改的 App 二进制宣称为 V392；现有 App 仍可继续读取向后兼容的 WorkRuntime 字段。
- 单 Agent 停止是协作式停止：已经发出的模型调用不能被虚构为硬中止；调用返回后其旧结果会被丢弃。
- 当前团队重启恢复采用“真实中断 + 显式重试新代次”，不会自动恢复尚未完成的模型调用，也不会自动重放文件、网页或外部系统写操作。
- 邮箱死信需要用户或上层调度器显式重派；系统不会无限重试。
- 独立验证器无网络和工具能力，它只能核验本次运行已经取得的来源与回执；缺失证据会保持未通过。
- 当前安装包没有 Authenticode 发布者签名；SHA-256 只能证明下载文件与本轮构建产物一致，不能证明 Windows 发布者身份。公开分发前仍需配置代码签名证书后重新构建。
