## 1️⃣ 测试日志详细化：输入 → 输出 → 判定 全上

之前日志只有"标题多级：true"这种结论。现在每条用例都打：
- **【输入】**：喂给函数的原始内容（Markdown 源串、消息序列、时间戳…）；
- **【输出】**：函数实际产出（解析出的块类型、去重后的消息、格式化后的显示…）；
- **【判定】**：期望 vs 实际 + ✓/✗。

例如 Markdown 用例会打『输入 `# 一级⏎## 二级`→输出 3 块 Heading→期望级别 1..3→✓』；消息覆盖
用例会打出服务端/本地各自的消息序列和覆盖后的结果。**把项目的输入、输出、判定都落进日志**，
方便你直接拿去分析。

## 2️⃣ 修"0ms 观感"

纯内存用例本就亚毫秒，之前显示"0ms"看着像没跑。现在每条结果都带**微秒级实测耗时**
（`⏱ 实测耗时：3ms（3358µs）` 或 `48759µs（<1ms，纯内存计算属正常）`）——看得出真跑了、跑了多久。

## 3️⃣ 测试再扩充（19 → 25 套件）

新增 4 个功能测试：消息字段完整性(thinking/status/id 全保留)、极端时间戳(远未来/远古/非法沉底)、
多轮覆盖叠加不串不丢、行内符号与长段落分段；新增 2 个压力测试：千轮覆盖循环(模拟长会话流式)、
单条 100 万字超长消息解析。端到端真跑 **24 PASS / 1 SKIP**（cache_json 装机即跑）。

现共 **12 功能测试 + 13 压力测试 = 25 套件**，覆盖 App 的 Markdown 渲染、消息列表重构、时间显示与
排序、后台流、缓存等全部核心功能。

## 4️⃣ 其他数据页跨导航持久化（与测试中枢 NativeTestHub 同款）

新增 `WorkbenchCache` 进程级单例。**质量/审计/高级能力/上下文透视**四个数据页接入：重进页面
**先秒显上次拉到的数据**、不再空转重拉；需要最新点刷新即可。（进程存活期内有效，冷启动清空正常。）
