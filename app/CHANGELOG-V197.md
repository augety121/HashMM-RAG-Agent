# HashMM App V197 变更说明

基线：V196。本轮六项全部落地，均为"现象 → 根因 → 改法"式修复/重构；配套桌面端 V203 增加接力回执（详见文末联动说明）。

## 1. 远程操控：操作按钮与虚拟鼠标（RemoteControlScreen/ViewModel、SettingsStore）

- 虚拟鼠标"点不动"的根因：触控板模式的光标与点击坐标按整个屏幕框归一化，而桌面端协议要求"视频内容区"坐标——在铺满模式/异形屏上，箭头指的位置与点击落点错位。修复：新增 contentRect() 与触屏 norm() 同一套数学，箭头绘制、拖动增量、点击坐标全部统一到内容区坐标系；适应/铺满/任意机型手感一致。
- 无法拖选：桌面驱动链只实现 left_click_drag（down/up 在协议里有名但驱动未实现）。新增拖选状态机：长按虚拟鼠标左键定起点（屏幕上画出起点圆点与到光标的橡皮筋虚线），移动光标后再点左键，一次 left_click_drag 完成框选/拖动窗口/拖文件；再长按可取消。左键在拖选态高亮显示"完成"。
- 电脑键盘一批"假键"：`[ ] \\ ' ; , . / - = PrtSc ScrLk Pause Ins Caps` 发出的键名不在桌面白名单，被静默丢弃。修复：符号键映射协议名（; → semicolon 等），无协议名的符号在无 Ctrl/Alt/Win 时改走"键入文本"真实打出；新增 Win 粘滞修饰键；第二页死键行重排为 截屏(Win+Shift+S)/Home/PgUp/PgDn/End/Del；快捷键面板 Caps 换成 Del。
- 设置抽屉去 demo：删除四个不可能真实生效的开关（指纹验证、自动解锁被控端、被控端静音、防窥模式——依赖桌面系统级驱动，做不到就不摆出来）与两个纯摆设开关（按键映射、平板触控）。保留并实装两项安全能力：结束后锁定被控端（断开自动发 Win+L）、结束后清空被控端剪贴板（推过去的密码不留在对方机器），均持久化（SettingsStore 新增两个偏好），统一走 exitStreaming() 在任何退出路径生效；另加"立即锁定被控端"动作。
- 细节：拖选中长按屏幕不再误触右键；工具栏/快捷键面板最小字号提到 10sp。

## 2. 历史对话图标（ChatListScreen）

红色渐变首字方块视觉噪音大、像联系人应用。改为 Material 3 tonal 风格：柔和圆形容器 + 对话符号，明暗主题自适应；置顶会话用品牌色弱底 + 品牌色图标突出。App 启动图标未改动（按要求只允许微调，本轮未动）。

## 3. 语音输入"手机未提供语音服务"（ChatHomeScreen、ChatHomeViewModel）

首页语音原先只调系统识别弹窗，国产无 GMS 机型直接报错。重构为三级真实链路：
A. 端上 SpeechRecognizer（有系统识别服务时，免弹窗、带实时部分结果）；
B. 录音 → 上传后端 /api/stt 转写（无 GMS 机型主路径；点一下开始、再点结束，转写中转圈）；A 级运行报错时自动切 B；
C. 系统识别弹窗兜底。
只有三级全部失败才提示，且提示给出可行办法。占位文案随状态变化（聆听中/部分结果/录音中/转写中），麦克风按钮三态可视。

## 4. 快捷指令四组重构（WorkbenchHubScreen、ChatHomeScreen、Routes、ChatDetailViewModel、MainScaffold、HashMMApp）

根因：工作台与首页的"盘点电脑文件/取电脑文件"等项只是把一句话发给云端 Agent——后端看不见你的桌面文件、也无法 computer use，等于摆设；且与对话窗口能力重复。重构：
- 路由新增 dispatch 参数：`chat/{convId}?initial=&dispatch=`。dispatch 非空时，详情页首条不发 Agent，而是经 /computer-task 或 /request-file 下发到电脑客户端（桌面轮询器接走、computer-use 执行、结果回本会话），并乐观插入一条【电脑任务】气泡。
- 工作台快捷指令拆成两组并各配一句说明：「电脑任务 · 交给电脑客户端」（盘点文件 / 取文件 / 浏览器查 / 整理下载文件夹，附电脑端在线状态提示）与「对话任务 · 直接问 Agent」（总结对话 / 提炼知识库）——与对话窗口不再重复。
- 首页"+"抽屉的"把电脑里的文件发我"同步改为真下发。
- 对话内原有四组下发菜单（智能·记忆/电脑操作/取电脑文件）链路本就正确，保持不变。
- 工作台"客户端能力"移除"远程控制"入口（与"我的"页重复）。

## 5. 接力：周期状态跟踪（RelayViewModel/Screen/Repository + 桌面端 remote-host.html）

原先只发一条信号+toast，之后黑盒。现在是完整状态机：发送中 → 已送达（等待接管，持续转圈）→ 桌面已接管（绿色对勾，含主机名）/ 失败。实现：桌面端收到 handoff 后回写 handoff_ack 信令（含 conv_id/主机名/时间），App 每 2.5s 查一次回执、30s 窗口，命中即推进状态；在线主机列表页内每 5s 自动刷新。状态卡可手动收起。

## 6. 无感同步 + "我的"页（ChatHomeViewModel、ProfileScreen、ProfilePages、SettingsViewModel、AvatarRepository、Routes、HashMMApp、MainScaffold）

- 无感同步（对标 Claude/Codex）：首页内联会话建立 Supabase Realtime 订阅——桌面端或其它设备发的消息实时回流，无需手动刷新；新会话从第一条起订阅，切换/新对话正确退订；流式中让位给轮询避免互踩。（会话列表与动态页原已接实时，本轮补齐了首页这最后一块。）
- "我的"页重构：
  - 删除"工作区"分组（记忆中心/知识库已在工作台 Tab）。
  - 新增"账号"分组 → 个人信息页：头像点按更换、昵称编辑（写 profiles.display_name，与桌面端互通）、邮箱、用户 ID 一键复制。
  - "客户端连接"由内联小编辑框升级为独立页面：实时连接状态卡（在线/耗时/一键重测）、三步工作原理说明、手动地址（高级）。
  - "关于"完善：帮助与反馈（四条常见问题折叠卡 + 邮件反馈自动带版本与机型）、软件许可及服务协议（原用户协议更名）、隐私政策、个人信息采集清单（逐项列采集内容/用途/场景/去向，如实）、关于 HashMM（版本号改读 BuildConfig，不再写死；含产品说明页）。
